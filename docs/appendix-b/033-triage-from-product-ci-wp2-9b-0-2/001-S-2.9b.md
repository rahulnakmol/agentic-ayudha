# S-2.9b

## Plan assumption

WP2.9: `aayudha-triage.yml`, installed by `init --gates`, classifies new intake issues in Actions with the triage lane's model (keys in the `ai-gateway` environment); ground rule 5: "`triage` in Actions"; WP2.6: `--gates` installs the triage workflow; the registry's triage `ModeNote` "direct in Actions"

## Finding

Founder decision (2026-10-16): product CI never calls a model. Triage runs from the user's own agent (Claude Code, Codex, Cursor, or Amp) on request, or by @-mentioning an installed app. A repository that already has the workflow is told and offered its removal

## Implemented instead

`init --gates` no longer installs `aayudha-triage.yml`: the template, its embed, `initrepo.TriageWorkflow`, and its golden are removed, and this repository's own copy is deleted with its `.aayudha/state.json` entry. `doctor.RetiredWorkflows` names it with the reason. Every `aayu init` (with or without `--gates`) runs `retired` first: for each retired workflow present whose `name:` is aayudha's, a dry run plans its removal, a human confirms (`--yes` for a human; refused for an agent) before it is deleted and forgotten from the init state, and without confirmation it is kept with a note. A product's own file of the same name is never touched. `doctor` gains a `retired-workflows` row that warns while one is present. The triage verb is unchanged: the host's model passes `--as` (the skill), and without it the binary calls the triage lane only for a person who holds a key; its `ModeNote` now says "the host's model passes --as; never in product CI". `TestModelChecksNeverGateAndNeverShip` fails if any workflow `init --gates` installs names `ai-gateway`, `AAYU_SECRET_`, `AAYU_MODELS__`, or `AAYU_AI_GATEWAY`. Rule 5, WP2.6, and WP2.9 are unchanged in text; this row records where their "triage in Actions" no longer applies. The guides (adopt, how-architecture, how-models) no longer list a model key for CI
