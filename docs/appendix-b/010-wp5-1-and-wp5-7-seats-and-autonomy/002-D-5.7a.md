# D-5.7a

## Plan assumption

WP5.7: `aayudha-streak.yml` (protected) computes the streak per layer footprint from merged-PR history; corrections detected automatically (changes-requested review, non-bot commit on the PR, post-pass `fix`/`rebuild`, revert, Incident/Bug linked within N days) plus the manual `aayu:correction`; `autonomy/corrections.jsonl` on `ledger` written by CI; uses the WP1.6 `[notify]` sender; `aayu halt` sets a repository variable every workflow and verb checks, `aayu resume` clears it. Accept: streak math at 19/20/21 and on each correction kind; `halt` stops a running loop within one poll

## Finding

Built ahead of M4.5 (founder scheduling, 2026-10-12). D1: the workflow token can never push `ledger`, and the bot App does not exist yet. The plan fixes neither N, nor which PRs are agent work, nor what "post-pass" and "linked" mean. V7 fixes the plumbing list, so there is no command slot for the streak. `inspect` (WP4.8) and `build` (WP5.5), whose dispositions and checkpoint commits the detection reads, are not built. A required check whose job is skipped counts as passing, so a job-level `if:` cannot halt CI. A running job never re-reads `vars`. The App manifest (D-2.6a) and the workflow token have no Variables permission

## Implemented instead

`internal/autonomy` computes, `aayu status --streak` (a new `status` input; MCP read, `--apply` still pinned off) reports, and the template `aayudha-streak.yml` (embedded, golden-tested, installed by `init --gates` as the fourth gate workflow, and committed on aayudha as the template rendered for `dev`) runs it on every push to `dev`, daily at 05:17 UTC, and on dispatch, with only read permissions. Agent work: a PR opened by a bot (`type: Bot`, a `[bot]` login, or `[identity] bot_logins`) or labelled `agent-authored` or `identity:human-fallback`. Corrections, per agent PR: any `CHANGES_REQUESTED` review; a commit whose author is not a bot, is not a merge, and carries no `Aayudha-Checkpoint:` trailer (so on the day-one path every hand-made commit counts); a comment holding an `<!-- aayudha:` marker and `disposition: fix\|rebuild` posted after the first human approval (n/a until `inspect` and `review` post them); a later merged PR titled `Revert "<title>"`, saying `Reverts …#N`, or carrying a commit that reverts the merge commit; a `type:bug` or `type:incident` issue created within `[autonomy] correction_days` (new key, proposed 14) after the merge that names `#N` or `…/pull/N`; the `aayu:correction` label. Footprints come from the layer globs in `LAYERS.md` at the checkout root (`verify.ReadLayers`, WP4.3), else the registry. A layer's streak is the number of agent PRs on it merged after its newest corrected one; it is autonomous at `[autonomy] streak` (20) unless it is in `[autonomy] never`, and a footprint is autonomous only when every layer in it is. The newest 100 merged PRs are scanned. With `--apply`, refused outside `--ci`, the workflow appends the corrections the ledger file lacks (keyed by PR, kind, and ref; read through the contents API at `ledger`) under the App token and pages them through `[notify]`; without `AAYUDHA_APP_CLIENT_ID` it runs without `--apply` and logs a `::notice::` that the ledger write was skipped, and the streak still lands in the job summary. Halt: `aayu halt [--reason]` sets the Actions variable `AAYUDHA_HALT` to the reason, login, and time (kept on a second halt) and pages through `[notify]` (urgent); `aayu resume` (refused for agents) deletes it, clears the `[budget]` breaker's pause file, and pages. Every job in every aayudha workflow (13 in `ci.yml`, 6 in `release.yml`, the others, the protected-paths trio, and the broker, Ready guard, triage, and streak templates) starts with a step that fails while `vars.AAYUDHA_HALT` is set, so a halted repository can merge nothing; template steps that run the binary pass `AAYUDHA_HALT` in their environment. Every verb except the read-only `doctor` checks before it runs (the environment when a workflow set it, else the API with the human token; agent lanes and CI fail closed when GitHub cannot answer, humans get a warning) and, when it could read the API, re-reads it every 30 s while it runs and is cancelled with exit 4 when it is set. The host `pre-tool` hook blocks agent tool calls while halted, asking GitHub at most once per poll. `halt` does not cancel workflow runs already past their first step (SECURITY.md says to cancel them). Tested: `TestStreakAtThreshold` and `TestCorrectionKinds` (each kind with a near miss that must not count), `TestStatusStreak` (fake GitHub, local ledger), `TestHaltStopsRunningLoop` (200 ms poll), `TestHaltFromWorkflowAndHook`, and `TestHaltLive` (AAYU_LIVE=1: a scratch repository, a 3 s poll; stopped 1.3 s after the halt on 2026-10-12). A workflow carrying the halt step on a scratch repository failed at that step while halted and passed after `aayu resume`. The ledger write from CI is untested live until the founder creates the App
