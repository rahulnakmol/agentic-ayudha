# D-5.1a

## Plan assumption

WP5.1: RACI generated from the registry with one Accountable seat per verb and one owner per layer, executes vs owns distinguished, rendered into `AGENTS.md`; `seat add <seat> --human <login>` writes `[seats.<seat>]`, adds the login to CODEOWNERS for the seat's layers, posts the charter and a "how we work" digest as an onboarding issue, and flips the WP0.1 solo-mode policy off when it adds the second human (D2: one approval with native CODEOWNER review; the gate and the admin bypass removed); `remove` reverses it, hands open stories' Technical Owner to the twin, and records the change on `ledger/seats/`. Accept: registry lint; `seat add` fixture gives the expected CODEOWNERS diff and onboarding issue; `seat remove` leaves no dangling human owner

## Finding

Built ahead of M4.5 (founder scheduling, 2026-10-12). GitHub evaluates CODEOWNERS from the base branch and never counts an author's own approval, so switching the ruleset in the same step as the CODEOWNERS change deadlocks (nobody can approve the PR that makes the second human a code owner), and after the bypass is gone a path whose only code owner is one human can never be changed by that human. The gate reads only root-anchored literal patterns and fails closed on any other. `init` does not install the gate (D-2.5a), so only aayudha has the solo-mode ruleset. A personal repository has no organization to count humans in. The registry had no Responsible, Consulted, or Informed data

## Implemented instead

RACI: `Command.Seat` is A; R is always A's agent twin in the verb's lane (with its paired human); `Command.Owns` (else A) owns thresholds and policy, so `verify` is executed by the AI Native Engineer against the Quality Architect's floors and `inspect` policy is the Engineering Manager's, executed by the review lane; C and I live in `internal/verbs/raci.go`. `verbs.LintRACI` (A known; every verb has a RACI entry; C and I known, unique, and distinct from A and the threshold owner; every layer one known owner) runs in the generator and `TestLintRACI`, so a breach fails `go generate` and CI. The generator writes `docs/RACI.md`, the region between `BEGIN/END GENERATED: raci` in each hand-authored `seats/<seat>/CHARTER.md` (twelve; generation fails if one is missing or a stray seat directory exists), and the `aayudha:raci` section of `AGENTS.md` through `hosts.RenderAgentsMD`; `seat add\|remove` render the same section into a product's `AGENTS.md`. Humans are counted as the distinct user logins in CODEOWNERS plus paired seat humans, excluding teams, emails, and `[identity] bot_logins`. `seat` keeps one block at the end of CODEOWNERS (`# BEGIN aayudha:seats` … `# END aayudha:seats`) rebuilt from the paired seats, never editing hand-written lines: each glob of a paired seat's layers becomes a root-anchored literal line (`dir/**` → `/dir/`) owned by the seat's human and the hand-written owners; with two or more humans every hand-written line is re-declared with the paired humans of the layers that cover it, and any line that would name fewer than two humans gets every human, so each human can review the other's changes. The same seats render the same block, so `remove` restores the file byte for byte. The policy switch reconciles ruleset `protected-paths-codeowner-review` (found by name; absent means "n/a" on product repositories): second-human review (one approval, CODEOWNER review, the `protected-paths` check dropped, no bypass actors) only when both the checkout's rendered CODEOWNERS and the default branch's (contents API) name two humans; so `seat add` is run twice, once to write the files (merged by a solo-mode bypass) and again after the merge to switch. Solo mode (no approvals, CODEOWNER review on, the check required with the GitHub Actions app, the admin role as bypass in pull-request mode) returns as soon as either names fewer than two, and `remove` switches back before writing files so the founder can merge them. `seat add\|remove` are refused for agents, need a terminal yes or a human's `--yes`, verify the login is a GitHub `User` and not a bot login, and refuse a seat already paired with someone else. The onboarding issue (label `seat:onboarding`, found again by a marker so reruns post nothing) holds the digest, the seat's generated RACI, and the charter. `remove` rewrites the Technical Owner field of open Story and Bug bodies and the Technical Owner row of their Ready snapshot comments that name the human (when the human sits in no other seat) to "the `<Seat>` twin"; the Ready guard then strips `status:ready` from a story whose body changed, so it is re-readied. Both actions append to `seats/changes.jsonl` on `ledger` when they change something. Tested against the fake GitHub with a fixture checkout holding aayudha's own CODEOWNERS and config and the live ruleset's JSON (`TestSeatAddRemove`); this repository's rulesets were not changed and no second human was added (founder action)
