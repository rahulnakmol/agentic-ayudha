# D-2.1a

## Plan assumption

WP2.1: "Ten types", with fields per stage, parents, and links

## Finding

The plan names the count and, across WPs, Goal, Initiative, Feature, Story, Bug, Decision, Feedback, Incident, Release, and the Experiment that `experiment`/`readout` work on; "Result" is something written onto a Goal, Initiative, Feature, or Experiment, not a type. It fixes no field lists or link kinds

## Implemented instead

The ten types are Goal, Initiative, Feature, Story, Bug, Decision, Experiment, Release, Feedback, Incident (`internal/workitems/schema.go`, schema v1; `grill`'s `type` input is now this enum). Result is a Complete-stage field. Parents: Initiative → Goal, Feature → Initiative, Story → Feature (required at Ready); Experiment → Feature or Initiative (required at Ready); Bug → Feature or Story, Decision → any delivery type or Incident, Release → Goal (optional); Feedback and Incident are intake with no parent. Links are typed lines `<kind> #N` in a Links field: `supersedes`, `constrains`, `depends-on`, `caused-by`, `becomes`, `includes`, `waives`. A Completion Goal criterion is one line `N. [evidence_kind] state: …; expected: …`; Measure, Threshold, Scenario, and Environment are separate Ready fields of the Completion Goal. A criterion without a valid evidence kind is unmapped. Effort is required at Ready for Story and Bug; `effort:XL` blocks Ready for every type
