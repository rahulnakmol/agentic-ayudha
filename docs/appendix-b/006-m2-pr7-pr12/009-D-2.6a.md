# D-2.6a

## Plan assumption

WP2.6: `--projects` (Portfolio/Delivery/Ops views), `--gates` (broker and Ready guard), `--identity` (GitHub App), `--integrations` (bucket, PostHog, Sentry, GrowthBook), each with a cost/scope summary and `y/N`

## Finding

The Projects v2 API cannot create views, so three views of one project are not possible from code. Creating a GitHub App needs the human's browser (the manifest flow). A gate workflow needs the aayudha binary, and there is no published release yet

## Implemented instead

`--projects` creates three Projects v2 (`<repo> Portfolio`, `<repo> Delivery`, `<repo> Ops`) owned by the repository owner and linked to the repository (GraphQL `createProjectV2`; needs the `project` scope), adopting any with the same title; they hold views only. `--gates` writes exactly `aayudha-token.yml` (the WP1.4 broker) and `aayudha-ready-guard.yml` (golden-tested); the guard installs the binary with `go install …/cmd/aayudha@<release tag>` (a development build installs `@dev`), runs `aayudha ready <n> --guard --ci` with the workflow's own `issues: write` token, and never writes the ledger. `--identity` serves a local page that posts the App manifest (contents, issues, pull requests write; actions, checks read; no webhook) to GitHub, takes the code GitHub redirects back with, converts it, seals the private key straight into the repository secret `AAYUDHA_APP_PRIVATE_KEY` (libsodium sealed box, `golang.org/x/crypto/nacl/box`), sets the variable `AAYUDHA_APP_CLIENT_ID`, adds `[identity] app_id app_slug broker` to config, makes the App the ledger ruleset's only bypass actor in place of the admin role (D1), and prints the App's installation URL; the key never touches disk or the actions log. `--integrations` adds `[integrations.<name>] secret scope = "read"` for PostHog, Sentry, and GrowthBook (values are set with `aayu auth set-secret`) and, on a terminal, `[proof] media` for an `s3://` or `r2://` bucket. Each flag first looks for what it would create and asks only when something is missing, so reruns write nothing. The App, projects, and integrations are recorded as external objects: `uninit` keeps them and `uninit --external` lists them; `uninit` deletes the secret and variable it set
