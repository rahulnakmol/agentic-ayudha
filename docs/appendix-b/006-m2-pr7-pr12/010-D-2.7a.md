# D-2.7a

## Plan assumption

WP2.7: body → typed struct by heading; `ready` posts a replace-in-place snapshot (body hash + Completion Goal hash), writes `specs/<id>/ready.md` under the bot or the tagged human identity; a guard workflow strips `status:ready`; accept: "`audit` fixture lists" the human-fallback snapshot

## Finding

`audit` is WP7.6. The plan does not fix the hash inputs, the snapshot's form, or the guard's identity; D1 rules out the workflow token for ledger writes

## Implemented instead

`workitems.Parse` maps level-2 and level-3 heading sections (the issue-form layout; headings inside code fences are ignored) to fields by label or field ID; the type is the GitHub issue type or the `type:<type>` label (they must agree, R1); a section that is not a field of the type is a problem. Feedback and Incident are intake and never Ready. Body hash: SHA-256 of the body with CRLF→LF, trailing spaces trimmed per line, and the whole trimmed. Completion Goal hash: SHA-256 of the canonical JSON of the parsed criteria with Measure, Threshold, Scenario, and Environment. Technical Owner: the body's value, else the Code Architect seat's paired human, else the literal "the Code Architect twin". `ready` resolves the parent (sub-issue API) and the types of linked issues, validates, and on a pass writes the ledger file (snapshot plus the body at Ready), then the `<!-- aayudha:ready-snapshot -->` comment, then the labels (`status:ready` replaces any other `status:*`, plus `identity:human-fallback` on the day-one path); a failing item writes nothing and exits 4, as does `--check`. A rerun on an unchanged item writes nothing. The guard (`ready --guard --ci`, run by `aayudha-ready-guard.yml` with that workflow's `issues: write` token, stamped `ci` in the actions log) removes `status:ready` and explains in a `<!-- aayudha:ready-guard -->` comment when the item no longer validates, has no snapshot, or its body hash differs from the snapshot's; it never writes the ledger. Until `audit` exists, the actions log is what it will reconcile: every human-fallback write is a record with `"identity":"human-fallback"` (the test greps it with `aayu actions grep`)
