# D-2.1b

## Plan assumption

WP2.1: Priority/Effort/Risk/Health/Horizon "as labels on personal repos, GitHub issue fields where available"

## Finding

GitHub issue fields are organization-level and in preview, with no support in go-github v90 (the newest release whose `go` directive fits the 1.25 floor, D5)

## Implemented instead

Every repository uses labels in 0.1 (`priority:P0–P3`, `effort:XS–XL`, `risk:low/medium/high`, `health:on-track/at-risk/off-track`, `horizon:now/next/later`; values proposed here), with one label per prefix enforced by validation. The label is the only home, so these are not form fields. Delivery Status is `status:<value>`. Moving a field to issue fields later is a schema-version migration (WP1.9)
