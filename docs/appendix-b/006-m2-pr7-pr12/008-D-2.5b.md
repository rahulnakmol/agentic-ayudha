# D-2.5b

## Plan assumption

WP2.5: init writes the ledger ruleset, then config and `AGENTS.md`; D-4.2b.h: the ledger rulesets

## Finding

Defect (1) of D-5.5c.12 (live megaman test, PR #269): on a private personal repository on GitHub Free, `aayu init` stopped at the ruleset step with GitHub's 403 "Upgrade to GitHub Pro or make this repository public to enable this feature." (rulesets need Pro on a private personal repository; the list call `GET /repos/{repo}/rulesets` already refuses), and `--resume` retried the same step, so `config` and `agents` never ran

## Implemented instead

The ruleset step treats that 403 (status 403 and GitHub's "Upgrade to GitHub" message) as "not applied": init prints `not applied ruleset aayudha-ledger` with GitHub's message, that the ledger branch is unprotected (anyone with write access can force-push or delete it), and the fix (make the repository public or upgrade, then run `aayu init` again); records the message as `rulesets_unapplied` in `.aayudha/state.json`; and carries on, so `config` and `agents` run and init exits 0. A later `aayu init` applies the rulesets once the plan allows them and clears the record. Any other error still stops the step. New `doctor` row `ledger-rulesets` warns with the recorded reason and the fix. Regression test `TestInitWithoutRulesets` (the fake answers every rulesets request with GitHub's 403; without the fix init exits 5: "init step ruleset: GET …/rulesets: 403 Upgrade to GitHub Pro …"); doctor's row is in `testdata/checks.golden`. Live (2026-10-16, private scratch `rahulnakmol/aayu-scratch-1792183418877274608`, owner plan `free`, deleted after the run): `aayu init --yes` exited 0 with the `not applied` line, wrote `.aayudha/config.toml` and `AGENTS.md`, and pushed the ledger branch; `aayu doctor` printed `WARN ledger-rulesets ledger rulesets not applied: GitHub answered 403: Upgrade to GitHub Pro or make this repository public to enable this feature.`
