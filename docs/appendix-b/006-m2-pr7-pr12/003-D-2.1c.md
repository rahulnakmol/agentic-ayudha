# D-2.1c

## Plan assumption

WP2.1 parents, WP5.3 `grill`: a vague single-feature ask forced a Goal, an Initiative, and a Feature before its Story (release #268)

## Finding

Megaman, D-5.5c.12 defect (8) (PR #269, squash 68b65fa): from a fresh repository, Claude Code given "Make the CLI simple and fast." ran `grill --assess` (verdict `unpack`), asked four questions, and then filed a Goal, an Initiative, a Feature, and the Story. A Goal's Metric must be a snapshot name or a provider query, so the agent filed `north_star` as a stand-in. Cause: the schema required a parent Feature for a Story at Ready (and an Initiative for the Feature, a Goal for the Initiative), and the skill told the agent to pass `--parent <feature>` and to propose a Goal

## Implemented instead

Founder decision (2026-10-16): a vague ask produces a Story directly, and parent items are offered only when the human states a real goal. Schema: a Story's parent Feature is allowed but optional at Ready (Feature, Initiative, and Experiment keep theirs). `work-items/README.md` and the forms are regenerated, and a form with an optional parent says "If it has a parent …". Skill: a Story stands on its own; `--parent` only for an open Feature the facts show and the human confirms; a Goal (and its chain) only for a goal the human states with their own number; never a stand-in metric. `story.md` asks about a parent the same way. Regression test: TestReadyFailures "story without parent is Ready" fails on the old schema; `ready 6 --check` (a parentless Story fixture) now passes. Not changed: D-5.5c.12 (8)'s other half (`grill` refuses `status:in-progress`, and no verb sets it)
