# D-2.5a

## Plan assumption

WP2.5: init writes labels, issue types, forms, `.aayudha/config.toml`, `AGENTS.md`, the `ledger` branch, and `.aayudha/state.json`

## Finding

The repository files cannot be pushed to the default branch: on a governed repository it takes pull requests only, and forms and config are protected paths. The plan names no ledger ruleset for init, though WP0.1 expects `ledger` to be protected and "adds its rulesets alongside existing ones" implies one. A run needs a stable scope for idempotency keys that a later uninit/init cycle does not reuse

## Implemented instead

GitHub objects go through the API (`internal/initrepo`, every write an action): labels, issue types (organizations only), the orphan `ledger` (a tree, a parentless commit, and the ref; on a private repository with `.gitattributes` LFS lines for media extensions and a `.lfsconfig`; on a public one with neither), and ruleset `aayudha-ledger` (deletion, non-fast-forward, and update restricted; bypass: repository admin role, D1) unless an active ruleset already protects `refs/heads/ledger` with deletion and non-fast-forward rules. Repository files are written into the local checkout, and init prints that they must be committed through a pull request: `.github/ISSUE_TEMPLATE/aayudha-<type>.yml`, `.aayudha/config.toml` (only when absent; public repositories get `[proof] media = "" # required: private bucket`; a repository without `dev` gets `[branches]` mappings, a new config section), `.aayudha/.gitignore` for runtime state, the `work-items` section of `AGENTS.md` through the shared `internal/hosts` renderer, and `state.json`. Objects that exist already are adopted (recorded with `adopted: true`) and never changed; a file that exists with other content is kept and reported. State records each object's GitHub ID (labels, types, rulesets) or SHA (ledger) after every write, the completed steps, and a run ID that scopes idempotency keys. An incomplete state refuses a plain rerun (exit 2) and `--resume` continues; a complete state reruns as a no-op. `init` and `uninit` need a yes on a terminal or a human's `--yes`. `uninit` deletes, by stored ID, what init created and nothing it adopted; it keeps a ledger that has been written to since init and files edited since init, removes init's `AGENTS.md` section, and deletes `state.json` when nothing is left. `proof push --media` (WP4.2) exists only as the V3 refusal: exit 4 while `[proof] media` is empty on a public repository. `doctor` gains `ledger-media`: a public repository whose ledger has LFS configuration is a floor-blocking failure
