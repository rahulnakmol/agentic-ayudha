# D-0.4g

## Plan assumption

WP0.4 and D-0.4a: the stable gate's `smoke` job runs every unit test on Ubuntu, macOS, and Windows

## Finding

Stable gate run 38742897657 on `dev` failed on macOS and Windows. Three product defects: `status --work` compared `git worktree list`'s resolved, forward-slash paths with the unresolved checkout, so it listed no worktree on macOS (`/var` is `/private/var`) or Windows (a WP5.5b regression); the floor sandbox's `lookPath` accepted only `.exe` on Windows, so a tool installed as a `.cmd` shim (npm's `lighthouse` and `impeccable`) never resolved, and `node_modules/.bin/<tool>` resolved to the POSIX script; and the ledger lock treated Windows' "access denied" on a lock file another writer is deleting as an error, so concurrent writers failed. The rest were tests that assumed Unix: `syscall.Kill`, shell stand-in tools without a Windows extension, Unix permission bits, `/`-separated or drive-less paths, LF in a `core.autocrlf` worktree, a Windows path in a TOML basic string, and case-sensitive variable names. `internal/cli` is not hung on Windows: it takes about 880 s (`TestReleaseFailsClosed` 336 s), since git starts about ten times slower than on Linux, past `go test`'s 10-minute default

## Implemented instead

Product: `status --work` resolves both sides (`filepath.EvalSymlinks`, which also expands 8.3 names such as `RUNNER~1`); floor tools resolve through `exec.LookPath` per PATH entry, so PATHEXT applies on Windows; the ledger lock retries on "access denied" on Windows until its timeout. The smoke job runs `go test -timeout 30m`. Tests take the OS's paths and line endings, and Windows stand-in tools are `.cmd` files that run the shell script with Git for Windows' `sh`. Not supported on Windows, by test and here: `examples/benefits-qa/deploy/serve.sh` is POSIX `sh` that tracks the app by Unix pid, so its tests are `//go:build unix`; the benefits-qa interrupt test sends itself SIGINT, which Windows cannot (Ctrl+C reaches the same `signal.NotifyContext`), so it is Unix only. Different on Windows, asserted only on Unix: the age secrets file and identity have no `0600` mode, they take their directory's ACL (under the user profile: the user, SYSTEM, and Administrators), and aayu sets no ACL, so a `HOME` or `XDG_*` directory outside the profile shares its access; a floor's child sees one of `HTTPS_PROXY` and `https_proxy`, since names are case-insensitive; and an actions log path under a file reads as missing (Windows reports the path not found), as it does when the log is absent
