# S-B1

## Plan assumption

Appendix B is one table per section in `docs/BUILD-PLAN.md`, and every work package appends its rows there (AGENTS.md, "Source of truth").

## Finding

Parallel branches appending rows to the same file collided about 12 times in 10 threads: end-of-file rebase conflicts, one resolved into malformed headings, and one row ID reused by a concurrent change ([agent steering patterns](../../research/agent-steering-patterns-2026-10.md), P5; Feedback 330). No check caught a duplicate ID.

## Implemented instead

Story 397: every row since PR1 is a file, `docs/appendix-b/<NNN>-<section>/<NNN>-<ID>.md`, read by `internal/appendixb`. `go generate ./...` fails on an ID used twice, a wrong heading, or a bare `\|` (`TestDecisionIDsUnique`), and moves a row written in `docs/BUILD-PLAN.md` by hand into its own file with an error annotation that names `docs/appendix-b/` and AGENTS.md, so `generate-drift` fails until the file is committed (`TestAdoptHandWrittenRows`). Two branches that each add a row, even with the same number, merge without a conflict (`TestParallelRowsMergeCleanly`). The migration of 365 rows in 39 sections is lossless: `go run ./internal/appendixb/gen -print` reproduces the old tables byte for byte. Relative links in a row are written relative to its file, so the docs job's link check checks them there. AGENTS.md, CONTRIBUTING.md, and `docs/appendix-b/README.md` say how to add a row.
