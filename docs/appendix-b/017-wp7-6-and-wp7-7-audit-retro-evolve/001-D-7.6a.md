# D-7.6a

## Plan assumption

WP7.6 `audit`: floors, proof coverage, waivers, decision SLA, autonomy exceptions, reconciliation of GitHub audit events against `actions` segments (flags unlogged writes), licence scan; report to `ledger/audit/<date>/`; inputs (`ledger` SHA, GitHub event cursor, actions segment list, config hash) in the header; accept: dogfood outputs match fixtures, a direct `gh` write outside `actions` is flagged, a solo-mode self-approval (WP0.1) and a human-fallback write (WP1.4) each appear, a re-run with the recorded inputs is byte-identical. WP0.1 and D2: the hand-run reconciliations on the ledger (`audit/2026-10-11/…`, `audit/2026-10-12/…`) are what `audit` automates

## Finding

GitHub has no single event stream with a cursor. Rule suites (`rulesets/rule-suites`) need a repository admin token, are listed for at most a month (`time_period`), and list no actor for a deploy-key push (D1); the repository events API stops at 300 events or 90 days; issue timelines carry no request identity, so a write can be tied to an actions record only by request, target, and time. Nothing distinguishes a raw `gh` write from an `aayu` run whose segment never reached the ledger (D-M4.5a, D-4.10b). D2 made the self-approval a ruleset bypass after a "Solo-mode bypass:" comment, and D-4.10a added `ship --solo-bypass`. The plan names no rule for which PR delivered a story, and stories #38–#50 merged before the merge gate and `ship` existed (founder decision, 2026-10-12: done but unproven, counted as uncovered)

## Implemented instead

`internal/audit`: `Fetch` reads every source up to `--until` (the cursor, exclusive) and the ledger at `--ledger` (a new `ledger.Writer.ReadAt`, which must be the tip or an ancestor, and `Tree.Log` with the `Aayudha-Identity` trailer); `Build` is pure and `Markdown` holds no clock reading but the inputs, so the same inputs give the same bytes. Because GitHub's history is mutable (a comment can be edited) and rule suites age out after a month, everything read from GitHub is also frozen into a GitHub inputs snapshot (`audit/<date>/audit-<cursor>.inputs.json`, comment text cut to its first 160 bytes, PR bodies reduced to the stories they reference) written in the same ledger commit as the report; `aayu audit --replay <snapshot>` regenerates the report byte for byte from the snapshot and the recorded ledger commit without asking GitHub, and refuses when the configuration hash differs. The header records the window, the cursor and the newest rule suite, the snapshot path and SHA-256, the ledger commit, the code commit (the dev commit at the cursor, for the licence scan), the SHA-256 of the effective config, and every segment with its SHA-256 and record count, plus both regeneration commands (`--replay`, and a live re-read with `--since --until --ledger`, which gives the same bytes while GitHub is unchanged). Bypasses (rule suites with result `bypass` pushed in the window, each read in full for its failed rules) are classified: a PR merge (the suite's `after_sha` is a merged PR's merge commit) is a **solo-mode bypass** when the only failed rule is a required status check whose details name only `protected-paths` and a comment starting "Solo-mode bypass:" came at or before the push, otherwise unexplained (no comment, or another check bypassed); a push to the ledger branch is a **founder-identity ledger write (D1)** when its commit is in the ledger history at the recorded commit, a deploy-key push named from that commit; a push to `rolling`/`main` is a **promotion** when its commit subject is `Rolling snapshot: …`/`Release: v…` and a successful `ci.yml` `workflow_dispatch` run (the gate) on that commit started before the push; a `v*` tag bypass is accounted for when the tag is on `main`, when `release.yml` refused it (rule 8), or when a never-released tag is deleted; anything else is unexplained unless an earlier report on the ledger lists its rule-suite ID (every table row of a hand-run reconciliation; only rows an `aayu audit` report marks accounted for). `ship --solo-bypass` passes come from the ship records. Human-fallback writes: segment records with identity `human-fallback`, items labelled `identity:human-fallback` in the window, and ledger commits with that trailer. Unlogged writes: every write in the timelines of items changed in the window (creations, comments, labels, closes, merges, reviews, sub-issues, …; mirrors and consequences left out), every `workflow_dispatch` run, and every ledger commit, matched, oldest first, to a done segment record with the same request and target within 10 minutes, each record accounting for one write (one per label of a labels request), a comment record whose result is a comment ID matching only that comment, and a dispatch record matching only a run of the workflow file it dispatched, so a logged write cannot cover a direct one beside it; `…[bot]` actors that are not `[identity] bot_logins` are workflow and App writes, recorded by their runs; the rest are listed, grouped by target. A story is delivered when its status at the cursor is merged, released, measured, or done, or a PR merged into dev delivers it: a `story/<n>-` branch or `Refs #n` (Closes, Fixes, Resolves) in the body, or, in a PR with no such reference (written before the convention), `Story #n`; the first such PR is the merge PR. It is covered by an authoritative pack that verifies against the Ready snapshot and whose floors hold; otherwise it is **merged without proof (pre-gate)** when its merge PR merged before GitHub registered `aayudha-merge-gate.yml`, else merged without proof, both uncovered. Labels at the cursor are replayed from the timeline for items changed in the window and for every story, bug, and Decision. Floors and waivers come from packs created in the window (misses counted in authoritative packs); Decision SLA is business hours of `[time]` from creation to close or the cursor; autonomy exceptions are WP5.7 corrections and agent merges on `[autonomy] never` layers; the licence scan checks every go.mod requirement of the code commit against a THIRD_PARTY_NOTICES.md row with the same version and an allowed licence (the CI allow list) and reports the CI `security` job's conclusion on that commit (go-licenses and the npm scan). Without an admin token `audit` exits 4 rather than report an incomplete reconciliation; unexplained bypasses, unlogged writes, and uncovered stories are reported, not an exit code. The report goes to `audit/<date>/audit-<cursor>.md` under the bot, or the founder tagged `identity:human-fallback` (D1), and the run's segment is checkpointed; an identical report already at the tip is not written again. `--since` defaults to the cursor of the newest report, else seven days back. `audit --mark-merged <list>` (no report) moves listed stories the audit calls merged without proof (pre-gate) to `status:merged` with a replace-in-place `<!-- aayudha:audit-pre-gate -->` comment naming the merge PR and saying that no authoritative pack exists, through `internal/actions`, and refuses (exit 4, nothing written) any story that is covered, not delivered, or merged after the gate. Its first run here found two go.mod modules missing from THIRD_PARTY_NOTICES.md (`github.com/mattn/go-isatty`, `github.com/ncruces/go-strftime`, both MIT, via `modernc.org/libc`), added in the same PR. Tests: `TestAuditDogfoodFixture` (a synthetic copy of the hand-run reconciliations' cases against the fake GitHub and a local ledger with fixed commit dates and no machine git configuration, compared with the reviewed golden `internal/cli/testdata/audit/report.golden`), `TestAuditFlagsUnloggedWrite`, `TestLoggedCommentIsNotReused`, `TestLoggedDispatchNamesItsWorkflow`, `TestClassifyBypasses`, `TestAuditSoloBypassAndHumanFallback`, `TestAuditRerunByteIdentical` (a live re-read after the ledger moved on, then a replay after the solo-mode comment is edited and the rule suites age out), `TestAuditMarkMerged`, `TestAuditGitHubErrors` (any GitHub error exits 5 and writes nothing)
