# D-1.7a

## Plan assumption

WP1.7 check list and "nonzero on floor-blocking failures"

## Finding

Several checks depend on later WPs or have no GitHub API (LFS quota on personal accounts); the plan does not name the exit code or how hosts are detected

## Implemented instead

`internal/doctor` runs 20 checks as pure functions of a probe, each golden-tested on a healthy and a failing fixture (`testdata/checks.golden`). Floor-blocking (exit 3): git < 2.40 or missing, git-lfs missing, invalid config, a repository schema newer than the binary. Warnings never fail: development build or newer release, missing `gh`, no or over-scoped token, bot identity not configured (day-one path), no detected host (`AMP_THREAD_ID`, `CLAUDECODE`, `CURSOR_AGENT`/`CURSOR_TRACE_ID`, or `--host`), no writable secrets backend, missing optional tools (one row), leaked worktrees, integration secrets not set. Not yet available: skill copies vs `lock.toml` (WP3.2), MCP registrations (WP3.3), LFS quota (WP4.2), stale leases (WP5.5), provider reachability and real key scope (WP5.2). Coexistence: local workflow files and their check names, branches other than dev/rolling/main/ledger, the default branch and the `[branches]` mapping `init` will write, rulesets through the API, and collisions with `aayudha-*.yml` or `aayudha/` checks. `--fix` reports nothing to re-sync until WP3.2. `--all` checks each `[fleet]` repo through the API
