# D-1.4b

## Plan assumption

Appendix B D2: extend `protected-paths` to pass on a human CODEOWNER's approval of the head commit

## Finding

`pull_request_target` does not fire on reviews, and `pull_request_review` runs the PR's own workflow file

## Implemented instead

The gate logic is Go (`internal/identity.ProtectedPathsGate`, fixture-tested) run from a checkout of the base branch (the `pull_request_target` default; never the PR). A review fires `protected-paths-review.yml` (no token, no checkout), whose completion fires `protected-paths-rerun.yml` from the default branch, which re-runs the base-branch `protected-paths` run for that head SHA. Latest decisive review per reviewer counts, as on GitHub; every protected path needs one of its own owners; `[identity] bot_logins` is read from the base branch's `.aayudha/config.toml`. Only root-anchored literal CODEOWNERS patterns are supported; any other pattern fails the gate closed. Team owners are not resolved
