# D-1.3a

## Plan assumption

WP1.3: "after every secret-handling command" and a headless-Linux CI job for the env and file backends

## Finding

V7 fixes the plumbing list, so there is no `secret` command; the plan does not say where the age key lives; provider scope APIs belong to the WP5.2 adapters

## Implemented instead

Secrets are handled by `aayu auth set-secret <name>` (value from stdin only, refused for agents), `auth delete-secret`, `auth list-secrets` (names and backends, never values), and `auth status`. File backend: an X25519 identity at `$XDG_CONFIG_HOME/aayudha/age-identity.txt` and the ciphertext at `$XDG_DATA_HOME/aayudha/secrets.age`, both 0600. The canary test runs each command against a store whose keychain is unavailable (as on the `build` job's headless Ubuntu runner, which is the headless-Linux CI job) and scans home, repo, temp, and output. `[integrations.<name>] scope` is enforced before any call by `secrets.CheckScope` (a read verb refuses a `write` key); verifying the key's real scope with the provider is n/a until WP5.2
