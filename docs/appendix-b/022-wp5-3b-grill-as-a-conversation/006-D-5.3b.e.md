# D-5.3b.e

## Plan assumption

WP5.3b: works in the CLI TUI, the MCP prompt, and the host skill

## Finding

The TUI runs without a model, so it cannot reflect, propose, or brainstorm

## Implemented instead

The TUI asks the idea first, runs the assessment, and inserts one question per dimension of each qualifier with its default and up to three facts; an answer may be `default`, `park`, or `defer`. The Completion Goal question shows what the human said. The human writes every criterion, so each is recorded `stated (interview)`; accepted defaults become Assumptions, `defer` an open question, `park` a parked idea, and an unsettled qualifier is deferred with an open question. The review screen is the readback ("Here is what done looks like …", also returned as `readback` by `grill --json` for the host). Brainstorming is the host skill's job (its "How a grill goes" and "Voice"); the MCP prompt carries the same instructions and, with `idea`, the assessment
