# D-5.3b.c

## Plan assumption

WP5.3b: Ready validation flags remaining vague words in criteria; catalogues as data that grow per domain

## Finding

"Resolved" is a judgement; a rule can only approximate it

## Implemented instead

Six catalogues (`ux`, `perf`, `simple`, `sec`, `scale`, `rel`), parsed strictly by `grill.LoadCatalog` (a heading with the domain ID, a `Qualifiers:` list, and `### <Name> (<domain>.<id>)` dimension headings (the ID in backticks) each with Ask, Default, Evidence, and Facts); a malformed catalogue is an error. Qualifiers match whole words, case-insensitively, hyphen or space ("high-quality" = "high quality"), longest first, never inside quotes or backticks (UI copy and paths are literal). The rule: a criterion (state and expected) or Threshold that contains a qualifier and no digit outside quotes is refused with the catalogue to use; "fast: p95 under 200 ms" and "clean at 390 px and 1280 px" pass. The UX catalogue keeps accessibility "beyond the floors only if asked" and performance budgets as a confirmation, not a default criterion, so the D-5.3c floor rule stands
