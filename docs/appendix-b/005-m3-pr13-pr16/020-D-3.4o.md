Neither error was the skill's or the case's: one call got a server error inside its stream (`api_error: Internal server error`), and one reply degenerated into 32000 tokens of `<br>`, the model's sampling, not anything the session asked for. map-drift is the longest session (six to eight calls a run), so it meets the most provider faults. Who was wrong: the harness. It retried a call once only when the network dropped it, but a 5xx from the gateway (the 524s and 502s of earlier runs) and a server error inside a stream are the same kind of fault: the call failed, not the reply, and a model call writes nothing

## Implemented instead

A call is retried once on a dropped connection, a 5xx, or a stream `api_error` or `overloaded_error` (`models.StreamError`; `TestTier2RetriesServerErrors`, which also holds that a 400 is not retried). A retry repeats a failed call, never a judged run. A degenerate reply at the cap is not retried (a retry under the same cap would usually stop there again) and stays an error, within the one a case may have. No skill, case, floor, or rubric changed.
