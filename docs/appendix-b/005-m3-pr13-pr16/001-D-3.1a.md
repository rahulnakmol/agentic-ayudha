# D-3.1a

## Plan assumption

WP3.1: frontmatter includes `paths`; lint checks "every `aayu` call resolves", hooks, and Mobbin-origin images

## Finding

Claude Code reads `paths` as globs that limit when the model loads a skill on its own, so an empty list would hide a skill; the plan gives no globs per verb, and a product repo's layer globs are its own. Prose mentions of the binary ("the aayu binary") are not calls. A skill's hooks live in its frontmatter (Claude Code `hooks`). Mobbin terms forbid its pixels, not links to it

## Implemented instead

`paths` is a registry field (`Command.Paths`), rendered only when set; no verb sets it yet. `internal/skills.Lint` replaces the WP0.4 subset (D-0.4e) and runs over the embedded tree in `go test` (`TestSkillLint`, CI job `build`). Calls are read from inline code, fenced code, and `scripts/`; a call resolves when the command is in the registry, a bare first argument is a value of an enum first positional, and every `--flag` is the command's input or a global flag (`verbs.GlobalFlags`, moved from `internal/cli`). `scripts/` may hold only comments, `set` options, and `aayu …` lines without shell operators. Hooks must be `type: command` with the command exactly `aayu hook <name>` (optionally `--host <host>`). Mobbin: an image file whose name or bytes (embedded metadata) mention Mobbin, or an image embed whose URL does; plain links pass. A ninth rule rejects symlinks (V2). Each rule has a failing fixture in `internal/skills/lint_test.go`, with 200/201-character descriptions and 500/501-line bodies at the boundary
