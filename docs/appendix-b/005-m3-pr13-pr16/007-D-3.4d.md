## Implemented instead

`models.Response` carries `StopReason` (Messages `stop_reason`, Responses `status` with `incomplete_details.reason`, Chat `finish_reason`) and `Truncated` (stopped at the cap). `models.Structured` returns a truncated reply at once as a `ReplyError` marked `Truncated`, without a retry under the same cap. Every run in the results file lists each model call: role, model, stop reason, truncated, input and output tokens, cap, and any call error. A truncated reply makes the run an `error` whose message starts `truncated:`, with the reply's start and end as the excerpt. Reaching `max_usd` records the remaining runs as errors and still writes the results file. Follow-up (founder decision, 2026-10-12, after run 38185993917 measured complete drafts at 1700-2430 output tokens and showed `input_tokens` 2 on every Anthropic call): the skill cap is 4000 output tokens and `max_usd` is 3.0 (five 4000-token drafts with their judgements cost about 1.85 USD at the fallback rate); the skill model is the registry lane of the verb the skill is or stands in for (`[tier2] verb`; the stub stands in for `grill`, lane `spec`: `claude-opus-5-5` today), never a lane or model named in the case, and when that model's call fails at the endpoint the lane's registry alternative (`ModelDefault.AlternativeID`, `claude-sonnet-5-5`) takes it; the judge stays pinned and must differ in family from both; Anthropic `cache_read_input_tokens` and `cache_creation_input_tokens` count as input tokens (at the full input rate) for cost and the `[budget]` breaker. Rubric and stub skill: conventions of the format the request names (a CSV header row) are not invented requirements; exact column order, content type, encoding, file name, size limits, and durations are. csv-export gains a size-limit scope rule, and `TestScopeConventionVersusInvented` keeps both sides of the line: a header row passes, each invented specific fails
