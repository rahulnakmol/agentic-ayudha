# D-3.2a

## Plan assumption

WP3.2: `install` writes copies, `lock.toml`, `AGENTS.md`, the `CLAUDE.md` stub, MCP registrations "using the absolute binary path with version check", host hooks, and an Amp plugin stub; user-home edits are listed and confirmed separately; golden trees per host incl. Windows

## Finding

Amp reads `.agents/skills/` (and `.claude/skills/`), Cursor `.agents/skills/` (and `.claude/skills/`), Claude Code `.claude/skills/`. Amp's workspace MCP servers (`.amp/settings.json`) need a per-machine `amp mcp approve`; its user settings do not. Claude Code's project servers (`.mcp.json`) need enabling. A Cursor permission hook must print valid JSON or it blocks the action; exit code 2 blocks in Claude Code, Cursor, and (by the stub's choice) Amp. An absolute path is specific to one machine

## Implemented instead

Hosts: Amp and Cursor get `.agents/skills/<verb>/`, Claude Code `.claude/skills/<verb>/`, all as real copies; a symlinked `.claude/skills` (the pre-V2 setup) or skill directory is replaced by copies. MCP: `.cursor/mcp.json`, `.mcp.json` (enabled through `enabledMcpjsonServers` in `.claude/settings.json`), and `amp.mcpServers` in `~/.config/amp/settings.json`, the one home edit; a `settings.jsonc` or a file that is not plain JSON is left alone with a note to add the entry by hand. Every registration and hook runs the symlink-resolved absolute path of the running binary, and install first runs `<path> version` and refuses (exit 5) unless it reports this binary's version. Hooks are `aayu hook session-start` (reports copies out of sync with the lock) and `aayu hook pre-tool` (blocks tool calls while the `[budget]` breaker's pause file exists; `halt` is n/a until WP5.7), registered as Claude Code `SessionStart` and `PreToolUse` (matcher `*`), Cursor `sessionStart`, `beforeShellExecution`, and `beforeMCPExecution` (JSON replies), and the Amp plugin `.amp/plugins/aayudha.ts` (`session.start`, `tool.call`). JSON files are merged: only aayudha's server entry and hook entries (recognised by their command) are replaced, keys come out sorted. `AGENTS.md` gets the `skills` and `hosts` sections through `hosts.RenderAgentsMD`, the one renderer agreed with WP2.5 (`<!-- BEGIN aayudha:<id> -->` markers; text outside them is never changed). `CLAUDE.md` is a stub importing `@AGENTS.md`, or an existing file gains that line. `lock.toml` (schema v1) records `installed_by`, `skills_version`, `pin`, the hosts (they accumulate across runs; with no `--host` the lock's hosts, else all), and per-skill SHA-256 over the skill's files with LF line endings, so one lock serves every OS. On Windows every text file is written with CRLF; a file that differs only in line endings is not rewritten, so re-apply is a no-op on either. `--host` reads the global flag (`amp`, `cursor`, `claude`, `all`). `--pin` must equal the skills version this binary carries; a lock pinned to another version is refused (exit 4) until `--pin` moves it. `--apply` is refused for agents (exit 4); home edits apply only after a terminal "y" or a human's `--yes`, and otherwise the repository edits land and install exits 4 naming the skipped home edits. `doctor` checks copies against the lock for real, and `doctor --fix` re-syncs copies and the lock (not hooks or registrations, which `install` rewrites); this is also how copies migrate to a new binary's skills, since lock schema v1 has no migrations. The absolute paths in committed host files mean each machine re-runs `install --apply`. Golden trees: `internal/hosts/testdata/golden/<host>-<unix\|windows>/`, from a two-skill fixture so they do not churn with every skill edit, byte-exact (Windows trees are CRLF, kept by `-text` in `.gitattributes`), no symlinks, re-plan empty; the CLI test installs the 30 real skills and lints the copies on disk with the WP3.1 lint
