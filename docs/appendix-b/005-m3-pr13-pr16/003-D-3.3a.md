# D-3.3a

## Plan assumption

WP3.3: tools generated from the registry; read + authoring verbs by default (`ready --check` among them); write verbs need `[mcp] expose_writes = true`; human-only verbs never exposed; long verbs report progress and honour cancellation and timeouts; prompts for `grill <type>` and `brief`; resources `aayudha://config\|status/<goal>\|ledger/<story>`; accept: "dry-run round-trip through `actions`"

## Finding

Several read-exposed verbs write on some inputs (`ready` without `--check`, `status --digest` pages through `[notify]`, `proof push\|purge`, `doctor --fix`), and two verbs take a human-only flag (`tell --publish`, `decide --accept`). The registry had no way to say so. No write verb has a handler yet: `triage` (WP2.9) is the first, in the parallel M2 stack

## Implemented instead

Server on `github.com/modelcontextprotocol/go-sdk` v1.8.0 (Go 1.25 floor), stdio through the CLI's `IO` (stdout carries only frames). One tool per verb with the MCP surface, its input schema read from the generated `internal/mcp/schemas/<verb>.json`. Exposure: `read` verbs always (`grill`, `slice`, `plan`, `proof`, `ready`, `research`, `status`, `brief`, `doctor`), `write` verbs only with `expose_writes`, `never` verbs (`decide`, `ship`, `release`, `respond`, `init`, `install`) and plumbing never. Two registry input fields close the gap, rendered into the schemas as `x-aayu-read-only-values` and `x-aayu-human-only`: `ReadOnlyValues` pins an input while writes are hidden (`ready` always runs with `--check`, `status` without `--digest`, `doctor` without `--fix`, `proof` only `get\|verify\|list`), and `HumanOnly` inputs are never exposed. Each call runs the verb in-process as an agent lane (`AAYU_AGENT=1`, empty stdin), with `--json`, flags, then `--` and the positionals, so no value is read as a flag; the server's `--repo` and `--set` carry through. Tools that can write take `dry_run`, which maps to `--dry-run`. Progress: a notification every 5 s while a call runs, when the client sent a progress token; each call has a 15 min deadline; a client cancellation cancels the verb's context. Prompts: `grill` (`type`) returns the skill body plus `skills/grill/references/<type>.md` (n/a until WP5.3, which says so), `brief` (`subject`, `register`, `purpose`) the skill body and the exact `aayu brief` call. Resources: `aayudha://config` (`config show --origin --json`), templates `aayudha://status/{goal}` (`status --json`, n/a until WP2.8) and `aayudha://ledger/{story}` (`proof get --json`, n/a until WP4.2); ids must be issue references. The round-trip test drives the real `aayu mcp` over stdio pipes with the SDK client and, because no write verb has a handler yet, a stand-in `triage` that makes one label write through `actions.Do`: with `dry_run` the result is the `planned` record, the actions log has it, and the fake GitHub saw zero requests; without it, `done` and one request. `doctor`'s MCP check is real: each locked host's registration exists and its absolute path runs and reports this binary's version
