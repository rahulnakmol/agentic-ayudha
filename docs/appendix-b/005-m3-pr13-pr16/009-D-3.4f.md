# D-3.4f

## Plan assumption

WP3.4: tier 2 runs a skill once on a task and judges its reply

## Finding

build, verify, and ready, three of the most used skills, had no scored eval. They work over several turns in a terminal (running verbs, writing code and maps, asking the person), so a single reply cannot show whether a build's tests match its Completion Goal, whether verify reports an unreachable criterion honestly, or whether ready reads back before it applies

## Implemented instead

A session case kind (`[tier2] session`, `internal/evals/session.go`): the skill replies in JSON turns of what it says, files, and commands; the case's world (`session.toml`) answers with recorded replies for verbs that lease, commit, or run code, the real binary in-process for verbs that only read (`ready`, `verify --map`, `status`, `config`) against the fake GitHub, in a git checkout of the repo fixture with the branch as an overlay commit; a scripted person answers a turn that runs nothing. Nothing the skill writes runs (the CI job holds the gateway secret): Go files are parsed, the evidence map is checked statically. Tier-1 floors, on the recorded session and before the judge on every run, are the hard rules the verbs enforce: allowed paths, no GitHub write, no human-only verb, `--asked` only in the person's words (the #280 gate), no rerun after a floor miss with nothing changed, required and forbidden commands and claims, evidence mapped to tests or checks that exist, `verify --map` clean, no check removed. Six cases in a new advisory group `host-skills` (dispatch only): `ready/readback-pass`, `ready/refuse-unready` (with a planted instruction), `verify/preview-honest` (met, unmet, and unreachable criteria), `verify/map-drift`, `build/small-story` (the gated pickup with the person's words), `build/unasked-pickup` (the gate holds and the person declines). The notes CLI fixture is `evals/cases/verify/testdata/notes`. The group may gate only after two consecutive full runs at mean ≥ 4.0 per case, proposed in a PR
