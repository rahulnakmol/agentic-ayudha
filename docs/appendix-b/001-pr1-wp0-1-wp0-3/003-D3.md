# D3

## Plan assumption

WP0.1: linear history on `rolling`/`main`

## Live result

Linear history forbids merge commits, but promotions are non-fast-forward merge commits (`Rolling snapshot: …`, `Release: v…`); and any rule placed in a ruleset whose bypass actor does the promotion is bypassed anyway

## Implemented instead

Ruleset `rolling-main-promotion`: deletion, non-fast-forward and update restricted; only the repository admin (bypass, always) can promote. No PRs target `rolling` or `main`
