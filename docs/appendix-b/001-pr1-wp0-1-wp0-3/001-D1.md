# D1

## Plan assumption

WP0.1: `ledger` is pushable only by the bot identity and CI

## Live result

**Partly enforceable.** A ruleset `update` restriction works on a personal repo: the founder's own token (repo admin) and Amp's user-to-server App token were both rejected (`GH013 … Cannot update this protected ref`), and a deploy key in the bypass list pushed (rule-suite `result: bypass`). But the GitHub Actions app (15368) cannot be a bypass actor on a personal repo (`422 Actor GitHub Actions integration must be part of the ruleset source or owner organization`), so CI's built-in `GITHUB_TOKEN` can never be a ledger writer. Only a GitHub App installed on the owner account is accepted, and only its installation tokens bypass; user-to-server tokens act as the user. Individual users (a machine user) cannot be bypass actors; only repository roles can. The rule-suite list shows no actor for the deploy-key push while the single-suite endpoint shows the repo owner's login, so `audit` must identify deploy-key writes from the ledger commit, not from the actor name

## Implemented instead

Ruleset `ledger-writers`: deletion, non-fast-forward and update restricted; bypass = repository admin role (the founder, day-one rule). WP1.4 `init --identity` replaces the admin bypass with the bot App (Integration actor), and CI writes `ledger` with that App's installation token (`actions/create-github-app-token`), never `GITHUB_TOKEN`. The machine-user fallback becomes a deploy key (or a repository-role bypass, which covers every collaborator in that role)
