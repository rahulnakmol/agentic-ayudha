# D-4.8b.2

## Plan assumption

WP4.8b: findings with severity, evidence (file:line), suggested fix; noise filtering (confidence threshold, de-duplication, style nits the linters own); learning from dismissed findings

## Finding

Model-chosen line numbers drift; self-rated confidence filtered poorly on its own in every published reviewer (research §1); aayudha has no vector store; in solo mode every agent (Cursor and Amp included) writes under the founder's account, so a 👎 reaction or a reply cannot be told apart from the builder's own

## Implemented instead

Findings v2 carry `category`, `quote`, `fix`, and `confidence`; aayu places each by its quote (an added line first), keeps the model's line only when it is in a hunk, else posts it in the summary only (line 0). `Filter.Clean`: a file outside the diff is dropped; `style`, and P2/P3 titles naming typos, formatting, imports, or naming, are linter-owned; files matching `[inspect] generated` or with a `Code generated … DO NOT EDIT` header are not reviewed; P2/P3 below `[inspect] min_confidence` (0.5) are dropped, P0/P1 never; P3 nits are counted, not posted; duplicates (same file, within 3 lines, title-and-detail word overlap ≥ 0.35, or the same fingerprint) merge keeping the highest severity. Dismissal is human-only: `inspect <pr> --dismiss <id> --reason …` (refused for agents, hidden from MCP) appends to `inspect/dismissed.jsonl` on the ledger; a finding is suppressed when it matches one dismissal's fingerprint, or resembles (word overlap ≥ 0.6, same file or directory) `[inspect] suppress_after` (2) distinct dismissals, never a P0 in security, data, or concurrency. A fix whose every P0–P2 finding was refuted or dismissed, with no unmet criterion, is lifted to merge with a note; the floors still downgrade it (rule 7). The comment lists what was not posted and why, and a collapsed review plan
