# D-5.5b.2

## Plan assumption

WP5.5b: hand the receiving agent the Ready snapshot, plan, and evidence map; prefer the most portable trigger with a per-host adapter; the PR must reference the story

## Finding

The receivers differ in transport: Cursor has a REST API that opens the PR; Amp's CLI starts an orb thread; claude-code-action answers an `@claude` comment but does not open PRs; Codex cloud has only the experimental `codex cloud exec` and a "Create PR" click (research §5). PRs from Cursor and Amp are opened as the human, so authorship identifies nothing

## Implemented instead

`internal/delegate`: one `Brief` for every receiver (the Ready snapshot's criteria from the ledger, the story body quoted as data, the plan's checkpoints, an evidence-map skeleton filled with the plan's tests, branch and PR rules with `Refs #n`, Conventional Commits and DCO, `[delegate] checks`, CODEOWNERS paths, the cycle cap, AGENTS.md abridged), passed through the actions log's redaction and a credential-shape filter; its SHA-256 is recorded. Adapters: `CursorAPI` (`POST /v1/agents` with `autoCreatePR`, `GET …/runs/{id}`, `POST …/runs`), `AmpCLI` (`amp -ox --project`, `amp threads continue`), `ClaudeMention` (an `@claude` comment on the story, then on the PR; aayu opens the PR from the pushed `claude/issue-<n>-…` branch), `CodexCloud` (`codex cloud exec`, `status`, and `diff`; aayu applies the returned diff in `.aayudha/worktrees/<n>-codex` and opens the PR through build's checkpoint, verify, and push). The PR is found by its PR URL, a `Refs #n` body or story branch, or the receiver's branch. Fixtures in `internal/delegate/testdata/` are synthetic, in the documented shapes; `AAYU_LIVE=1` tests skip without credentials
