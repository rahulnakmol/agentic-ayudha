# D-4.8b.3

## Plan assumption

WP4.8b: peer mode, two different-family reviewers cross-check before posting; general mode, one reviewer

## Finding

The registry's review lane is one model; a delegated Codex PR is built by the review lane's own family (OpenAI)

## Implemented instead

`[inspect] mode` (general) and `delegated_mode` (general since D-4.8b.7, for PRs with a `delegate/<n>/state.json`), or `inspect --mode`. Reviewer A is the review lane's model; when its family equals the builder's and it is a registry default, the first of `verbs.PeerReviewCandidates` (GPT-6.1 Sol, Grok 4.7, Gemini 3.1 Pro, Claude Opus 5.5) of another family reviews instead, with a note (a configured one is refused). Reviewer B is `[inspect] peer_model` or the first candidate whose family differs from both. Each reviews the same input; each one's single-source findings go to the other with `VerifySystem`, an asymmetric "prove it wrong" check (after OpenCodeReview's filter, as an idea: refute only what the diff contradicts, never for low importance); refuted findings are dropped, except a P0 in a protected category, which is posted as disputed. Dispositions combine to the worse; a criterion is unmet when either says so. When B fails, the review falls back to A in general mode with a note. The builder's family for a delegated PR comes from the delegation state on the ledger
