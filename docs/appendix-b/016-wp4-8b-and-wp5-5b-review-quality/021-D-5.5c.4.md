# D-5.5c.4

## Plan assumption

WP5.5b: Claude Code's cloud transport is the `@claude` mention through claude-code-action

## Finding

That action needs `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` as a repository secret, against the founder's rule of no AI keys in a product repository's CI. Claude Code on the web starts from the user's signed-in CLI: `claude --cloud "<task>"`, with follow-ups through `claude -p … --cloud <session>`; sessions push a branch and open no PR

## Implemented instead

`delegate.ClaudeCloud` replaces `ClaudeMention`: it runs `claude --cloud <brief>` in the repository, records the session ID and its `claude.ai/code` link, treats the branch the brief names as the signal (aayu opens the PR from it), and queues follow-ups on the session. Claude Code counts as cloud-connected when its CLI is on PATH; whether that CLI's claude.ai sign-in can start cloud sessions is checked by the agent-environments detection, which the routing PR adopts. `[delegate] claude_trigger` stays in the schema, unused, so 0.1 configurations still load. The fixtures are synthetic: no claude.ai sign-in was available
