# D-5.5c.24

## Plan assumption

WP5.5c, D-5.5c.22: a Codex that answers through its own model provider is ready to run locally

## Finding

Megaman D-5.5c.22: aicoder's `codex` is a wrapper that sets `CODEX_HOME` to a custom-provider configuration (`[model_providers.private_gateway.auth]`); `codex exec` answers, `codex login status` says "Not logged in", so `agentenv.Detect` and `aayu doctor` reported "not signed in" and `build --delegate codex --local` would refuse it. aayu cannot read the wrapper's `CODEX_HOME`, so only Codex can say how it will answer. Checked in this orb with codex 0.163.0: `codex doctor --json` loads the configuration as `codex exec` does and reports `checks["auth.credentials"]`: "OpenAI auth is not required for the active model provider" for a provider with an `auth` command; "active model provider auth env var is missing" (fail) for an `env_key` that is unset, and "auth is provided by the active model provider" once it is set; "no Codex credentials were found" with the default provider and no login. `checks["config.load"].details["model provider"]` names the provider. `codex doctor` exits 1 when any check fails, such as an unreachable endpoint, and still prints the report

## Implemented instead

When `codex login status` says not signed in, Detect asks `codex doctor --json` (15 seconds) and counts Codex as ready to run locally when `auth.credentials` is ok, the active provider needs no OpenAI auth, and its credential is not an environment variable other than `CODEX_API_KEY`: the local receiver's scrubbed environment never passes a model provider's key (D-5.5c.5), so such a provider would fail there. Doctor shows "codex: … runs through model provider `<id>`". Cloud still needs a ChatGPT login. Live: a wrapper setting `CODEX_HOME` to a provider with an `auth` command, old binary "not signed in", new binary "runs through model provider private_gateway". Trade-off: `codex doctor` probes the provider's endpoint, so Detect is no longer free of network calls in this one case (the guide says so). The scrubbed environment then dropped a `CODEX_HOME` set in aayu's own environment rather than inside a wrapper; fixed in D-5.5c.25. Test: `TestDetect`
