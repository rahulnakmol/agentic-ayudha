# D-5.5c.18

## Plan assumption

WP2.8: `status` rolls up Delivery Status

## Finding

Defect from the megaman run (D-5.5c.12 problem 9): while `build` held a lease and PR #5 was open, `status` counted Story #4 as Ready, because it reads only the label

## Implemented instead

`status` lists the repository's open pull requests once per walk. A story or bug still labelled `status:ready` whose open PR names it (its body says `Refs #n`, or its branch is `story/<n>-…`) counts as in progress. A PR that only mentions the story does not. Regression test: `TestStatusCountsAStoryWithAnOpenPRInProgress`
