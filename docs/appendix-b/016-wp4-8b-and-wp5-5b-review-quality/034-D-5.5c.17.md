# D-5.5c.17

## Plan assumption

WP2.1, WP5.5: Delivery Status moves as the work does

## Finding

Defect from the megaman run (D-5.5c.12 problem 8): no verb set `status:in-progress`, and `grill` rejects it on a new item, so a story stayed `status:ready` while it was built and delegated

## Implemented instead

`build` (and so `build --delegate`) moves the story from `status:ready` to `status:in-progress` when it takes the lease, and its later runs accept either label. Ready's body-hash check still runs on every build, which matters because the Ready guard acts only on `status:ready`. `blockBuild`, `ready`, and `ship` already replace every `status:` label. `grill` still refuses `status:in-progress` on a new item: only work under way is in progress. Regression test: `TestBuildLeaseAttemptsResume` checks the labels after the first build
