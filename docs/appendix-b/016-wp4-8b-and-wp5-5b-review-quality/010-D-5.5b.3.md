# D-5.5b.3

## Plan assumption

WP5.5b: the review loop ends at merge-ready or the cap; the receiving agent addresses the findings

## Finding

inspect runs in the merge gate, not in `build`; there are no webhooks from Cursor v1, Amp, or Codex; inspect stops calling the model after two fix cycles

## Implemented instead

Each later `build <n> --delegate <r>` syncs: the receiver's status, the PR, and inspect's state from its PR comment. On `fix` for the current head it sends one follow-up per head (`delegate.FollowUpMessage`: the finding IDs, places, and suggested fixes) through the adapter, or, locally, runs the CLI on it in the worktree and pushes a checkpoint; on `merge` it reports merge-ready and names `aayu ship <pr>`; on `rebuild`, or when the head moved after inspect's cap, it pages a human and exits 4. The hand-off, follow-ups, and local runs are actions (`delegate.handoff`, `delegate.follow-up`, `delegate.local-run`); `delegate/<n>/state.json` and a replace-in-place `<!-- aayudha:delegate -->` comment on the story record every step. The sync runs when the founder's host (or `/codex` … `/amp`) asks; a scheduled loop is later
