# D-5.5c.21

## Plan assumption

WP3.3, D-3.2b.c: the model in Codex is offered the aayudha MCP tools through the founder's AI gateway

## Finding

Founder request (2026-10-17), on megaman as `aicoder` (origin/dev `a8b26f2`, codex-cli 0.163.0). The Akmol gateway (`https://aisvc.akmols.cloud/v1`) was configured only in a throwaway `HOME` (`.codex/config.toml` custom provider, `wire_api = "responses"`, token inline). **D-3.2b.c reproduces, and the gateway is the cause.** With the aayudha plugin enabled (`codex mcp list`: `aayudha … enabled`) and the prompt "call the aayudha MCP tool named status", the model answered "I have no `aayudha` MCP tool named `status`" and listed only flat functions. A logging proxy between Codex and the gateway showed what Codex sent. With `gpt-5.5` (`supports_search_tool`), the request carried a `tool_search` tool (`"execution": "client"`, its description naming aayudha) and no MCP tools up front. With `gpt-5.4`, it carried a `namespace` tool `mcp__aayudha` holding 12 tools (`brief` … `survey`, `status` among them). Both got HTTP 200, and in neither did the model see or call an aayudha tool; it fell back to `list_mcp_resources` and `read_mcp_resource`. Direct `/v1/responses` requests (one tool `status`, the prompt asking to call it), for both `gpt-5.4` and `gpt-5.5`: as a flat `function` tool, the response echoed `tools: [["function","status"]]` and the output was a `function_call` `status`. As a `namespace` tool, the response echoed `tools: []` and the model replied "NO TOOL". As a `tool_search` tool, the response also echoed `tools: []` and the model replied "NO TOOL … No tools were given". So the gateway silently drops `namespace` and `tool_search` tools and returns 200. `go test ./internal/hosts -run 'TestHostPluginsLoad/codex' -v` passes; it uses a fake endpoint, not the gateway

## Implemented instead

No product change: aayu's MCP server lists its tools correctly, and Codex declares them correctly. To serve aayudha's MCP tools to Codex, the gateway must forward Responses `namespace` tools, and the `tool_search` tool with `execution: "client"`, unchanged. It must also forward the items that follow them: a `function_call`'s `namespace` field, and `tool_search_call` and `tool_search_output` input items. Otherwise it should reject them with a 4xx rather than drop them. Until then the aayudha skills still work in Codex through `aayu` in the shell (`docs/guide/hosts/codex.md`). The throwaway configuration and the proxy were deleted
