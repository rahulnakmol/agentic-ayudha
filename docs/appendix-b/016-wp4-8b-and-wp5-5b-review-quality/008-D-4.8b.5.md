# D-4.8b.5

## Plan assumption

WP4.8b: evaluate with seeded-defect PRs, precision and recall, general vs peer, before and after, through the eval harness

## Finding

The harness scores skills with a rubric judge; a reviewer is scored against known defects, and the review calls cost about 70 per run of the set

## Implemented instead

`[review]` cases in `evals/cases/inspect/`: twelve synthetic PRs (nine with planted defects of eight kinds, ten defects in all; three clean controls), generated as real `git diff` output, with the head's files stored as `<path>.txt` so this repository's build, linters, and scanners never compile or flag them. Tier 1 checks each case's construction (every defect on added lines). Tier 2 runs each case k = 2 times in three variants: `legacy` (the 0.1 prompt and schema, kept in `internal/evals/review.go`), `general`, and `peer`, four cases at a time, and scores what each would post: a finding within 3 lines of an unmatched defect in its file is a true positive, a second one a duplicate (false positive), any other a false positive; a run scores 1 + 4·F1 (a clean control 5 with no false positive, else 1). The results file gains per-variant precision, recall, F1, and clean-control false positives. The `review` group is advisory (never gates promotion) and runs only on `workflow_dispatch` (new group keys `k` and `events`; `cmd/eval` reads the workflow's `EVENT`), so `evals.yml` needs no change
