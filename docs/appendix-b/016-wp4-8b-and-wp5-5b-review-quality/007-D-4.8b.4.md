# D-4.8b.4

## Plan assumption

WP4.8b: posts structured, de-duplicated comments; requests fixes

## Finding

A bot or the founder's account cannot request changes on the founder's own PRs (D2), and receivers act on review comments

## Implemented instead

One PR review per run with event COMMENT (never APPROVE or REQUEST_CHANGES) and one inline comment per new P0–P2 finding placed on a line, each with its ID marker, fix, and any dispute; the IDs posted go into inspect's state so a later cycle posts only new ones. The summary comment and its state stay replace-in-place. The summary speaks as the Engineering Manager twin (Kiran, `seats/engineering-manager/persona.toml`) with the evidence rule; findings stay in the schema
