# D-5.5c.25

## Plan assumption

WP5.5c, D-5.5c.24: the local Codex receiver runs the Codex that Detect reported ready

## Finding

Open point of PR #359, decided for the founder (2026-10-17): `agentenv.Detect` runs `codex login status` and `codex doctor --json` with aayu's own environment, but `delegate.ScrubEnv` dropped `CODEX_HOME`, so with `CODEX_HOME` set in aayu's environment (not inside a wrapper) Detect could report a Codex ready that the receiver did not run. Checked in this orb with codex 0.163.0 and `CODEX_HOME` pointing at a custom-provider configuration: doctor's row said "runs through model provider private_gateway"; `codex doctor --json` in the old scrubbed environment reported `"model provider": "openai"` (it read `~/.codex`), and in the new one `private_gateway`

## Implemented instead

`CODEX_HOME` is a path, not a secret, so the scrubbed environment of a Codex receiver keeps it, like `HOME` (`receiverPaths`); no other variable is added, and no other receiver gets it. Detect and the receiver now read the same Codex home: Detect's probes inherit aayu's environment, and the receiver's environment is built from that same environment. The Codex cloud adapter, which uses the same scrubbed environment, keeps it too. Test: `TestScrubEnv`
