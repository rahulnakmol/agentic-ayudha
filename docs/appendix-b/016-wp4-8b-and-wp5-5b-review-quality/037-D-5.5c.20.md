# D-5.5c.20

## Plan assumption

WP5.5, WP3.2b: an agent builds only the work the person asked for

## Finding

Megaman defect D-5.5c.12 (3) (PR #269, squash 68b65fa): given "Using aayudha: …", Codex ran `--assess` (`unpack`), then took open Story #4, ran `aayu ready 4`, and built it to PR #5 without asking. D-3.2b.b (#276) added the routing rule as guidance only; nothing in `ready` or `build` held the story

## Implemented instead

Founder decision (2026-10-17): a gate with a warning. `build` holds an agent's pickup of a story labelled `status:ready` before the lease, the label change, and the worktree. It exits 4 with: `build #<n> "<title>": the person has not asked for this story in this session (<marker>), so build stopped before taking it. Ask them first: "Shall I build #<n>, <title>?" Build it only if they say yes, and pass their words: aayu build <n> --asked "<their words>"` (and `next:` the same command). An agent is `AAYU_AGENT=1` or a host's agent marker (`AMP_THREAD_ID`, `CLAUDECODE`, `CODEX_THREAD_ID`, `CURSOR_AGENT`; not `CURSOR_TRACE_ID`, which Cursor's own terminal sets for a person). Asked for means one of two things. Either the agent passes the person's words with the new `--asked` input, or `grill … --create` filed the story in the same session. grill notes each story it files in `.aayudha/state/asked.jsonl`. The session is `AMP_THREAD_ID`, `CODEX_THREAD_ID` or `CLAUDE_CODE_SESSION_ID`, and a note counts for 12 hours. A person in their own terminal is never held. A story already `status:in-progress` passes: later checkpoints, `--resume`, and the `ci-failed` loop's delegation sync (`AAYU_AGENT=1 aayu build <n> --delegate …`) continue work that was already asked for. Every confirmation and every hold is an actions-log record `build.asked` with the words, the marker, and the session, so the ledger shows who asked. `hosts.Routing` gains the same sentence (agreed with the hosts thread T-01a13d97). The build skill, `/codex`, `/cursor`, `/claude`, `/amp` (they pass the person's request word for word), `/next` (asking for the next step is not asking for a story), and the Amp palette's build entry say the same. Limit: `--asked` is the agent's report of the person's words, not proof. It is a deliberate, logged act instead of a silent default. A hard gate (a human-only flag the pre-tool hook blocks) would make the person run build in their own terminal. Regression test: `TestBuildHoldsAStoryThePersonDidNotAskFor`. Without the gate, the agent's `build 2` exits 0 and takes the lease. The test also checks that the warning leaves the label, lease and worktree untouched, that `--asked` starts the build and its words reach the actions log, and that a story grilled in session s1 is held in session s2 and passes in s1
