# D-1.4c

## Plan assumption

WP1.1: `--yes` is human-only, refused when `AAYU_AGENT=1`; WP1.4: human actions verify the human, and `init` requires a TTY confirmation; D2 and D-5.5a: in solo mode only the human runs `ship --solo-bypass` and `plan --solo-bypass`

## Finding

Bug #170: only the MCP server and the loops set `AAYU_AGENT=1`; no host sets it for the shell commands its agent runs, so an agent running `aayu` from a skill with the founder's token was the founder. WP3.2b (#169) added a pre-tool hook that blocks human-only shell commands in Claude Code, Codex, and Cursor, but it reads only the command text the host forwards (a script or alias hides it) and the Amp plugin forwards none. Each host does set its own marker in its agent's commands: Claude Code `CLAUDECODE=1` (documented), Codex `CODEX_THREAD_ID` (D-3.2b) and `CODEX_SANDBOX`/`CODEX_CI`, Cursor `CURSOR_AGENT=1`, Amp `AGENT=amp`, `AI_AGENT`, and `AMP_THREAD_ID` (observed in this orb's agent shell, absent from the orb's own environment); Cursor's `CURSOR_TRACE_ID` is also set in a person's terminal, so it is not a marker

## Implemented instead

Two layers. The hook (#169) is unchanged and stays the first stop where a host forwards the command. Below it, `Env.Agent` is true for `AAYU_AGENT=1` or any marker in `hosts.AgentMarkers` (one table in `internal/hosts`, beside `HumanOnlyCommand`), so every existing agent refusal (`--yes`, the pause file, the halt fail-closed rule, grill's bot client) covers host agents. Every human-only action goes through `Env.requireHuman`: an agent lane is refused (exit 4, naming the marker); with no marker, standard input must be an interactive terminal, else exit 4 (fail closed). That covers `ship --solo-bypass`, `plan --solo-bypass` and `--approve`, `decide --accept`, `release`, `tell --publish`, `inspect --dismiss`, `resume`, `seat`, `install --apply`, `upgrade --apply`, `self-update`, and `init`/`uninit` (through `confirmOrBlock`); `--yes` still answers a confirmation, but only on a terminal. `auth set-secret` refuses markers but needs no terminal, so a person can pipe a value in. No host file was changed: each host already sets its marker, and writing `AAYU_AGENT=1` into host settings would duplicate it (the founder may want it in WP3.2b's adapters as a second marker). Limits: the markers are honest-agent signals, not authentication: an agent that clears them inside a pseudo-terminal looks like a person, and a person whose shell exports `AGENT` for another tool is refused until they unset it. Consequence: agents (this repository's orchestrating Amp threads among them) can no longer run `release`, `ship --solo-bypass`, or `plan --solo-bypass`; AGENTS.md's agent-run promotion policy needs the founder's decision. Tested by `TestHumanOnlyRefusedInHostShells` (`plan --solo-bypass`, `decide --accept`, `release`, `resume` from Amp, Cursor, Claude Code, and Codex shells on a terminal: exit 4, no GitHub write; the hook blocks the forwarded `aayu ship --solo-bypass` and misses `sh ./merge.sh`; no marker and no terminal: exit 4) and `TestShipMobileWaiverAndSoloBypass` (every solo-mode condition met: refused from each host's shell and without a terminal, nothing merged; a person on a terminal ships). Live on 2026-10-15 (`internal/cli/testdata/host-shells`, checked by `TestHostShellRecords`): from this Amp thread's own shell, from Claude Code 2.1.300's Bash tool (driven by a scripted local stand-in for the Messages API, so no real model ran), and from a Claude Code hook (all `CLAUDECODE=1`), `ship --solo-bypass`, `plan --solo-bypass`, `decide --accept`, `release`, and `resume` all exited 4 naming the marker; with no marker and no terminal they exited 4, and in a pseudo-terminal the human check passed. Cursor could not run: its agent needs a signed-in account and Cursor's backend, and with none the CLI stops before any hook or tool runs. Its record (`cursor-agent-source.txt`, 2026-10-17) is the installed Cursor Agent CLI 2026.10.14's bundle, with its SHA-256 and the three places its shell and terminal tools set `CURSOR_AGENT=1`. Rebased onto dev on 2026-10-17 (after v0.2.0): `hosts.AgentMarkers` is now the one marker list. Each entry names its host, so `doctor.DetectHost` reads the list too (plus `CURSOR_TRACE_ID`, which names Cursor but marks no agent; it now ranks after Codex's markers), and build's asked gate (D-5.5c.20) reads `Env.agentSignal` instead of its own copy. The gate therefore also holds `CODEX_SANDBOX`, `CODEX_CI`, `AGENT`, and `AI_AGENT` shells, and names the marker without its value. The later `Env.Agent` callers on dev now cover host agents too: `install --loops --apply` and `--run-now` are refused, `install --env` and `install --loops` do not prompt, and `home` and `next` show an agent the person's step as waiting on a person. Test: `TestBuildHoldsAStoryThePersonDidNotAskFor` (an `AGENT=goose` shell is held, naming `AGENT`; a person with only `CURSOR_TRACE_ID` builds). The first PR (#189) reached inspect's two-cycle cap asking for these live traces, so it was closed and rebuilt (D-8.1d)
