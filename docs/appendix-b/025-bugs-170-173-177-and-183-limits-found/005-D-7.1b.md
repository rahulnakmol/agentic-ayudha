# D-7.1b

## Plan assumption

WP4.2: retention TTL from config and `aayu proof purge`; WP7.1 and D-7.1a: loops honour `halt` and `[budget]`, and `init --gates` renders a product's loops when it has `loops/`

## Finding

Bug #172: no loop, workflow, or template ran `proof purge`, so media retention (V3, personal data) depended on a person. A product without `loops/` got no loops at all. Purging writes the ledger, so in Actions it needs the bot App (D1), and a bucket purge needs the media credential, which no loop job received

## Implemented instead

A default loop, `loops.Defaults["proof-purge"]` (`command = ["proof", "purge"]`, daily at 03:40 in `[time] tz`, `bot = true`): `init --gates` writes `loops/proof-purge.toml` into a checkout that lacks it and renders it with the checkout's loops, so every product gets the Actions job, the Amp schedule, and the Cursor automation; aayudha commits the same file, so `go generate` renders it here. A new loop key `secrets` names aayu secrets the Actions job passes as `AAYU_SECRET_<NAME>` (the default passes `proof-media`; a product whose `[proof] media_secret` differs edits it). Each run starts with `aayu hook loop:proof-purge` (halt exits 4, the pause file and the minutes budget exit 6) and `proof purge` refuses while halted too; retention is `[proof] retention_days`. Without an App the Actions job skips with a notice, as the `decisions` loop does, so on this repository only a host schedule can run it. Media behind an `oidc` bucket credential (D-7.2b.2a) cannot be purged by the Actions job, which has no `id-token: write`; a host schedule or the bucket's lifecycle rule covers it. Tested by `TestInitGatesRendersProofPurge` (a scratch checkout without `loops/`, and this repository's generated workflow) and `TestLoopProofPurge` (the job's guard and command as the bot against a fake S3: a June pack's screenshot deleted and its pack tombstoned, an October pack untouched, and, halted, exit 4 at the guard and the command with nothing purged)
