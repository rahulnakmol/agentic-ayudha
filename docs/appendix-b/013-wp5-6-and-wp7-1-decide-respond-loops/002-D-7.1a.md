# D-7.1a

## Plan assumption

WP7.1: `loops/*.toml` → Amp schedules/plugin, Cursor Automations, and an Actions fallback; nightly `status --digest`, weekly `retro`, monthly seat self-review, quarterly `evolve`; all honour `halt` and `[budget]`; schedules in `[time] tz`. Accept: golden outputs per host (Amp schedule JSON, Cursor automation file, Actions cron with the tz-converted expression); the Actions fallback runs `status --digest` on the dogfood repo on schedule and the fake notify sink receives one digest; `halt` makes the next scheduled run exit 4 with no writes

## Finding

Built ahead of M7 (founder scheduling, 2026-10-12). V7 fixes the plumbing list, so there is no `loops` command. Amp has no schedule file: per its docs (Automations, 2026-10-12) a schedule is set on one thread by an agent through `set_schedule` (`title`, `prompt`, `schedule` as an RFC 5545 rule, `schedule_label`, `run_mode`), one schedule per thread. Cursor has no committable automation file either: automations are created in the editor, at cursor.com/automations, with `/automate`, through its API, or with its Terraform provider (`cursor/cursor` ~> 0.1, resource `cursor_platform_workflow`, `trigger.cron.schedule`); its docs do not state the cron's time zone, and the only statement found is a Cursor staff reply on the forum (2026-06-25) that it is UTC, with an unverified `CRON_TZ=` prefix. GitHub's cron is UTC. `[notify]` holds non-urgent pages until business hours, and a CI run keeps no held pages, so a digest sent overnight would be lost. `retro` and `evolve` are WP7.6 and WP7.7. No billing API reports one personal repository's Actions minutes. aayudha has no `[notify]` channel and no bot App (D1)

## Implemented instead

A loop is `loops/<name>.toml`: `description`, `command` (an aayu command; refused when it uses `--yes`, a human-only input, or a command gated on a terminal, a human pass, or the merge gate), `cron` (five fields in `[time] tz`: one minute; hours as a list or `*`; days of month or of week, not both; an hourly loop has no day fields), optional `hosts` (`amp`, `cursor`, `actions`; default all), `prompt` (extra work for a host's agent), and `bot` (the command writes as the bot). `internal/loops` renders, `go generate ./...` writes aayudha's own (CI drift-checks them), and `init --gates` writes a product's when it has `loops/`: `.github/workflows/aayudha-loops.yml`, `loops/amp/<name>.json` (the `set_schedule` input: the rule as `DTSTART;TZID=<tz>:20260105T<hhmm>00` plus `RRULE:FREQ=…;BYHOUR;BYMINUTE`, local time, so DST needs nothing; `run_mode` `fresh`; a human asks an Amp thread in the project to set it), and `loops/cursor/aayudha-loops.tf` (one `cursor_platform_workflow` per loop with `git_repo`, `git_branch`, the prompt, and cron triggers, applied with `terraform apply`). For the UTC hosts each local cron becomes one UTC cron per offset the zone uses (sampled on 15 January and 15 July), moving the days of the week when the time crosses midnight UTC; a day-of-month loop that would cross is refused. Every run starts with `aayu hook loop:<name>` (the `hook` plumbing command, no new command): exit 4 while `AAYUDHA_HALT` is set, exit 6 while the `[budget]` breaker's pause file exists or, in Actions, when this workflow's finished runs this month, each rounded up to a whole minute, reach `[budget] ci_minutes_month` (other workflows are not metered); otherwise it reports whether this run is the scheduled one: in Actions only the cron for the zone's current offset (`github.event.schedule`), elsewhere a time within 59 minutes after the local time, so of the two UTC crons exactly one runs each day; in Actions it writes `due=true\|false` to `GITHUB_OUTPUT`. Agents run the command with `AAYU_AGENT=1`, so verbs refuse while paused (exit 6) and while halted (exit 4). Each Actions job also starts with the halt step, here exiting 4, and keeps the `file` channel's outbox as an artifact. Loops: `digest` (`status --digest`, Mon–Fri 09:05: at the opening of business hours rather than nightly), `decisions` (the WP5.6 `decide` sweep, Mon–Fri 09:15, 13:15, 17:15; `bot`, so the Actions job mints the App token and skips with a notice without one), `seat-review` (monthly, Amp and Cursor only, since it needs a model), `retro` and `evolve` (not rendered: n/a until WP7.6 and WP7.7; the workflow lists them). `[notify] channel = "file"` (new) appends each page as a JSON line to `target` (default `.aayudha/state/notify-outbox.jsonl`); aayudha's own config uses it, so its digest lands in the run's `aayudha-notify-digest` artifact: that file is the "fake notify sink" of the acceptance. Tests: `TestUTCCrons` (London, Kolkata across midnight, New York, hourly, the Sydney refusal), `TestDue`, `TestParseRefuses`, `TestGolden` (`internal/loops/testdata/golden`: all three hosts), `TestLoopDigestOnSchedule` (the digest job against the fake GitHub at Monday 09:05 London: the BST cron is due and the GMT one is not, one digest in the outbox, then halt exits 4 at the guard and in the verb with no writes, then the minutes budget and the pause file exit 6), and `TestInitExtras` (`--gates` renders a checkout's loops). Live on 2026-10-12 against the scratch repository `rahulnakmol/aayu-scratch-loops-1791775332` (the generated workflow installing this branch; deleted afterwards): with `AAYUDHA_HALT` set, a dispatched digest run failed at its halt step with exit code 4 and ran no other step; with it cleared, the guard printed `dispatched by hand` and `status --digest` ran, its page held because 04:30 London is outside business hours, which is why the digest loop runs at 09:05
