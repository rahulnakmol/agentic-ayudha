# D-5.6a

## Plan assumption

WP5.6: `decide` with `[decisions] authority.<type\|layer>`; an SLA in business hours: at 24 h a page to the authority and an escalation comment mentioning founder B (`escalate_to`), at 48 h a reversible recommendation applied provisionally (`decision:provisional`, ratify/revert deadline in the body; ratification clears it), an irreversible one only re-paged and shown overdue; `constrains`-linked stories shown blocked; supersede chain; `decide --waiver <floor>`; `ops/actions.toml` read only from the protected default branch at a pinned SHA, edits needing two human CODEOWNER reviews and never `auto` on first merge; `respond` proposing a catalog action that, for `approval = human`, executes only through a GitHub Environment with required reviewers and a short-lived credential never in the agent env; timeline; close with a linked Bug and retro entry. Accept: non-catalog command refused, same-PR catalog edit unusable, human approval required and verified, the 48-hour reversible/irreversible pair

## Finding

Built ahead of M5 (founder scheduling, 2026-10-12). Nothing runs a sweep on a clock, so something must invoke it; `decide`'s registry inputs had a required Decision and no way to name the waived item; `respond` had no parameter or close input. The plan fixes no SLA start, ratify deadline, authority key set, or Decision-type taxonomy. A repository-wide rule cannot require two reviews for one path, and solo mode has one human (D2). A waiver applied provisionally would let an SLA lapse override a floor (rule 7). D-1.2a holds: the SLAs are business hours of `[time]`

## Implemented instead

`decide`'s positional is optional: `aayu decide` sweeps every open Decision (`type:decision`), `aayu decide <n>` one; WP7.1's loops run the sweep on a schedule. The clock starts at the issue's creation (as WP2.8's "near SLA" does) and counts `sla_hours` (24) and `provisional_after_hours` (48) business hours (`config.Clock.Add`; new `Clock.Between` gives status its hours left). At the SLA: one page per Decision per day through `[notify]` (key `decision-sla:` then `decision-overdue:`; on the GitHub channel the mention goes to the authority's login) and a replace-in-place `<!-- aayudha:decision-escalation -->` comment that mentions `@<escalate_to>`, or says nobody is configured; `escalate_to` stays unset by default (there is no founder B yet) and is validated as a login. At 48 h a Decision that is open, `reversible: true`, Decision-ready, not already provisional, and not a waiver gets `status:validation` (so the Ready guard does not strip it for the edit), a Decision section saying the recommendation applies from the 48-hour instant with "Ratify or revert by <RFC 3339>" one more `sla_hours` later, then `decision:provisional` last, so an interrupted run redoes it and a rerun writes nothing. Authority: `[decisions.authority]` keyed by the Decision's parent's work-item type, then `L04` for a floor waiver (the floors' layer), else the Founder seat; a seat value resolves to its paired human, else `[autonomy] approver`; no login configured means any human (day one). `decide <n> --accept <option>` is refused for agents and bot identities (`identity.IsBot`, `bot_logins`) and for anyone but the authority's login, needs the option named in Options (whole word) and a Decision-ready body, writes the Decision section, `status:done`, clears `decision:provisional`, closes it, and closes every `supersedes` target as not planned with a `<!-- aayudha:decision-superseded -->` comment. `status` counts open items an open Decision `constrains` as blocked and shows each provisional Decision's business hours left (`#n 9 h`, `overdue`, `no deadline`). `decide <story\|bug> --waiver <floor>` files a sub-issue Decision labelled `decision:waiver` (new label), `reversible: false`, recommendation `fix`, `waives #n`; reruns find the open one; the redaction floor is not waivable (V3); a waiver is never applied provisionally, whatever its body says. `verify` (D-4.9a) now applies only accepted waivers: closed as completed, by a non-bot, with `waive, accepted by @<login>` in the Decision section, so a filed waiver waives nothing (`TestVerifyMobileSkipAndWaiver` files one, sees the floor still fail, accepts it, then sees it waived); `audit` counting `decision:waiver` is n/a until WP7.6. Catalog (`internal/ops`, schema in `ops/README.md`): `version = 1`, `[[action]]` with `argv_template` (no shell; `{param}` fills a whole value; `sh -c` refused; the program is never a parameter), typed `params` (string with an anchored pattern and no leading `-`, int with bounds, enum, bool; `environment` reserved), `approval`, `environments`, `max_per_hour`, `rollback` (`none` or another action), `blast_radius` (`single\|service\|global`; global never auto); unknown keys refused. `respond` reads it through the contents API at the default branch's head SHA; the executor re-reads it at that pinned SHA only after the compare API shows the commit on the default branch. "Never auto on first merge" is enforced at read time: an `auto` action is effective only if its definition (everything but `approval`) first appeared on the default branch as `human`, walking up to 30 commits of the file's history, else it runs as `human`. Two CODEOWNER reviews: CODEOWNERS and the protected-paths gate cover `ops/`, and solo mode merges by the recorded admin bypass (D2); a second required review is n/a until a second human (WP5.1). `respond` gains `--params k=v,…` and `--close`. `respond <incident>` prints the incident wrapped as untrusted, the catalog, and the timeline, appending each finished `aayudha-ops.yml` run with who approved it; `--action` validates the action and parameters, refuses (exit 4) a human action whose environment has no required reviewers or lets any branch deploy, enforces `max_per_hour` over the last hour's runs, and dispatches `aayudha-ops.yml` on the default branch (`return_run_details`), appending to a replace-in-place `<!-- aayudha:timeline -->` comment. `aayudha-ops.yml` (template, installed by `init --gates` as the fifth gate workflow; not committed on aayudha, whose own catalog is empty) runs the job in the action's environment, so a human action waits for a required reviewer before any step runs; `respond --ci` then refuses unless the run is that workflow on the default branch with the matching run name, the catalog commit is on the default branch, a non-bot reviewer approved that environment (run approvals API), and the hourly cap holds, and runs the argv with only PATH/HOME/locale, the environment secret `AAYUDHA_OPS_CREDENTIAL`, and the job's OIDC request variables (no GitHub token, no `AAYU_*`); the executor writes nothing to GitHub. `--close` files the linked Bug (`caused-by #n`), appends `{incident, bug, timeline, …}` to `retro/incidents.jsonl` on the ledger, removes `needs:bug`, and closes the incident `status:done`. Tests: `TestDecideSLA` (47:59 and 48:00 business hours; the reversible Decision gains `decision:provisional` with a deadline of Thursday 10:00 London, the irreversible one and the waiver do not; every escalation mentions the fixture login `founder-b`; rerun writes nothing; acceptance refusals and supersede), `TestDecideWaiver`, `TestRespondProposes`, `TestRespondExecutes`, `TestRespondClose`, `internal/ops` (validation, rendering, auto provenance, PR commit refused).
