# D-7.8a

## Plan assumption

WP7.8: `release`: the promotion ladder for a Release issue; artifact identity; stamps included stories `released`; `tell release`; shipping evidence; triggers the `measure` schedule; accept: a dogfood rolling snapshot with stamped stories

## Finding

D-0.4a removes the human approval on this repository but keeps the gates and conventions, and CONTRIBUTING.md already fixes the procedure. The registry gives `release` the human identity and a terminal confirmation. WP stories here merge through `gh pr merge --admin` (solo-mode bypass), not `aayu ship`, so they keep `status:ready`. Only a story's PR links it to the commit that shipped it. The plan does not say whether "included" means what the Release lists or what the promoted range ships, what identifies a rolling snapshot (it has no GitHub Release, since `.goreleaser.yaml` ignores `rolling-*` tags, #77), or what the `measure` schedule is: loops (WP7.1) are in review, and `measure` needs exports that a human supplies. Rulesets on a personal account's private repository need GitHub Pro

## Implemented instead

`aayu release <release> --to rolling\|main` (`internal/cli/release.go`) drives CONTRIBUTING.md's procedure and nothing else. It is refused for agent lanes, in CI, and for a bot account (WP7.5's checks). It needs a checkout and a yes on a terminal or `--yes` from the human (on this repository, the D-0.4a path for the maintainer's credentials). The Release must pass Ready, be open, and, for main, have a `vX.Y.Z` Version that is not yet tagged. The ladder rule: main needs this Release's rolling rung (`releases/<n>/rolling.json` on the ledger) and that commit must still be on rolling. Branch names come from `[branches]`. The range is `git rev-list --no-merges origin/<target>..origin/<source>`. Its stories are those named, through `Refs #n`, an `Aayudha-Story` trailer, or a `story/<n>-` branch, by the merged PRs into dev that GitHub links to each commit. The Release's `includes` links expand a Feature to its stories and bugs. Each listed item must be in the range or already released, measured, done, or cancelled; anything else refuses (exit 4) before anything is written. Every story the range ships is stamped, listed or not, because the artifact holds it: those not yet released become `status:released` (from `ready` or `merged` alike). Ones the Release did not list are reported. `--dry-run` reports all of this and writes nothing. Then: the candidate `promote/rolling-<ts>` (or `promote/main-<v>`) is cut from origin/target in a temporary worktree with `git merge --no-ff --signoff -m "Rolling snapshot: <ts>"` (or `"Release: <v>"`) and pushed. For rolling, `evals.yml` runs on the source ref when the repository has it, and a red run stops the promotion. CONTRIBUTING's `gh run watch` there has no `--exit-status`, because `evals-gate` reads its results; `release` stops earlier, with the same outcome. `ci.yml` is dispatched on the candidate with `gate=rolling\|stable`, through `return_run_details`. The run must be on the candidate's SHA, and a failed run has its failed jobs re-run once (the transient `release-snapshot` signing timeouts). A gate that still fails exits 4 and promotes nothing. That exact commit is pushed to the target as a fast-forward and tagged: lightweight `rolling-<date>`, or `rolling-<date>.<n>` for the n-th snapshot of the day, or annotated `vX.Y.Z` (`Release vX.Y.Z: <title>`). For main, the binary waits for the tag's `release.yml` run and re-runs it once. A run still red after the bookkeeping exits 5 with the `gh run rerun` hint. Any failure after the target moved (the tag, the tag's run, stamping, notes, records, or evidence) exits 5. The message names the commit now on the target and the steps left; they have no resume yet and are finished by hand. The candidate branch is deleted on every exit. Every push, dispatch, and re-run is an action in the log. Artifact identity: the commit, tree, and source SHA; the gate's run artifacts (name and digest) for rolling, and the GitHub Release assets (name, `sha256:` digest, size) for main. A tag with no GitHub Release is noted; any other lookup failure is a failure after landing. `tell release` uses WP7.5's `ReleaseNotes`, checks them with `tell.Check`, and publishes them under the human account to `tell/release/<tag>.md` on the ledger and, for `v*`, to the GitHub Release. Records: `releases/<n>/<target>.json` on the ledger. The Release gets `status:released` and a Shipping evidence entry per rung (the runs, artifacts, stories, notes, and measure due dates); the main rung closes it. Measure schedule: each Goal or Initiative above a stamped story gets `measure/due/<n>/<tag>.json` on the ledger (one per release, so a later release never erases or postpones an earlier obligation), due 28 days after the release (measure's default window), for the loops (WP7.1) and the human to run `aayu measure` on. The release notes are built and checked before anything lands, so a story title with an avoided word refuses the promotion rather than its bookkeeping. Tests: `TestReleaseLadder` covers the fake GitHub and a local remote: the refusals, the dry run, a gate failing twice, the re-run, stamping (an abandoned PR holding the same commit serves nothing), notes, records, a second same-day snapshot that ships an unlisted story without `evals.yml`, main refused while the snapshot is gone from rolling, main with `release.yml` re-run and release assets, and a version that already shipped. `TestReleaseFailsClosed` injects GitHub failures: before landing nothing is promoted, and after landing the exit is 5 naming what landed. `TestReleaseRefusesBeforeLanding` covers an avoided word in the notes, a conflicting candidate, an unreadable brand, red evals, and a gate run on another commit; a tag the remote refuses after rolling moved is in `TestReleaseFailsClosed`. `TestReleaseRedTagWorkflow` covers a `release.yml` still red after its re-run (exit 5 with the `gh run rerun` command) and a product without one. `TestReleaseLive` (AAYU_LIVE=1) runs on an `aayu-scratch-*` repository created with `AAYU_LIVE_ADMIN_TOKEN`, made public so it can carry aayudha's `rolling-main-promotion` and `release-tags` rulesets, and deleted. It has stand-in `ci.yml`, `evals.yml`, and `release.yml` workflows, a Goal > Feature > Story tree, and the story's PR squash-merged into dev. The ladder ran under the human's fine-grained token through the admin-only rulesets: rolling in about 50 s, then main in about 45 s, with the `checksums.txt` asset digest recorded (passed on 2026-10-12, last on the final head of #110). The repository's own promotions are left to the orchestrator
