# D-0.4b

## Plan assumption

WP0.4: CI checks DCO and Conventional Commits

## Finding

GitHub writes the squash commit on `dev` itself, and promotion merges (`Rolling snapshot: …`, `Release: v…`) are not Conventional Commits by design

## Implemented instead

The `commits` job runs on pull requests: every non-merge PR commit needs a Conventional Commit subject and a `Signed-off-by` matching its author, and the PR title (the squash subject) must be a Conventional Commit. Pushes are not re-checked
