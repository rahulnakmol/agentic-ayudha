# D-0.4a

## Plan assumption

Promotions `dev` → `rolling` → `main` follow a deliberate human decision (stable only after an explicit decision; WP8.2 "brew/Scoop/winget after the stable decision")

## Finding

Founder policy, 2026-10-11: for this repository promotions need **no human approval**; the gates and the commit/tag conventions are unchanged

## Implemented instead

The gates are CI jobs: `ci.yml` dispatched with `gate=rolling` (PR suite + `integration` + `benchmarks`; `release-snapshot` is the production validation) or `gate=stable` (rolling + `extended-integration` + cross-OS `smoke`; `security` always runs). They run on a `promote/…` branch holding the exact `Rolling snapshot: …` / `Release: vX.Y.Z` merge commit, which is then pushed to `rolling`/`main` as a fast-forward and tagged. An annotated `v*` tag push runs `release.yml` end to end. The stable decision is now "an explicit stable-release request plus a green stable gate". Procedure: CONTRIBUTING.md, AGENTS.md
