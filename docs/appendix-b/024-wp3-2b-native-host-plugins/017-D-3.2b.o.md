# D-3.2b.o

## Plan assumption

WP3.2b: Cursor's print mode can run aayu and the aayudha MCP tools

## Finding

Megaman D-5.5c.23 defect (2): `cursor-agent -p` rejected the aayudha MCP tools ("User rejected MCP: aayudha-grill") until `.cursor/cli.json` allowed `Mcp(aayudha:*)`, and shell commands until it allowed `Shell(aayu)`; and the server loaded only after `cursor-agent mcp enable aayudha`. Cursor documents `permissions.allow` in `<project>/.cursor/cli.json` with `Shell(commandBase)` and `Mcp(server:tool)` (cursor.com/docs/cli/reference/permissions). Checked in this orb: approval is per person, in `~/.cursor/projects/<path>/mcp-approvals.json` as `<server>-<hash>`, and the hash covers the resolved entry, so a changed `.cursor/mcp.json` needs approval again

## Implemented instead

`install --host cursor` merges `Shell(aayu)` and `Mcp(aayudha:*)` into `.cursor/cli.json` `permissions.allow`, leaving other entries. The hooks still refuse a human-only verb and the MCP server never offers one, so these entries let print mode run what an agent may run anyway. Approval is the person's consent and lives in their home, so install does not give it: its note says to run `cursor-agent mcp enable aayudha` once, and again after the entry changes. `docs/guide/hosts/cursor.md` documents both. Test: `TestInstallKeepsThePluginsCommands`
