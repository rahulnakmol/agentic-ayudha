# D-3.2b.n

## Plan assumption

WP3.2b: Cursor gets the same commands as the other hosts

## Finding

Megaman D-5.5c.23 defect (1): with `install --host cursor` only, Cursor had no `home`, `next`, or hand-off command, so its agent tried `aayu home`, which does not exist. Cursor's agent CLI 2026.10.16-e3cb207 loads commands from the top-level `.md` files of `.cursor/commands` and `.claude/commands` in the workspace and home (`loadCommandsFromDirectory` skips folders), names each after its file, and takes the first line as its title (`parseMarkdownCommand`); there is no frontmatter in its command format

## Implemented instead

`install --host cursor` writes `.cursor/commands/aayudha-<name>.md` from `hosts/commands/` (the plugin's home, next, and hand-offs to the other three agents, never to Cursor itself): the body without Claude Code's frontmatter, so the command's own heading is its title. The `aayudha-` prefix keeps them apart from the person's own commands in the same folder; a later install removes an `aayudha-*.md` it no longer writes. Uncertain: Cursor's IDE was not run; that it lists these as `/aayudha-<name>` is read from the CLI's code. With Codex installed too, Cursor also lists the Codex command skills in `.agents/skills` (D-3.2b.k). Test: `TestInstallKeepsThePluginsCommands`
