# D-3.2b.c

## Plan assumption

WP3.3: the model in every host is offered the aayudha MCP tools

## Finding

Megaman D-5.5c.12 MCP row: in Codex, through the founder's AI gateway, the model was offered no aayudha tools, though resource listings answered. Not reproduced: with Codex 0.162.1, a fake Responses endpoint recorded the request. With the plugin alone, and with the plugin plus `install`, it carried a `namespace` tool `mcp__aayudha` holding the ten read tools (`brief`, `decide`, `doctor`, `grill`, `plan`, `proof`, `ready`, `research`, `slice`, `status`). The resource helpers are plain `function` tools. Codex always declares MCP tools as Responses `namespace` tools; no setting flattens them (codex-rs `core/src/tools/handlers/mcp.rs`, `create_tool_spec`, rust-v0.162.0). The likely cause is a gateway that drops `namespace` tools. That is unverified: the gateway was not available here

## Implemented instead

No product change, because aayu's tool listing is valid. `TestHostPluginsLoad/codex` now checks that Codex offers the model the aayudha tools through a fake Responses endpoint (it skips without `codex` on `PATH`). `docs/guide/hosts/codex.md` says a gateway must pass `namespace` tools through, and that the skills still work without them because they run `aayu` in the shell. To confirm the cause, rerun on megaman through the gateway and check whether it forwards `namespace` tools
