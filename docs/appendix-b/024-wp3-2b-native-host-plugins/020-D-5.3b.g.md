# D-5.3b.g

## Plan assumption

WP5.3b: after D-5.3b.f, the founder (2026-10-15) accepted the results and asked for one more round, then stop: per-topic scripted answers, a skill that never decides an unconfirmed detail, a narrower caching rule, the conversation cases in their own advisory group, and dispatches that a push cannot replace

## Finding

Run 38687921977 (after D-5.3b.f) showed three causes. The scripted human answered by dimension, so a follow-up on the same dimension got the same reply and every `request` or `other` clarification ("depend on #14?", "split this L story?") was parked. The skill decided details the human left open (the confirmation on `/order/review`) and once tagged a criterion with a dimension it never asked about. The search case's `\bcach` rule also matched "cold cache", a test condition. And `evals.yml`'s one concurrency group per ref let later pushes replace a pending dispatch, twice

## Implemented instead

Topics: every catalogue dimension lists `Topics` (kebab keys, parsed strictly), and the skill tags each question `<dimension>/<topic>`, a request topic (`request/dependency`, `request/size`, `request/existing-behaviour`, `request/parent`, `request/scope`), or `other/<key>`; the turn schema requires the topic. `human.toml` has `[topics."<dimension>/<key>"]` answers, `[dimensions."<dimension>"]` fallbacks, and the global fallback (park or defer); the bakery human now answers where the confirmation goes, where options go, the #14 dependency, the story's size, and existing payment, and the search human a cold cache. Provenance names the topic (`(ux.steps/screen-count)`); a criterion from a topic or dimension never asked fails tier 1 and the tier-2 floor. Placements: `grill.Check` (so `grill`, `ready`, and both tiers) refuses a grilled criterion whose expected result places something (a backticked route, "on the review screen", "above", "below", "next to", "at the top of", …) unless that word is in the criterion's quoted human words or the request; the skill says never to decide where something appears, what it is called, its order, or a number without the human, and to defer or park it instead. The search rule now matches result caching only (`cache … results`, `results cach…`, `cache per query`, memoizing); the recorded search run measures with a cold cache and passes (TestGrillSearchScopeCaching). Group `conversations` (the two cases, 20 USD, `gate = "advisory"` until a run meets the bar; like brief, not on pushes to `dev`); `skills` back to 6 USD and no longer holds them. `evals.yml`: a dispatch's concurrency group carries its run ID, so a push or schedule cannot replace it; pushes and the schedule keep the shared per-ref group and `cancel-in-progress: false`, so a running promotion run is never cut short. Tests: TestTier1GrillConversation (unasked topic, unasked dimension, unconfirmed placement), TestTier2GrillConversation (answers by topic, dimension, fallback), TestTopicsAndPlacements, TestCheck, TestGroups. The founder's instruction is one round and then stop, whatever the dispatched result
