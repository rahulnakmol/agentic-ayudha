# D-3.2b.k

## Plan assumption

WP3.2b, D-3.2b.h: a person loses nothing by having aayu installed; the plugin's own commands were off in installed repositories

## Finding

Founder decision (2026-10-17): D-3.2b.h turns the plugin off for Claude Code and Codex in an installed repository, which also took away `/aayudha:home`, `/aayudha:next`, and the hand-offs. Claude Code: a file in a subfolder of `.claude/commands/` is `/<folder>:<name>`, and a command file works like a skill, Claude may invoke it (code.claude.com/docs/en/skills). Codex: custom prompts are deprecated and live only in `~/.codex/prompts` (developers.openai.com/codex/custom-prompts); Codex turns a plugin's commands into skills named `aayudha:source-command-<name>` (seen in `codex debug prompt-input`, codex 0.162.1/0.163.0, `.codex-plugin/migrated-command-skills`), and reads repository skills only in `.agents/skills`, nested folders and a `name` with a colon included (probe skills)

## Implemented instead

`install` writes the commands itself, from `hosts/commands/`: for Claude Code the plugin's command files in `.claude/commands/aayudha/` (the same `/aayudha:<name>`); for Codex one skill per command in `.agents/skills/aayudha-source-command-<name>/`, in the form Codex gives a plugin command, so the names match (`$aayudha:source-command-next`). Live: with the Codex plugin, a trusted project, and `install`, `prompt-input` lists the five commands once, from the repository's `.agents/skills`. Cursor's agent CLI loads only top-level `.md` files from `.claude/commands` (`loadCommandsFromDirectory` skips folders), so it lists none of Claude Code's. Uncertain: the Cursor IDE was not run here. Cursor and Amp also read `.agents/skills`, so with Codex installed they list the Codex command skills once each (Amp beside its own palette commands); Cursor's rule that a skill's `name` matches its folder is not enforced by its CLI. Test: `TestInstallKeepsThePluginsCommands` (the names come from the plugin manifests)
