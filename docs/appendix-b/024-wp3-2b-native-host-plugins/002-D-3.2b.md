# D-3.2b

## Plan assumption

WP3.2: every hook and MCP registration runs the absolute, version-checked binary; "look up each host's current extension format"

## Finding

Sources: Claude Code [plugins reference](https://code.claude.com/docs/en/plugins-reference), [marketplaces](https://code.claude.com/docs/en/plugin-marketplaces), [skills and commands](https://code.claude.com/docs/en/slash-commands), [status line](https://code.claude.com/docs/en/statusline); Codex [skills](https://developers.openai.com/codex/skills), [MCP](https://developers.openai.com/codex/mcp), [hooks](https://developers.openai.com/codex/hooks), [plugins](https://developers.openai.com/plugins/build/plugins); Amp [plugin API](https://ampcode.com/docs/plugin-api) and `amp plugins show-docs`. A marketplace plugin is the same files on every machine, so it cannot carry a machine's binary path. Plugins cannot set Claude Code's main `statusLine` (only `subagentStatusLine`). Codex reads `.agents/skills/` and `AGENTS.md`, loads a project's `.codex/config.toml` only when the project is trusted, and runs `.codex/hooks.json` hooks only after the user trusts them (`/hooks`); its repo marketplace path, `.agents/plugins/marketplace.json`, is a protected path here. Codex 0.162.1 also reads `.claude-plugin/marketplace.json` and installs a Claude-format plugin from it, loading its skills, commands (as `source-command-<name>`), and MCP server. Codex exports `CODEX_THREAD_ID` to the commands it runs (found in the 0.162.1 binary, not documented). No host sets `AAYU_AGENT=1` for the shell commands its agent runs, so a human-only verb's refusal could not rely on it

## Implemented instead

The marketplace plugin's root is the repository (`"source": "./"`), so its skills are `skills/` itself with no copy; its hooks run `aayu hook <name> --skills <version>` and its MCP server `aayu mcp --skills <version>`, from `PATH`: the server refuses to start (exit 5, `next: aayu self-update`) and `session-start` reports when this binary carries other skills, and a hook without `--host` detects the host (`CLAUDECODE`, `CODEX_THREAD_ID`). `aayu install` keeps the absolute, version-checked path for every file it writes; the Amp plugin also checks at load that the binary reports the version install recorded and disables its commands otherwise. Use the plugin or `install` for a host, not both. `install --host codex` writes a block between `# BEGIN aayudha` and `# END aayudha` in `.codex/config.toml` (text outside it is kept, a product-owned `[mcp_servers.aayudha]` is left alone with a note) and `.codex/hooks.json` (`SessionStart`, `PreToolUse`; Codex blocks on exit 2 like Claude Code). `install --host claude` sets `statusLine` to `aayu hook status-line --host claude` unless the product has its own; `status-line` prints one line from the cached home screen (`.aayudha/state/journey.json`, D-1.1b) and never calls GitHub. `pre-tool` now reads the event the host sends (Claude Code and Codex `tool_input.command`, Cursor `command`) and blocks a shell command that runs a verb the MCP server never exposes (`decide`, `ship`, `release`, `respond`, `init`, `install --apply`), any human-only input, or `resume`, `self-update`, `tour`, `seat`, `uninit`; Amp's palette offers none of them. The Amp plugin registers Home, Next step, Status, Doctor, and six agent verbs (grill, ready, plan, build, verify, inspect) that ask the thread to run the skill, plus every shared command but home and next, which install writes into the plugin.
