# D-3.2b.q

## Plan assumption

WP3.2b, D-5.5c.3: what `TestHostPluginsLoad` proves for Cursor

## Finding

Megaman D-5.5c.23 defect (4): `cursor-agent --plugin-dir` and a copy in `~/.cursor/plugins/local/aayudha` load the plugin's MCP server and hook in a signed-in `-p` run, a symlinked local plugin is not loaded, and no command lists a plugin's skills or commands (`plugin` has only `marketplace`, `mcp list` omits plugin servers, and the stream-json `init` event carries no catalog)

## Implemented instead

`TestHostPluginsLoad` has a `cursor` subtest that only skips, with that reason, so a run shows Cursor as not covered instead of passing silently. Cursor's plugin is proven by `TestPluginManifests` (its manifest), the golden install trees, and the live megaman run for its MCP server and hook only; whether Cursor loads the plugin's skills and commands is unproven. A live subtest of the MCP server and hook would need a Cursor sign-in and a model call on every run, so it is not added
