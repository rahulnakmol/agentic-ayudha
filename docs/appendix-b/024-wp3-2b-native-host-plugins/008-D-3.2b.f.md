# D-3.2b.f

## Plan assumption

WP3.2b and D-3.2b.d: "use the plugin or `install`, not both"; with both, the skills still appeared twice

## Finding

Founder request (2026-10-17), after open point (c) of PR #276: with the aayudha plugin and `install` both present, a host lists every skill twice. Checked in this orb with Codex 0.162.1: `codex debug prompt-input` listed both `aayudha:build` and `build`. Each host's skill sources, from its own docs: Claude Code reads `.claude/skills/`; Codex reads `.agents/skills/`; Cursor reads `.agents/skills/`, `.cursor/skills/`, and, for compatibility, `.claude/skills/` (cursor.com/docs/skills). Amp keeps the first skill of each frontmatter `name`, including those under `~/.claude/plugins/cache/`, so it never lists one twice (ampcode.com/docs/customize/skills). Amp has no aayudha marketplace plugin. Cursor records a marketplace install with the account: `agent plugin marketplace add` needs a sign-in, and no local file shows it, so aayu sees only the local plugin folder `~/.cursor/plugins/local` (cursor.com/docs/plugins)

## Implemented instead

`install` records the installed hosts whose plugin is enabled as `plugin_hosts` in `lock.toml`. Detection: `enabledPlugins` for Claude Code, `[plugins."aayudha@…"]` for Codex, and a `.cursor-plugin/plugin.json` named `aayudha` under `~/.cursor/plugins/local/*` for Cursor. `install` writes aayudha's copies only to a skill directory that an installed host without the plugin reads, and removes them from one it filled before. Amp, Codex, and Cursor share `.agents/skills/`, so it stays while Amp is installed. The product's `verify-*` skills are still mirrored to `.claude/skills/` whenever Claude Code is installed. Cursor's hooks and MCP server now follow its plugin the way Claude Code's and Codex's do (D-3.2b.d). The `skills-copies` doctor row (`hosts.SkillDoubles`) fails, without blocking, in two cases: a host with the plugin enabled finds aayudha's copies in a directory it reads (it names the fix), or a host in `plugin_hosts` whose plugin is now disabled has no skills. Checked live: with the Codex plugin, the old install left 30 copies and `prompt-input` listed `build` twice. The new install removed them, leaving only `aayudha:build`, and `doctor` flagged the old state first. Test: `TestInstallLeavesSkillsToThePlugin`. Not fixed: without any plugin, installing for Claude Code and for Cursor still gives Cursor two copies (`.agents/skills/` and `.claude/skills/`), and a Cursor marketplace install is invisible to aayu
