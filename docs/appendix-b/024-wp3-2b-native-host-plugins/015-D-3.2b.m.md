# D-3.2b.m

## Plan assumption

WP3.2b: doctor's `mcp` row in an untrusted Codex project

## Finding

Founder decision (2026-10-17), on PR #286's note (also on `origin/dev` before it): in an untrusted project the plugin is on (Codex ignores the project's `.codex/config.toml`, D-3.2b.h) and the project registers the server, so the row failed with "the plugin's server and .codex/config.toml both register" and "need aayu install --apply", though Codex lists the plugin's server once and the step is the person's

## Implemented instead

The `mcp` row reports a Codex registration in an untrusted project as a warning that names the trust step, in the same words as the `codex-hooks` row (`hosts.CodexTrustStep`), instead of a failure. Without the plugin it says the same, since Codex loads the server only once the project is trusted. `codex-hooks` still fails until Codex trusts the hooks, because until then nothing refuses a human-only verb. Test: `TestCheckStates` ("untrusted Codex project")
