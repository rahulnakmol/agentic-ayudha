# D-3.2b.g

## Plan assumption

WP3.2b: each host lists each aayudha skill exactly once; with Claude Code and Cursor installed and no plugin, Cursor listed every skill twice

## Finding

Founder follow-up (2026-10-17) to PR #279, its open point (2). Cursor reads `.agents/skills/` and `.cursor/skills/`, and also `.claude/skills/`, `.codex/skills/`, and `.grok/skills/` when "Include Third-Party Plugins, Skills, and Other Configs" is on (Settings → Agents, per user, on by default) (cursor.com/docs/skills, cursor.com/docs/reference/third-party-hooks). Cursor does not deduplicate: the agent CLI 2026.10.16-e3cb207 (`getSkillIdForPath` in its bundle) names a second same-named skill `build-2`. Claude Code reads only `.claude/skills/` (code.claude.com/docs/en/skills); Codex reads only `.agents/skills/` and shows both of two same-named skills (developers.openai.com/codex/skills); Amp keeps the first of each name (ampcode.com/docs/customize/skills)

## Implemented instead

Skill copies go to one folder per reader, chosen only from the installed hosts (`Lock.SkillDirs`): `.claude/skills/` when Claude Code is installed, `.agents/skills/` when Codex is, and when neither is but Cursor or Amp is. Cursor and Amp share Claude Code's copies. An upgrade removes aayudha's copies from a folder the new set no longer needs and keeps the product's `verify-*` skills, which are still mirrored to `.claude/skills/`. Not possible: Claude Code, Codex and Cursor together need both folders, and Cursor reads both, so Cursor lists each skill twice; `install` says so, and doctor's `skills-copies` row warns (turn the import off on that machine, or install for one of the two). With the import off and Claude Code plus Cursor installed, Cursor sees no aayudha skills (installing for Codex adds `.agents/skills/`).
