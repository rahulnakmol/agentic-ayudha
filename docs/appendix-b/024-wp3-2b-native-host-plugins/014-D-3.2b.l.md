# D-3.2b.l

## Plan assumption

WP4.5b.3, D-3.2b.g: one folder per reader for the product's verify skills; Cursor listed each twice

## Finding

Founder decision (2026-10-17). install mirrored `.agents/skills/verify-*/` to `.claude/skills/`, and Cursor reads both. The source has to stay in `.agents/skills`: `aayu verify`, `inspect`'s coverage, the feature-map drift check, and `init --verify-skill` all use that path. Cursor deduplicates skills only by real path (`getDistinctSkillRealpathsFromDirectory`), and a committed symlink breaks Windows checkouts (V2)

## Implemented instead

Claude Code reaches each product verify skill through a pointer command, `.claude/commands/aayudha/verify-<product>.md` (`/aayudha:verify-<product>`): the skill's frontmatter without `name` and `paths` (`hosts.ProductPointer`), and a body that sends Claude to `.agents/skills/verify-<product>/SKILL.md`. Cursor does not read that folder, so it lists each product skill once, from `.agents/skills`. An upgrade removes the old copies in `.claude/skills`. A pointer follows its source, so a changed feature map no longer needs a re-sync; doctor reports a pointer behind a changed description, and `--fix` catches it up. The command name in Claude Code changes from `/verify-<product>` to `/aayudha:verify-<product>`. Tests: `TestInstallGivesCursorOneCopy`, `TestInstallMirrorsVerifySkill`
