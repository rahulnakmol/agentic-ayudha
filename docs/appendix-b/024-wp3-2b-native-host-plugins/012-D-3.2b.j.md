# D-3.2b.j

## Plan assumption

WP3.2b: a hook that counts or blocks runs once per event in every host combination; with Claude Code and Cursor installed, Cursor ran both

## Finding

Founder decision (2026-10-17) on PR #286's open points. Cursor runs Claude Code's hooks from `.claude/settings.json` (and `settings.local.json`, `~/.claude/settings.json`) when "Include Third-Party Plugins, Skills, and Other Configs" is on, which it is by default, and "all matching hooks from every source run" (cursor.com/docs/reference/third-party-hooks); it maps `PreToolUse` to `preToolUse`, so one shell command reached Claude Code's `pre-tool` and Cursor's `beforeShellExecution`. The agent CLI 2026.10.16-e3cb207 also runs `claude-plugin` hooks, and gives every hook it runs `cursor_version` in its input and `CURSOR_VERSION` in its environment (cursor.com/docs/hooks; `buildHookEnvironment` in its bundle). Claude Code sends no `cursor_version`

## Implemented instead

`aayu hook` treats an event with `cursor_version` that reaches a hook not registered for Cursor as Cursor running a Claude Code hook (`hosts.CursorEvent`): it answers in Cursor's format, and stands aside (`{"permission":"allow"}`, or `{}` for `session-start`) when Cursor runs another aayudha hook for the event: the repository's `.cursor/hooks.json`, the plugin in Cursor's local plugin folder, or, for the Claude Code plugin's hook, the repository's Claude Code hooks (`hosts.CursorRunsAnother`). With neither, the Claude Code hook is the guard and refuses in Cursor's format. A hook that stands aside also leaves the halt refusal to the one that runs, so a halt is refused once. The detection reads the event, not the environment, so Claude Code started from Cursor's terminal is unaffected. Not covered: a Cursor plugin installed from a marketplace (D-3.2b.i) beside the repository's Claude Code hooks still runs twice. Test: `TestPluginHooksAndStatusLine` (three hooks, one refusal)
