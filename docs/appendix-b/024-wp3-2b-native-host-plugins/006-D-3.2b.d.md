# D-3.2b.d

## Plan assumption

WP3.2b: "use the plugin or `install`, not both" (documented only)

## Finding

Megaman defect D-5.5c.12 (7): with both present, Claude Code ran both `PreToolUse` hooks and listed two aayudha MCP servers (the project one "Pending approval"). Codex ran both hook sets; its project `[mcp_servers.aayudha]` replaced the plugin's server of the same name

## Implemented instead

Two fixes. First, `install` checks whether the plugin is enabled: `enabledPlugins` `aayudha@…` in `~/.claude/settings.json` or the project's settings, or `[plugins."aayudha@…"]` in Codex's `config.toml`. If it is, `install` writes no hooks or MCP registration for that host, removes those it wrote before (leaving the product's hooks and the status line), and says why. Second, a plugin hook, which passes `--skills`, stands aside where the repository has `install`'s hooks for its host, and its `session-start` says to rerun `install`. The `mcp` doctor row accepts the plugin's server and fails on a double registration. Skills still appear twice while both are present. Checked live: Claude Code 2.1.300 `mcp list` showed only `plugin:aayudha:aayudha` after reinstalling. Tests: `TestInstallLeavesHooksAndMCPToThePlugin` and `TestPluginHooksAndStatusLine`
