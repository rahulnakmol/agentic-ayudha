# D-4.5b.1

## Plan assumption

WP4.5b.1: the `feature-map` floor; handles are "the `name`, `label`, `within`, and `test` values of a check's steps"; stale features are "sources changed since `verified_at`"

## Finding

Drift in a PR is often the change itself (a renamed button), and the maintain pass corrects the map in its own PR, so a blocking drift floor would block the very PRs it describes. Values deeper in a step (a request body's `"name"`) are data, not handles. A test name is a substring of longer test names. `verified_at` is a commit, and a shallow clone (the loops' checkout) has no history to diff

## Implemented instead

`internal/verify/featuremap.go`. Maps are found with `git ls-files --cached --others --exclude-standard` (tracked and not-ignored untracked files, so a map being written is checked before it is committed). The `feature-map` floor always passes: its value is the drift count, its detail starts "advisory:", and it writes `reports/feature-map.json`; `aayu verify --map` exits 3 on drift. No floor threshold, config key, or CONSTRAINTS.md row is added. Handles are the `HandleKeys` fields of a step's action object only (`{"click": {"name": …}}`), and a `test` handle matches as a whole word. A feature whose `verified_at` is not in the clone's history is reported stale ("never verified" when empty); stale is reported, never drift. Tests: `TestMapDrift`, `TestMapStaleOnly`, `TestMapFloor`, `TestVerifyMapExitCodes`
