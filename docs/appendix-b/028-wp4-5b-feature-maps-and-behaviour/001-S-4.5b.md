# S-4.5b

## Plan assumption

WP4.5: the web floors load each screenshot or recording criterion's URL and photograph it, and behaviour criteria are evidenced only by Go tests named in `.aayudha/evidence/<story>.toml`; WP4.6: k6 thresholds for API and CLI contracts; WP3.2: `install` copies only aayudha's own skills; WP7.1: the loops are the digest, decisions, retro, seat review, and evolve; the `verify` skill body is a stub

## Finding

Founder decisions (2026-10-15, relayed by the orchestrating thread), after the research in docs/research/verification-skills-2026-10.md: (1) generic, not UI-only: a feature map lists a repository's capabilities and each has a behaviour check of the kind that fits (a UI flow, a CLI command, an API call, a library or function call), with no assumption of user journeys or a browser; (2) the control tool uses the product's own stack (Node and Playwright for web apps, shell or a PTY driver for CLIs, plain HTTP for APIs, the product's test framework for libraries) and adds no runtime the product lacks; (3) behaviour checks block the merge gate at once when a mapped check fails, and run in CI deterministically with no model; (4) a free deterministic drift check runs on every PR; (5) no AI keys in a product repository's CI: the model-driven maintain pass runs weekly and on drift by @-mentioning an agent app the user installed (@claude, @cursor, @amp, @codex) with the maintain brief, and its result is at most one PR of map corrections through the normal gate; (6) the verify skill gains create and maintain procedures, `aayu init --verify-skill` creates it, `install` mirrors it to hosts, grill, plan, and inspect read the map, and a nightly loop sweeps every check. This extends the plan; WP4.5's static captures and WP4.6 stay

## Implemented instead

WP4.5b (five parts, WP4.5b.1–5), one small PR each to `dev`. The research's journeys become generic behaviour checks (`kind` ui, cli, api, or lib), its control CLI a contract (`<control> check`, JSON in, result and artifacts out) that each product implements in its own stack, and its source pass `aayu verify --map`. Per-PR drift is reported, not blocking (WP4.5b.1), so that the maintain pass's own PR can correct it; the behaviour checks themselves block
