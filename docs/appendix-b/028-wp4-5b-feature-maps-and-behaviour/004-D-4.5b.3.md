# D-4.5b.3

## Plan assumption

WP4.5b.3: `aayu init --verify-skill <web\|cli\|api\|lib>` scaffolds a stub for that kind; `install` mirrors product `verify-*` skills to every host's skill directory; `doctor` reports a map that is missing, malformed, or drifted

## Finding

One product mixes kinds (benefits-qa has ui, api, and lib checks), so the kind belongs to each check, not to the skill; what decides the control tool's language is the stack the product already has (founder decision 2). Amp, Cursor, and Codex read `.agents/skills/`, where the skill is written, so only Claude Code needs a copy. `aayu verify --map` already reports a missing, malformed, or drifted map, free and deterministic

## Implemented instead

`--verify-skill` is a bool. `internal/initrepo/verifyskill.go` detects the stack: `go.mod` → `hosts/verify-skill/go/control/main.go`, else `package.json` → `node/control.mjs` (Node and Playwright), else `other/control.sh`, a stub that blocks until it is replaced. It writes `.agents/skills/verify-<repo>/` (SKILL.md, a map with no features that passes `verify --map`, the tool) through init's owned-file writer, so uninit keeps an edited file. The examples' control tools are these templates (`TestInitVerifySkill`). `install` copies the root `.agents/skills/verify-*/` to `.claude/skills/`, never over an aayudha skill, records it under `[product_skills]` in `lock.toml`, and removes the copy of a deleted skill; a map nested in a monorepo is not mirrored. `doctor`'s `skills-copies` check reports a copy behind its source and `--fix` catches it up; map drift stays with `verify --map` and the floor. The skill body holds the create and maintain procedures (`skills/verify/references/`). Tests: `TestInitVerifySkill`, `TestInstallMirrorsVerifySkill`
