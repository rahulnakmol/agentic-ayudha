# D-4.5b.5

## Plan assumption

WP4.5b.5: `plan` writes the touched features' checks into the evidence-map skeleton; `inspect`'s context lists the features a PR touches

## Finding

A plan is written before the code, so which features a story touches is known only from its footprint layers. The skeleton is rendered by the delegation brief from the plan's checkpoints. The merge gate's pack already holds `reports/behaviour.json` (each check run, its feature, why it was selected, and its result) and `reports/feature-map.json`, and inspect already quotes the pack's text artifacts as untrusted data

## Implemented instead

`grill --assess` reports `feature:<id>` (kind `feature`) for each mapped feature whose id, surfaces, or check ids share a word with the idea, naming its checks. `aayu plan <story>` lists the mapped features in the footprint's layers; a checkpoint may name `checks`, which plan refuses when a map has no such check, and the brief writes them as `checks = [...]` beside `tests`. inspect is unchanged: it reads the features and checks from the pack's reports. The evals' grill conversations do not load maps, so their baselines are unchanged. Tests: `TestAssessFeatureFacts`, `TestPlan` (unknown check), `TestBrief`
