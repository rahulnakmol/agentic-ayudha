# D-5.1y

## Plan assumption

D-5.1x continued: retro gates after two consecutive filtered `retro/` runs on the same skill text pass the bar. Run 39062618066 (38ccc40) was the first pass after the D-5.1x fix: means 4.4 (em-enterprise), 4.6 (em-scaleup), and 4.8 (em-startup), every run at 4 or more, no floor failure, pass^5 1.0, 1.88 USD.

## Finding

The second run, 39063683121 (fbf4724, 0.82 USD), missed. Eleven of its fifteen runs ended in model-endpoint 502s, which survived the harness's two retries (D-3.4y); those are gateway faults, not scores. Of the four scored runs, one em-enterprise memo scored 3. It called a proposed Ready-time validation "a **check**-layer fix" and cited story #212 and `LAYERS.md` for it. The term comes from the skill's own step 3, which classifies Feedback by fix layer (codebase, check, prose, review) with `--classify`. The skill forbids citing the skill itself, and `LAYERS.md` holds the code layers L01 to L09, not fix layers. So the memo stated an unrecorded classification as fact and gave it a source that does not state it. The judge read this as an invented category that overreached its citation.

## Implemented instead

`skills/retro/SKILL.md`: an explanation names a Feedback issue's fix layer only as the report's "Fix layer of Feedback" table records it, citing the report. Otherwise it proposes the change and leaves the layer unnamed, and `LAYERS.md` is never the source of a fix layer. The rubric, the cases, and the floors are unchanged. Because the skill text changed, the count of consecutive passes starts again from zero: two more filtered runs on this text must pass before the gating PR opens.
