# D-5.9m

## Plan assumption

The founder's answer to the D-5.9l checkpoint: wire `--parity` and `--compat` into the merge gate for modernisation Stories; exact numeric parity needs a pinned reference build with pinned flags; a cheap check for `decided_by "request"`; a narrowly scoped secret for scratch-repo filing tests; evals dispatched on `dev` only

## Finding

Before this, a parity criterion was only text: nothing in `aayu verify` ran it, so a rewrite whose output differed could merge on other evidence. MINPACK's own Release flags change the numbers all six test drivers print (`probe:check-differs:hybrd1`, D-5.9j), so goldens from an unnamed build prove nothing. `decided_by "request"` was taken on trust. Survey filing needs only one repository's issues and its ledger branch, not the admin token that creates and deletes repositories (D-0.4f)

## Implemented instead

**Merge gate:** a `parity` floor in `verify.Standard()` (`internal/verify/parity.go`) applies when a Ready criterion runs `aayu survey --parity` or `--compat`. The Story's evidence map (`.aayudha/evidence/<story>.toml`) gives each such criterion a `[[criterion.parity]]` or `[[criterion.compat]]` run (`cases`, `bin`, an optional `build` run in the sandbox without network, and `ids` or `areas` for the part the Story delivers); the floor replays the case sets or suites the criterion names against the committed capture under `.aayudha/survey/golden/`. Any difference or regression fails it, a criterion with no run or a failed build blocks it, and only a holding run evidences the criterion, so the rewrite cannot merge while its contract fails; it is not waivable (`TestParityFloor`). The compat score is computed on a copy of the capture, so verify leaves the checkout as it found it. The evidence map, not a new config file, carries the runs, because it already maps criteria to evidence. **Reference build:** a case set that proves an `exact` interface names its `reference` (commit, toolchain and version, flags), or `aayu survey --draft` fails. **Request quotes:** an interface `decided_by "request"` carries `quote`, the request's own words, which must appear in the request (case and white space folded); whether those words mean that level stays the judge's call, a known gap. **Scratch secret (founder to create):** a permanent private repository `rahulnakmol/aayu-survey-scratch`; a fine-grained personal access token with access to that repository only, Issues read and write (issues, labels, sub-issues), Contents read and write (the ledger branch the actions log writes), Metadata read, expiring in 90 days; stored as `AAYU_SURVEY_SCRATCH_TOKEN` in the `live-tests` environment. Until it exists, filing tests stay on the fake GitHub. **Evals** are dispatched on `dev` only. The standing rule of D-5.9l holds: the survey group gates only after two consecutive full runs at 4.0 or more
