# D-5.9j

## Plan assumption

D-5.9i's runtime evidence on real legacy code: MINPACK (Fortran), Maruku (Ruby), and JSON-java (Java)

## Finding

The first pilot runs of `--probe` and `--compat` reported nothing or noise where the evidence was real

## Implemented instead

Each fault was in the tool, not the code under test. Coverage named no function when the index was read back from `index.json` (symbols kept only `At`) or the checkout was given as `.`, so `Index.index` restores each symbol's file and line and `Probe` makes the checkout absolute. An included build file (`cmake/UserOverride.cmake`, which sets MINPACK's Release flags `-O3 -march=native -ffast-math`) was never read for flags, and a flag after `(` was missed; `-march=native`, `-xHOST`, `-no-prec-div`, and `-ffp-contract=fast` are now flags that change results. `strace -y` resolves each opened path, since a JVM opens files relative to a directory it changed into; a directory opened is not a dependency, nor is the checkout's own source as an interpreter loads it, nor the user database; and more than five files under one directory outside the checkout are one fact (a class path, a gem directory). A case runs hermetically (PATH, a scratch HOME, `LC_ALL=C`, `TZ=UTC`), so `env` in the cases file adds what it needs (`GEM_PATH`, `LC_ALL=C.UTF-8`), each a recorded dependency: under `LC_ALL=C` a JVM wrote every non-ASCII character as `?`, which the locale probe caught. The Java locale rule now also matches a static-imported `format`, which JSON-java's `JSONPointer` uses for a message whose `%d` prints Arabic-Indic digits under `ar-SA`. MINPACK's test drivers are FORTRAN 77 main programs with no PROGRAM statement, so the index saw no entry point in them: a statement outside every unit of a Fortran source file (not an include file) now starts a main program named after the file, and READ or WRITE on a unit held in a variable (`data nread /5/`) is a `unit-io` surface. An implied-shape constant (`real, parameter :: y(*) = […]`) is no longer an assumed-size trap. `--check-bin` also records a case whose stdout or exit code differs on the checker build (`check-differs`): the same code built another way should print the same, and MINPACK's did not, under its own Release flags (6 of 6 cases) or an `-O1` sanitiser build (3 of 6). A `check-differs` fact now carries the checker build's error line from stderr (the first new line that reads like an error, since a warning often comes first): Maruku's frozen-string-literal build printed nothing for 156 of its 162 spec cases, and only stderr said why (`FrozenError` at `lib/maruku/input/linesource.rb:83`). Files read under a library path the case sets (a `*PATH` variable such as `GEM_PATH`, `PYTHONPATH`, or `CLASSPATH`, or `GEM_HOME`, `PERL5LIB`, `RUBYLIB`, `R_LIBS`) are expected loads, counted in one `ran` line instead of about 35 facts of gem files; any other variable (a configuration directory) stays a dependency whose reads are reported. The Ruby dynamic-require rule also reads the raw source for a path built by interpolation (`require "maruku/ext/#{e}"`, `bin/maruku:70`), which blanked strings hid (`TestProbe`, `TestKeywordLanguages`, `TestSurveyGoldenParity`)
