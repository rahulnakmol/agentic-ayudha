# D-5.9h

## Plan assumption

The founder's follow-up to Decision #287: index legacy stacks properly (Fortran with fixed and free form, modules, subroutines, functions, COMMON, INCLUDE, and USE; decide with evidence which other legacy languages deserve the same) and say plainly which languages are not indexed; make traps a first-class part of the survey

## Finding

A parser per language would need cgo or a server (D-5.9a). Traps are semantic (aliasing, implicit typing, reflection, default charsets, compiler flags that change arithmetic), so no pattern can decide one, and a list of every match would flood the draft

## Implemented instead

`internal/survey/keyword.go` reads the case-insensitive keyword languages with the standard library: Fortran (fixed form by extension: comment characters in column 1, labels and continuations in columns 1-6, columns 73-80 ignored, DEC tab form; free form with `!`), program units nested under their module, derived types, `CALL` and function references, `USE` resolved to the defining module's file, `INCLUDE`; COBOL (fixed or free reference format, PROGRAM-ID, sections and paragraphs, PERFORM, THRU, GO TO, and `CALL 'name'`, COPY); Pascal and Delphi (units, routines in the implementation part, `uses`, `{$I}`); Visual Basic (VB6 `VB_Name`, Sub, Function, and Property with their End, VB.NET classes and modules, Imports). The choice is by evidence of legacy weight: the TIOBE index for September 2026 ranks Visual Basic 7th, Fortran 11th, Delphi/Object Pascal 13th, and COBOL 20th, all above Ruby (22nd), Lua (31st), and Tcl, and these four are the stacks whose estates are retiring (TIOBE's March 2025 commentary). Lua, R, Tcl, Ada, PL/I, RPG, ABAP, assembly, JCL, and SQL are recognised and counted only: each language count carries `counted_only`, `aayu survey` prints it, and `SURVEY.md`'s limits say "counted by file and line only, never read". An extension-less script is read by its `#!` line (Ruby's `bin/maruku`); an `.inc` file is PHP, Fortran, or Pascal by what else the checkout holds. Traps (`internal/survey/traps.go`): about 90 rules across Fortran, Ruby, Java, C and C++, PHP, Python, JavaScript, COBOL, Visual Basic, and Pascal, plus generated files and semantics-changing build flags (`-ffast-math`, `-fdefault-real-8`, `-fno-automatic`, `-Dfile.encoding`, …), and a Fortran unit without IMPLICIT NONE (module procedures inherit their module's). Each rule records one `trap:<rule>:<path>:<line>` fact per file with a count, in the index, the summary, and each module pack, citable like any fact. `skills/survey/references/traps.md` holds the questions to check for every rule, and per stack the ones no rule can match (column-major arrays, Integer and Float semantics, checked exceptions); `TestTrapRulesHaveQuestions` fails on a rule without its heading. Run on three real legacy codebases: MINPACK in fixed-form Fortran (COMMON blocks and Hollerith FORMAT constants in the test drivers, 43 units without IMPLICIT NONE; its CMake build's `-fdefault-real-8` sits in a comment, which the first version reported, so build flags are now read with `#` and `//` comments blanked), Maruku in Ruby (a monkey patch of `Array`, `method_missing`, `File.exists?` removed in Ruby 3.2), and JSON-java (reflection over getters, `getBytes()` with the default charset, 11 swallowed exceptions in `JSONObject`) (`TestKeywordLanguages`)
