# D-5.9a

## Plan assumption

Decision #287: index first, deterministically: the build graph, symbols, and call graphs

## Finding

A parser per language (tree-sitter, clangd, or a language server) needs cgo or a running server, which ground rule 2 (`CGO_ENABLED=0`, one static binary) and the binary size budget rule out

## Implemented instead

`internal/survey` reads every stack with the standard library: Go through `go/parser`; brace languages (C, C++, Objective-C, Java, Kotlin, C#, JavaScript, TypeScript, PHP, Rust, Swift, Scala) by a scanner that blanks comments, string contents, and C preprocessor lines, then reads the text before each brace as a type, a function, or a block; Python by indentation; Ruby, Perl, and shell by their definition keywords. Calls are names followed by `(` inside a function's body, resolved by name only, so an edge to a name defined more than once lists every definition and is marked ambiguous, and dynamic dispatch (`$this->$m()`, `getattr`, `eval`, `dlsym`, reflection) is reported as a surface rather than guessed. A language the table does not know is counted under "not indexed" by extension. Tested on a mixed fixture (`internal/survey/testdata/legacy`) and on this repository (about 4,200 symbols and 16,000 edges in about 4 s)
