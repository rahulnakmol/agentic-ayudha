# D-5.2a

## Plan assumption

WP5.2: PostHog, Sentry, and GitHub read adapters return `{metric, population, window, value, source_query, fetched_at}`; accept: recorded fixtures give the golden tuples, a missing adapter exits 5 naming the `[integrations]` key, a write-scoped key is refused by WP1.3 before any call. WP1.3: `doctor` verifies read-only scope where the provider API allows

## Finding

Built ahead of M5 (founder scheduling, 2026-10-12) with no PostHog or Sentry account and no read-only GitHub key, so no exchange could be captured live. `[integrations.<name>]` had only `secret` and `scope`, and the providers also need a host, an organization, and a project. The plan names no metrics and no GitHub token for baselines. No verb consumes a baseline before `grill` (WP5.3)

## Implemented instead

`internal/integrations` (the tuple, `Resolve`, a read-only transport) with the adapters `posthog`, `sentry`, and `githubread`, and the catalog `providers` (`Baseline` for verbs, `Check` for `doctor`). `[integrations.<name>]` gains `url` (when not the default host), `org` (Sentry), and `project` (PostHog project ID, Sentry project ID, or the GitHub `owner/name`, default the current repository). Metrics: PostHog `events` and `users` (one HogQL `count()` or `count(DISTINCT person_id)`, the filter a HogQL predicate); Sentry `crash_free_sessions` and `crash_free_users` (sessions API, a fraction in [0, 1]; no sessions is an error, not 0), `errors` and `users_affected` (events API, errors dataset); GitHub `issues_opened`, `issues_closed`, `prs_opened`, `prs_merged` (search API `total_count`; incomplete results are refused). The window is half-open `[from, to)` in UTC; `population` names the provider, project, and filter; `source_query` is the exact request (method, URL, and PostHog's JSON body), so re-running it over the window reproduces `value`. GitHub baselines use their own key, `[integrations.github]`, not the human token, so the read-only rule covers them too. Before any data request, in order: a missing section, field, or secret is `ErrNotConfigured` (exit 5; the message names the section, the fields to add, and the `aayu auth set-secret` command); `scope = "write"` is `secrets.ErrWriteScoped` (exit 4) with zero requests sent; then the provider's own report of the key (PostHog `GET /api/personal_api_keys/@current/`, Sentry `GET /api/0/`, GitHub `X-OAuth-Scopes` on `GET /user`), where any scope that is not read-only (`*`, `…:write`, `project:releases`, `repo`) is refused (exit 4). Fine-grained and App GitHub tokens report no scopes, so the configured scope is trusted and `doctor` says so. Every adapter request passes a transport that allows GET and HEAD plus the one PostHog query POST and refuses anything else as `actions.ErrCapability`, so the adapters cannot write and have nothing to put in the actions log. The fixtures are synthetic, written from each provider's API reference and labelled so in their `source` field; `TestBaselinesGolden` replays them request by request (method, URL, body, auth header) against tuples written by hand. `TestLive` (behind `AAYU_LIVE=1`) skips each provider whose key is absent; its GitHub case passed against this repository on 2026-10-12. `doctor`'s `integrations` check lists every adapter (`not configured; set [integrations.<name>] for …` is not a failure), refuses a write-scoped key without sending it, and reports reachability and the verified scope; an unreachable provider or a write-capable key fails the check without blocking. The CLI maps `ErrNotConfigured` and provider errors to exit 5 and an invalid query to exit 2
