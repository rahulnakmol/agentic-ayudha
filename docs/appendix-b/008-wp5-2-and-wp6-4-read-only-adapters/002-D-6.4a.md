# D-6.4a

## Plan assumption

WP6.4: Figma REST + PAT primary (`get images`, nodes, variables), remote MCP opt-in; Mobbin MCP client returning URLs and IDs only, never pixels; lint blocks Mobbin-origin images anywhere; accept: `doctor` reachability, a `research` fixture returns a reference set with URLs only

## Finding

Built ahead of M6 (founder scheduling, 2026-10-12) with no Figma or Mobbin account. Mobbin's MCP endpoint (`https://api.mobbin.com/mcp`, streamable HTTP, Pro plan and up) and Figma's (`https://mcp.figma.com/mcp`) authorise with OAuth only, and the Go SDK's client-side OAuth is experimental (V5). Mobbin's results carry a preview image and an expiring `image_url` beside the page link; its published tools are `search_screens`, `search_flows`, `search_sections`, all read-only, and their exact result shape is not published. `research` itself is WP6.5. The WP3.1 Mobbin rule covered skills only

## Implemented instead

`internal/integrations/figma`: REST with `X-Figma-Token` (`Nodes` from `/v1/files/:key/nodes`, `Images` as rendered URLs from `/v1/images/:key`, `Variables` from `/v1/files/:key/variables/local` in each collection's default mode with aliases resolved and colours as `#rrggbb[aa]`); `[integrations.figma] transport = "mcp"` (a new key, Figma only) switches `Nodes` and `Variables` to the remote MCP tools `get_metadata` and `get_variable_defs` (variables used by the given nodes, without collection or type) and refuses `Images` (REST only). `internal/integrations/mobbin`: `Search(kind, query, platform, limit)` returns an `integrations.ReferenceSet` of `{source, kind, id, url}`: the ID and the `https://mobbin.com/…` page URL of each result, read from structured content or JSON text, plus Mobbin page links in plain text; image, audio, and embedded blocks are never read, and image URLs, CDN hosts, app names, and descriptions are dropped, so the set holds URLs and IDs only (a result whose only link is an image is dropped). Only arguments the tool's input schema declares are sent. For both MCP servers the secret is an OAuth access token minted outside aayudha (for example by a host's MCP login) and sent as a bearer token; there is no refresh, so an expired token shows as unreachable in `doctor`. The token's scope is the server's tool list: a tool that is neither one the adapter knows as read-only nor annotated `readOnlyHint` makes the token write-capable, and the adapter then refuses to call anything (exit 4); if Figma's server offers write tools to a token, the opt-in is refused and REST stays the path. MCP traffic passes the read-only transport (POST and DELETE to the endpoint path only). `providers` adds `figma` and `mobbin` (`Check` for `doctor`, `providers.Figma` and `providers.Mobbin` for WP6.5's verbs). `doctor` reports Figma reachable through `GET /v1/me` (Figma does not report a PAT's scopes, so the token needs `current_user:read` and the configured scope is trusted) and Mobbin through `initialize` and `tools/list`. Lint: `skills.MobbinImages` applies the WP3.1 rule to any tree, and `TestNoMobbinOriginImages` (CI `build`) runs it over the whole repository except `.git` and `node_modules`; product repositories and `ledger/design/` get it with the WP6.5 artifacts. Fixtures are synthetic and labelled so: a replayed REST session for Figma, and recorded MCP surfaces served by an in-process go-sdk server for Mobbin and Figma. `TestLive` in each package runs behind `AAYU_LIVE=1` and skips without `AAYU_SECRET_FIGMA` (plus `AAYU_LIVE_FIGMA_FILE`, `AAYU_LIVE_FIGMA_NODE`) or `AAYU_SECRET_MOBBIN`
