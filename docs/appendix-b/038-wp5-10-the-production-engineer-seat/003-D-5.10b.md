# D-5.10b

## Plan assumption

Decision #324: `slo` and `runbook`; the error budget feeds release and promotion gates; safe rollout and rollback in plan and release, the rollback tried once; production loops under the schedules-only model

## Finding

The ladder's gates (`ci.yml` `gate=rolling\|stable`) run in Actions, where no telemetry may reach; an SLO window (28 days) is wider than a query's 7-day bound; release had no source of "tried once"; the plan draft had no place for a rollout

## Implemented instead

**A recorded budget gates release.** `ops/slos.toml` (`production.ParseSLOs`: `availability` or `latency` under a threshold, an objective below 100 %, a 1d to 90d window, the alert, the runbook) is measured from a sanitised export over the covered part of its window (`production.Measure`: good and total, budget left, 1h and 6h burn rates), and `aayu slo --telemetry <dir> --record` writes `slo/status.json` to the ledger from the person's own session. `aayu release` reads the source branch: with SLOs, a status older than 8 days (the weekly review plus a day) or missing an SLO refuses, and while a budget is spent only Bugs ship, a Story needing an accepted `error-budget` waiver (`decide.Waivable` gains it); with catalog rollback actions, each must have a successful `aayudha-ops.yml` run (matched by its run name) before a release depends on it. The gate runs before the candidate, so a refusal promotes nothing. `aayu slo --draft` checks an SLO document (Journey, Objectives, Error budget, Alerts, Budget policy) whose toml block is the proposed `ops/slos.toml`, and `--create` writes it into the checkout; `aayu runbook` checks `ops/runbooks/*.md` (Symptom naming an SLO, a bounded Confirm query, a catalog Mitigate action, Verify, the catalog Rollback, Tried) and names each alerting SLO with no runbook, and `--create` writes a checked one; both files are protected paths a person reviews. A plan of a product with SLOs needs a `rollout` (flag, canary, the SLOs to watch, the rollback trigger, the rollback; `planning.CheckRollout`, `evals/schemas/plan.json`). Loops (agent loops, never Actions): `alert-triage` (twice each weekday: fast burn and incidents with no investigation note), `error-budget-review` (weekly: measure and record), `patch-sweep` (weekly: the deps floor, a Bug per fixable advisory, which ships while a budget is spent). The investigate query log becomes one type that `slo` reuses (`TestSLOs`, `TestCheckRunbook`, `TestSLOAndRunbook`, `TestReleaseProductionGate`, `TestPlan`)
