# D-1.1b

## Plan assumption

WP1.1b: "fun never costs correctness"; persona data "from the parallel persona work, not duplicated"; "every error ending with the exact next command"; golden tests per mode

## Finding

The persona work (WP5.1b, merged while this was built) gives each twin a name, a purpose, and signature questions, but no intro or sign-off line. A celebration needs to know what is a first. The status table has 13 columns, wider than a terminal. Hosts cannot afford a GitHub call on every status-line refresh

## Implemented instead

`internal/ui` resolves each stream's level: Machine (a pipe, `--json`, `AAYU_AGENT=1` and so MCP, `--ci` or `CI`) adds nothing to a command's existing text; Plain (`--plain`, `[ui] plain`, `AAYU_PLAIN=1`, `TERM=dumb`) is ASCII words only; Rich adds symbols, motion, and colour (none with `NO_COLOR`; themes `auto`, `saffron`, `contrast`, `mono` under `[ui] theme`). Results go to stdout; the seat's intro and sign-off, live progress, and celebrations go to stderr, so `aayu status > file` holds only the result. A status keeps its word (PASS, WARN, FAIL, N/A) at every level. The seat voice reads the seat's `persona.toml` (WP5.1b, `seats.Persona`) from the embedded assets: the twin's name, its purpose up to the first colon as the intro, and one of its signature questions, picked by a hash of the command name so it is stable, as the sign-off; a seat without a persona falls back to the first clause of its charter's `## Purpose` and has no sign-off. Milestones are recorded once per checkout in `.aayudha/state/milestones.json` (first Ready story, first proven ship, Level 1); every release celebrates. Errors print `next:` with the command the error itself names in backticks, else one for its exit code (`<command> --help` for usage, `aayu doctor` for external errors, `aayu next` when blocked, `aayu verify` for a floor miss, `aayu status` for budget), and `--json` errors gain `next`; `ready`, `build`, and `tour` name their own. `status` and `doctor` show a person a seven-column table and a status table with a tally; machines keep the markdown table and the tab-aligned rows. The home screen reads GitHub with the human token (Ready, in-progress, and blocked story labels; up to ten open story PRs, their reviews, and their check runs, using `ship`'s gate checks), local packs, and `measure/due/` on the local `origin/ledger`, and caches itself in `.aayudha/state/journey.json` for host status lines. `verify` runs its floors one at a time to show each (the report is the one `verify.Execute` builds). The effective config gains `[ui]`, so the audit fixture's config hash changed. Tests: `TestHomeModes` (nine goldens), `TestNextForAgentsAndScripts`, `TestHomeOutsideARepoAndWithoutGitHub`, `TestErrorsEndWithNext`, `TestVoiceReadsThePersona`, `TestTour`, `TestCompletionScripts`, `internal/ui` level, mark, progress, and table tests, and `internal/journey` `TestNext`
