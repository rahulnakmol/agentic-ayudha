# D-5.8a

## Plan assumption

S-5.8: a vagueness gate at every entry point that takes free text, running `aayu grill <type> --assess --idea` deterministically

## Finding

"Vague" cannot be decided by rule, only approximated; a gate that unpacks too often adds friction to concrete asks. The four delegate commands (`hosts/commands/{codex,cursor,claude,amp}.md`) and the Amp palette (`hosts/amp/aayudha.ts`) are owned by the delegation thread (WP5.5b), whose commands already run `aayu grill story --assess --idea "<goal>" --json` and hand off only after `aayu ready` passes, and `build --delegate` refuses a story that is not Ready

## Implemented instead

`internal/grill.GateFor` (in the assessment, JSON `gate`): **unpack** when the request has a catalogue qualifier (`vague`), an abbreviation or jargon term (`term`: all caps or a numeronym, not a code identifier, not on the jargon file's Plain list, with its usual meanings, several meanings named), or, with no qualifier, nothing observable (`outcome`: no number outside issue references and terms, no quoted wording or backticked literal, no route or path, no flag), carrying the rough-idea dimensions; **pass** otherwise, with `next` telling the skill to draft from the request's own words (`stated (request)`). Entry points: the grill skill's new "The gate" section, and the build, slice, and plan skills ("Words, not an issue? Unpack first"); the MCP `grill` prompt puts the verdict first, and a new MCP `ask` prompt (`request`, `verb` build, plan, slice, or grill; slice assesses a Feature) wraps the words as untrusted, embeds the assessment, and tells the host to unpack or pass and then continue with that verb's skill; `aayu build` or `plan` given words instead of an issue fails with ``next: aayu grill story --assess --idea "…"``. The TUI asks one step per term and per rough-idea dimension. The delegate commands (WP5.5c, owned there) already run the same assessment and then the grill skill's gate step, so they are unchanged; switching their step to read `gate.verdict` and the Amp palette are left to that thread. Tests: TestGate (each kind and its near misses: an issue reference and B2B are not numbers, a backticked command is observable), TestGrillAssess (gate, terms, build given words), TestPromptsResourcesAndExitCodes (`ask`)
