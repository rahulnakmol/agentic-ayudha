# S-7.1e

## Plan assumption

S-7.1b to S-7.1d: scheduled and event loops in each agent's native tooling, every host the user has set up at once, doctor per host × loop

## Finding

Founder decisions (2026-10-16), narrowing the design for 0.2: (1) 0.2 ships scheduled (cron) loops only, as the starter: `install --loops` and `init --gates` set up no event trigger in any tool (no Amp spawners, no Cursor event automations, no Claude Code GitHub triggers, no record-only Actions event jobs), and the useful work of the default event loops moves to schedules; event loops are deferred to a later version, with D-7.1e's research and host × event matrix as the basis. (2) The user picks one tool to run every loop, offered only from the tools detected; it warns when loops are already active in another tool, since each would run twice; doctor shows each loop's owner tool. (3) Per tool: Amp fully automatic (`set_schedule`); Cursor through its API or Terraform, else a prompt for its `/automate` skill; Claude Code an exact `/schedule` prompt per loop; Codex a prompt to paste into a Codex or ChatGPT chat; a "Run now" test for each. (4) This repository: pause the `triage-new` spawner, keep the weekly triage schedule, add a daily one. (5) The loops guide and the hand-offs deep dive say so

## Implemented instead

One PR. **Format:** `loops.Parse` refuses `on` and `filter` with "event loops are deferred to a later version (S-7.1e)" and requires `cron`; the event code goes: `Events`, `Loop.Native`, `AmpSubscription`, the Cursor event triggers, the Actions event jobs, the guard's event branch, and the session-start pick-up (`loopEvents`, its cursor file, and the fake GitHub fields only it used), so nothing can render an event loop (`TestParseRefuses`, `TestGolden`). **Default loops:** `triage-new` and `feedback` are removed; `triage-daily` (daily 09:00) classifies new intake issues and the weekly `triage` stays; `ci-failed` becomes a sweep (weekdays 09:45, 13:45, 17:45) that syncs each delegated story whose pull request has a failed required check; `release-measure` becomes weekly (Mondays 10:30) and reports only when a release was published that week; Feedback reaches `evolve` on its monthly schedule. The four agent-only loops have no Actions job. **One tool:** `install --loops` asks "Which tool should run this repository's loops?" at a terminal, offering only the CLIs `agentenv.Detect` finds, takes `--host`, or uses the only one detected; `--host all` is refused. It warns when `loops/active.json` records loops in another tool, and `--record <loop>=` (an empty ID) forgets one. In Actions the guard answers "not due here" for a loop recorded in an agent tool, so the fallback never runs it a second time (`TestLoopDigestOnSchedule`). doctor's `loops` row lists each loop with its owner tool: active, stale, missing, or double (`TestChecksGolden`). **Per tool:** Amp, `--apply` runs `amp -ox --project <repo> --no-archive-after-execute -x` once per loop, a headless thread in an orb of the project that calls `set_schedule` with `loops/amp/<loop>.json` and keeps that schedule, and records it; Cursor, `--apply` runs Terraform as before, and `loops/cursor/automate.md` (new) has one `/automate` prompt per loop; Claude Code, `loops/claude/routines.md` has one `/schedule` prompt per loop with its cron and zone; Codex, `loops/codex/scheduled-tasks.md` has one chat prompt per loop with its RFC 5545 rule. **Run now:** `--run-now <loop>` (human-only) runs the loop's prompt once with the tool's own CLI in the checkout (`amp -x`, `cursor-agent -p`, `claude -p`, `codex exec`), marked as a test so `not due` does not stop it while halt and the budget still do; at a terminal it is offered after setup (`TestInstallLoops`)
