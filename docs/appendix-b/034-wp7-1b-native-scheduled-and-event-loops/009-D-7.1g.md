# D-7.1g

## Plan assumption

S-7.1e: `aayu install --loops` is the one entry point that sets a repository's loops up in one tool

## Finding

Defect from the live megaman test (D-5.5c.12, defect 5; PR #269, 68b65fa): in a fresh repository, `install --loops` stopped with "no loops/*.toml in this repository; `aayu init --gates` adds the defaults", but `init --gates` only renders the loops a checkout already has and writes no `loops/*.toml`, so the Claude Code and Codex plans failed until the person copied aayudha's `loops/` in

## Implemented instead

Founder decision (2026-10-16): fix before v0.2.0 (#268). The default loops (`loops/*.toml`) are embedded in the binary (`aayudha.Assets`). In a repository with none, `install --loops` writes them (`loops.Defaults`) and every tool's render (`loops.Files`: `loops/amp/`, `loops/cursor/`, `loops/claude/`, `loops/codex/`, and `.github/workflows/aayudha-loops.yml`), says so, and then plans as usual; `--record` there still refuses. `loops.Defaults` leaves out `setup` and `setup_run` with the comment above them, because they are this repository's own (its example's Playwright, D-8.1b); a product adds its own. Regression test `TestInstallLoopsAddsDefaults` (claude and codex in a fresh checkout; it fails without the fix with that exit 2). **Proven on a scratch repository (2026-10-16, a local `git init` with origin `rahulnakmol/scratch-loops`, deleted afterwards):** `aayu install --loops --host <tool>` without `--apply`, a fresh scratch per tool, exit 0 for amp, cursor, claude, and codex; each added 25 files, listed digest and verify-sweep as run by Actions, and gave its tool's steps: amp `--apply` for 9 loops (`loops/amp/*.json`), cursor `loops/cursor/aayudha-loops.tf` and `automate.md`, claude 8 `/schedule` prompts in `loops/claude/routines.md`, codex 8 prompts in `loops/codex/scheduled-tasks.md` (seat-review runs only in amp and cursor); no `setup_run` or `aayudha/floors` in the scratch's `verify-sweep.toml` or workflow; a second run added nothing
