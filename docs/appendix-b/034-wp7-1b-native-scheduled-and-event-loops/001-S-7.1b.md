# S-7.1b

## Plan assumption

WP7.1 and D-7.1a: a loop is scheduled only (`cron`), rendered for Amp (`set_schedule` input), Cursor (Terraform), and the Actions fallback

## Finding

Founder decisions (2026-10-16, confirmed as gating v0.2.0): aayu sets up scheduled automations (daily, weekly, monthly, any cron) and event-based ones (an issue opened, a PR opened or updated, a required check failed, a Feedback issue, a release published, map drift or a failed sweep) in each agent's native tooling, Amp, Cursor, Claude Code, and Codex, per repository and project, in the user's own session; the Actions fallback never answers an event with a model. This extends WP7.1; it replaces nothing

## Implemented instead

WP7.1b, four PRs: the format and renders in #247 and #248, the default loops in #249, and the entry point in #250. A loop sets `cron` or `on`, never both: `on` is one of `issues.opened`, `issues.labeled`, `pull_request.opened`, `pull_request.synchronize`, `check_suite.completed`, `release.published`, with an optional `filter` (`label` on issues and PRs, a required one for `issues.labeled`; `conclusion` `failure` or `success` on check suites), and its command may name the subject (`{number}`, `{tag}`). `Parse` refuses both or neither, an unknown event, a filter the event has no field for, a label outside `[A-Za-z0-9:._/ -]`, the wrong placeholder, and `setup` on an event loop (`TestParseRefuses`). Renders: Amp `loops/amp/<name>.json` is the `set_schedule` input for a schedule or the `create_github_subscription` input (an orb spawner, `destination` new-orb) for an event; Cursor `loops/cursor/aayudha-loops.tf` gains `git_pull_request` (`pr_action` opened or pushed), `git_ci_completed` (`condition`), and `git_label` (issues, `on_added`, `label_name`) triggers; Claude Code `loops/claude/routines.md` and Codex `loops/codex/scheduled-tasks.md` give the exact values per loop (D-7.1e); Actions gets one record job per event loop, which runs the halt check and writes the event to the run summary, with no checkout, no install, and no model. A host without the trigger does not render the loop and says why. The guard `aayu hook loop:<name>` starts every run on every host and is due for an event loop whenever its own event started the run; halt (exit 4) and `[budget]` (exit 6) still stop it first (`TestLoopGuardEvent`). Golden: `TestGolden` renders one fixture of scheduled and event loops for all five outputs
