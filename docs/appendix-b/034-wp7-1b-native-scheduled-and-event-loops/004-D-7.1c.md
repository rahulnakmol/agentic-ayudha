# D-7.1c

## Plan assumption

S-7.1c: "label, prioritise and route new issues with `aayu triage`"; "stale Ready issues"

## Finding

`aayu triage` took one issue and, without `--as`, called the triage lane's model, so a loop could not run it first with no model. triage only labels the class (feedback, bug, incident), which routes the issue; no verb sets a priority. No verb lists Ready issues

## Implemented instead

`aayu triage` with no issue lists the open intake issues, oldest first, read-only and with no model call (`--as` without an issue is a usage error; `TestTriageListsIntake`); the loop's agent then runs `aayu triage <issue> --as <class>` for each. Priority stays with `slice` and the humans. The housekeeping prompt reads Ready issues with `gh issue list` (a read) and checks each with `aayu ready --check`. **Founder decisions (2026-10-16), accepted as built:** triage sets only the class, never a priority; drift and failed-sweep hand-offs stay with `verify-sweep` and `verify-maintain`, with no separate event loop
