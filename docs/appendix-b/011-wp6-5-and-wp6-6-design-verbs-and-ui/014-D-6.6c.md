## Implemented instead

Who was wrong. **The lane's instruction, not the model**: `uireview.System`, which both `aayu review` and the case send, never asked for fixes inside the design system or said that invisible focus blocks a keyboard user, while the rubric (and WP6.6's polish, which applies the fixes) needs both. It now says a fix reuses a colour, size, or style the page already defines (an existing text colour that meets the floor; a `:focus-visible` ring in the page's focus or accent colour), never a new value, and that a persona who can finish only by guessing, such as a keyboard-only user who cannot see focus, is blocked. Passing the product's `[design] tokens` to lane A would be stronger, but the review command does not read them today; the page's own CSS carries the same values. **Model**: no limit shown; flash found every defect in every run. **Rubric, cases**: none wrong.
