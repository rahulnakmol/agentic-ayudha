# D-6.5b

## Plan assumption

WP6.5 and WP6.6: the UX skills (`research`, `wireframe`, `mockup`, `prototype`, `review`, `polish`, `baseline`) had no scored eval (founder, 2026-10-17: a new advisory group, at least two realistic cases per skill, rubrics grounded in each SKILL.md and the design system, deterministic floors where the output has hard rules, the judge scoring the artefact the skill produces, at least 4.0 per skill over k = 5 with judge `gpt-6.1-sol`, 80 USD of tier-2 spend)

## Finding

The WP3.4 harness asks for a work item or a Markdown draft; these skills produce stage directories (`stage.json` plus SVG, HTML, Markdown, and code), a lane A critique, a polished page, or a command sequence. The design verbs' checks need a ledger, the prototype's figma-diff gate needs a Figma file and a running app, and the a11y floor needs Chromium. Lane A's instruction is `uireview.System` in the binary, not the review SKILL.md body. While recording the cases two checks were wrong: `design.CodeConnect` read `node-id=3-30` as `3:0` (its separator class `[-:%3A]+` also swallowed the digit 3), and `CheckLiterals` read an issue reference in parentheses, "(#423)", as the colour #442233

## Implemented instead

New case key `[ux]` (`internal/evals/ux.go`) and group `ux` in `evals/eval.toml` (prefixes `research/` … `baseline/`, 35 USD a run, `gate = "advisory"`, `events = ["workflow_dispatch"]`, so every run's spend is chosen). Fourteen cases, two per skill, on two synthetic Features: #420 (orders list delivery status, startup) and #570 (choosing a delivery window, scaleup), each chained research → wireframe → mockup → prototype through the recorded outputs (`upstream`, built and pinned with `design.Build`, new field `Static` that stops a prototype before Figma and the gate); review and polish on the WP6.6 delivery-preferences fixtures (planted and clean, with captures recorded by the binary's capture script) and an orders page with four defects; baseline on a release candidate (private, bucket) and a refused run (public, no bucket, uncommitted work). The skill replies with its files as JSON; floors run before the judge, and a failing reply gets the findings once, as a host does when the binary refuses. Floors: `aayu <stage>`'s own checks and every Completion Goal state; research references only from the host's search results (two of each case's are images) and quotations word for word from the data, plus the team stage's artefact (`seats.CheckStage`); token-only colours in a prototype's code; for polish, token colours, every control kept, every finding in `polish.md`; for baseline, the commit checked out before `aayu baseline --sha` (never the SHA changed to match), the case's target and never production, no GitHub write, nothing discarded; the mockups' and polished pages' HTML through lane B in Chromium (impeccable, axe, the focus and 44 px probes: no contrast, focus, target, label, or keyboard finding), which the `ux` job of `evals.yml` installs (`packages/floors`, Playwright) and CI `floors-web` runs on the recorded outputs (`TestUXA11yFloor`, `TestTier1`). Review is lane A itself: `uireview.Prompt` on the recorded capture (both screenshots, markup, tree) on the ui-review lane's model (`gemini-3.1-pro-low`), once per eval run (the 2-of-3 consensus is the binary's, tested by `TestLaneAConsensus` and `TestReviewLive`), with no revision; it must report every kind lane B measured at severity 2 or more and none it measured clean, with severities within their heuristic scores and all four personas. **What the judge sees**: the task, the upstream stages' files, the context files (tokens, the design-system summary, the Figma file's frames and components, the critique), the skill's files as text, and the floors that passed; for review, lane B's results, the markup, and the tree. **What it cannot see**: pixels. It never sees a rendering or a screenshot, so visual hierarchy, spacing, and layout at 390 px are judged from markup and styles; contrast, focus, and target sizes are measured by the floors instead; the prototype's pixel diff against Figma is not run. `design.CodeConnect` takes `-`, `:`, or `%3A` as the node separator, and `CheckLiterals` counts a parenthesis only after a function name (`drop-shadow(#00ff00 …)` still counts), both with test cases. Tests: `TestUXFloorsCatchLapses` (one planted lapse per floor on a recorded run), `TestUXA11yFloor` (floors-web), `TestTier2UXRuns` (a refused wireframe revised once and judged; lane A's request carries both screenshots, a missed defect scores 1), `TestGroups`
