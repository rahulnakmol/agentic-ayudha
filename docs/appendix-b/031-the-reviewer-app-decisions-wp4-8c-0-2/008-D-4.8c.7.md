# D-4.8c.7

## Plan assumption

Decision 4 (P5): for Bug stories the gate reruns each mapped proving test on the base commit; advisory four weeks, then blocking, by a dated config value

## Finding

`internal/verify` is owned by the feature-map thread. Only Go tests are mapped by name today

## Implemented instead

\#229: `verify --ci` in the gate (full floors, PR with a `type:bug` story) runs `redOnBase` (`internal/cli/redbase.go`): a temporary worktree at the merge base, the PR's changed `*_test.go` and `testdata` files from the head, and `go test -json -run <mapped tests>` in the verify sandbox. Each criterion is red on base, green on base, or inconclusive (did not run, e.g. a new API). The `red-on-base` check lands in the pack and the floor table: `pass` with no green criterion, `skipped` with "advisory until 2026-11-13" before `[verify] red_on_base_blocking_from` (default `2026-11-13`; empty keeps it advisory), `fail` from that date. Inconclusive never blocks. Non-Go products get no check
