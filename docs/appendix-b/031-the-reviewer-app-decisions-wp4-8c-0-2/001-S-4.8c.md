# S-4.8c

## Plan assumption

Ground rule 5: the binary calls a model directly for "`inspect` in the merge gate" (and "`triage` in Actions"); §0.1: CI runs `inspect`; WP4.8: inspect uses the "review-lane model (family ≠ builder)", with `[budget] per_pr_inspect_max`; D-4.8a: the `aayudha/inspect` job holds the model key in the `ai-gateway` environment; D-4.8b.1: "the merge gate's `aayudha/inspect` job holds the model key"; WP4.8b, D-4.8b.3, and D-4.8b.7: peer mode (two model reviewers) and `delegated_mode` in the gate; the merge-gate template's setup comment (model keys in `ai-gateway`); the merge-gate guide's model-review sections

## Finding

Founder decision 1 (2026-10-15): no AI keys in a product repository's CI. For every repository aayudha sets up, CI runs only deterministic checks. The merge gate's AI review moves to @-mentioning an agent app the user installed on the organisation or account (@claude, @cursor, @amp, @codex); install and doctor detect them; config picks the reviewer; the different-family rule stays, falling back to a human review when no app of another family exists; aayu reads the reply deterministically into the disposition and criterion verdicts; a missing or malformed reply fails closed. aayudha's own repository keeps its AI gateway for evals only. Decision 2: inspect takes two ideas from Open Code Review and depends on nothing from it. Decision 3: a PR may edit its own checks, but weakening is flagged. Decision 4: red-on-base proof for Bugs, advisory for four weeks by a dated config value. Decision 5: P2, P6, P3, and Q4 (high-risk PRs stay on the single reviewer)

## Implemented instead

The merge gate's `inspect` job has no environment, secret, or model call. `[inspect] reviewer` (`auto`, `claude`, `codex`, `cursor`, `amp`, `human`, or `model`; default `auto`), `[inspect] apps` (the installed apps), and `[inspect.app_families]` pick the reviewer (`inspect.ChooseReviewer`); `reviewer = "model"` keeps the 0.1 lane for a repository that accepts a key. `aayu inspect <pr>` outside CI posts the request under the person's account; the gate reads the reply (`inspect.ReadReply`, `Runner.Judge`, no model call); a new `reply` job (`aayudha/inspect-reply`) re-runs the head's inspect job when the reviewer replies. `doctor` gains `reviewer-apps`; `install` notes detected apps. This repository's own gate uses the same path (`[inspect] apps = ["codex"]`); its gateway stays for `evals.yml`. The rule-5 text, §0.1, and WP4.8 are unchanged in text; this row records where their "model in the merge gate" no longer applies. Peer mode, `delegated_mode`, `peer_model`, and `[budget] per_pr_inspect_max` apply only to `reviewer = "model"`
