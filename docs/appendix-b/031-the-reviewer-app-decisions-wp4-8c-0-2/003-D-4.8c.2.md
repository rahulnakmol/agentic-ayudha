# D-4.8c.2

## Plan assumption

S-4.8c: aayu reads the reviewer's reply in a stated format

## Finding

Codex will not use a custom format: any `@codex` text with review words gets its native review, and task mode needs a Codex environment set up in the ChatGPT UI. Its review is a receipt (`<!-- codex-review-receipt:v1 -->` and "Reviewed commit:" with the first ten hex digits of the commit), as a review body when it has findings and as a comment ("Didn't find any major issues") when it has none, plus inline comments with a P0–P3 badge on that commit. Its `codex-review-state:v1` summary comment is not reliable

## Implemented instead

The stated format is a fenced `aayudha-review` JSON block (`AppSchema`: the review schema plus `head` and `reviewed`), read only from the reviewer's login, newest first; one that fails JSON or the schema is `malformed-reply`, one for another head is skipped. For Codex, its native review counts: a receipt naming the exact head (review or comment) and its inline findings on that commit (P0/P1 → `fix`, else `merge`); it judges no criterion, so each is `unclear` unless a P0/P1 finding names "criterion N" (then `unmet`). In human mode an APPROVED review of the head by the approver counts. Any other post by the reviewer after the request is `malformed-reply`; nothing is `no-reply`. Both exit 4 and are not fix cycles
