# D-4.8c.1

## Plan assumption

S-4.8c: CI @-mentions the reviewer app

## Finding

Live (probe `rahulnakmol/aayu-scratch-probe-1792110386`, kept): the Codex app answered a person's `@codex review` with its own review, but answered the same text from `github-actions[bot]` with "create a Codex account and connect to github" (run 38830182006); the apps act for the people who connected them. A token cannot list an account's app installations (`/user/installations`: 403 for a personal access token)

## Implemented instead

The request is posted by `aayu inspect <pr>` outside CI, under the human token (`HumanGitHub`), as one comment per head (`<!-- aayudha:review-request {"head":…,"reviewer":…} -->`): the mention first, then the criteria and the stated format. `build`'s Next names `aayu inspect N`, and a `delegate` sync posts it while it waits for inspect (`requestReview`). The request and the reply job have no pack, so they read the builder's `Aayudha-Model` claim from the head commit, the same trailer `verify` copies into the pack, and pick the same reviewer as the gate (`TestInspectThroughApp`). `inspect.DetectApps` reads org installations where allowed, then the comment, review, and check-run authors of the last 10 PRs; doctor and install report what they found and the config to set, and never edit config
