# D-4.3a

## Plan assumption

WP4.3: floor interface, scrubbed child env, no-network default, results into the pack; diff coverage from lcov, Cobertura, and Go coverprofile; threshold from config (90 %); accept: 89.9 % fails, 90.0 % passes, a child cannot read `AAYU_*` or `GITHUB_TOKEN`

## Finding

The plan does not say how a floor's tools are isolated, which test command produces coverage, which lines are "the diff", or how a pack's criteria get evidence that CI actually observed. Unprivileged network namespaces are Linux-only and Ubuntu's AppArmor can forbid them

## Implemented instead

`internal/verify`: `Floor{Name, Applies, Run}`, `Execute` (a floor whose tool is missing or errors is `blocked`, never a pass; one that does not apply is `skipped` with its reason), `Pack`. Children get only an allow-listed environment (PATH, locale, temp, Go and Node cache locations, never `AAYU_*`, `GH_*`, `GITHUB_*`, or anything named token/secret/password) and a throwaway HOME; the tool is resolved on the child's PATH. No network by default: on Linux the binary re-executes itself in a new user and network namespace with only loopback up (CAP_NET_ADMIN is dropped before the tool runs); where namespaces are unavailable the proxies point at a closed port and `GOPROXY=off` (`network: proxy-blocked` in the check). Floors that need the network say so (semgrep's rule registry, the OSV database). Coverage: `[verify.floors.coverage] command` (argv) and `report` (new keys), else in a Go module `go test -json -covermode=set -coverpkg=./... -coverprofile ./...` (since WP4.8: code exercised by another package's tests counts, as the CLI's tests exercise most packages); the changed lines are the new-side lines of `git diff -U0 <merge-base>..<head>`; lines the report does not list are not executable; the comparison is exact in integers, so 899/1000 fails 90.0 and 900/1000 passes; a failing test command fails the floor. Criteria evidence: `.aayudha/evidence/<story>.toml` in the PR maps each criterion to tests (`[[criterion]] id, tests`), and verify turns the `go test -json` events of tests that passed in this run into `evidence/criterion-<n>.jsonl` (kind from the criterion); a test that did not run or failed leaves the criterion unmapped. `aayu verify [pr] [--floor f]`: story from `Refs #n` in the PR body, an `Aayudha-Story` trailer, or a `story/<n>-…` branch; the Ready snapshot from the ledger; refuses (exit 4) a checkout that is not the PR head; writes `.aayudha/proof/<story>/`; exit 3 on a floor miss
