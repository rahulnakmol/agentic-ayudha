# D-4.1a

## Plan assumption

WP4.1: `pack.json` v1 with story, `pr_head_sha`, checkpoint, seat, host, model, identity, `completion_goal_hash`, criteria, artifacts `{path, kind, sha256, size, lfs\|bucket}`, checks `{floor, result, value, threshold, tool, version, waiver?}`, cost, links; schema versioned

## Finding

The plan names no authority field, no place for media that were not pushed, and no tombstone, and `proof verify` has to know what "head" and "criteria" to compare against

## Implemented instead

`internal/proof` (schema `internal/proof/schema/pack.v1.json`, validated with the WP1.6 JSON Schema subset; `Decode` dispatches on `schema_version` so every shipped version keeps a reader, WP1.9). Added fields: `repo`, `pr`, `base_sha`, `footprint`, `authority {kind advisory\|authoritative, workflow, run_id, writer}`, `created_at`; artifact `store` is `git` (data on the ledger), `lfs`, `bucket` (with `object`), or `none` (media not pushed: hash only), plus an optional `tombstone {purged_at, reason}`; check `result` is `pass\|fail\|skipped\|waived\|blocked` with `detail` and `network`. `proof verify <story>` checks the best pack (newest authoritative, else newest advisory) against the PR's current head (API), and the Completion Goal hash and criterion numbers of the Ready snapshot on the ledger (`specs/<n>/ready.md`, parsed by `ready.ParseSnapshot`): every stored artifact's SHA-256 and size, every Ready criterion mapped to at least one artifact, every evidence reference resolvable, `pr_head_sha` = head. Floor results are reported (`floors_hold`) but are not integrity problems. Exit 4 on any problem
