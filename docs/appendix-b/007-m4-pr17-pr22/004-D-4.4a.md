# D-4.4a

## Plan assumption

WP4.4: semgrep rulesets per language, gitleaks, osv-scanner; zero critical/high; accept: planted findings fail, clean fixture passes

## Finding

Semgrep reports ERROR/WARNING/INFO (or LOW…CRITICAL); osv-scanner groups advisories and Go advisories often carry no CVSS score. The CI `security` job already installs the pinned tools

## Implemented instead

`sast`: registry packs per language tracked in git (`p/golang`, `p/javascript`, `p/typescript`, `p/python`, …, plus `p/github-actions`), CRITICAL → critical, ERROR/HIGH → high, WARNING/MEDIUM → medium. `secrets`: `gitleaks git --redact` over the PR's commits (`base..head`); any finding above `max_findings` (0) fails. `deps`: `osv-scanner scan source -r`, one finding per advisory group by CVSS (≥ 9 critical, ≥ 7 high), else the database severity, and an unscored group counts as high (rule 7 errs closed). Reports are artifacts (`reports/*.json`, kind report). Tests: stand-in tools with recorded reports in `go test`; the real pinned tools in the CI `security` job (`TestFloorsWithRealTools`: a tainted SQL string, a GitHub token, and `golang.org/x/text v0.3.0` each fail their floor; a clean module passes), with every planted fixture generated at run time so this repository's own scans never see it
