# D-4.10a

## Plan assumption

WP4.10: `grill story` as a markdown-only skill writing the issue via `actions`; `build` minimal (refuse unless Ready and body hash = snapshot; worktree from `origin/dev`; `Aayudha-Checkpoint` commits; open PR); `ship` minimal (green gate, one approving human review, squash-merge, Complete section, cleanup); accept: tier-1 eval for `grill story` yields an issue passing `ready`, `build` on a non-Ready issue exits 4, `ship` with only a bot review exits 4

## Finding

A skill cannot write GitHub itself, so the binary needs inputs for the draft. GitHub refuses self-approval (D2), there is one human and no bot App, so no PR here can get an approving review from someone other than its author. No bot App also means CI cannot write the authoritative pack (D1). WP2.8's proof coverage was n/a until M4

## Implemented instead

`grill` gains `--title`, `--body`, `--labels` (label-held fields only), and `--create` (pinned false over MCP): it validates the draft at Create and Ready (the parent from `--parent`) and, only with `--create` and a pass, creates the issue (`type:story`, `status:planned`, the labels, `identity:human-fallback` on day one) and links it under the parent; other types are n/a until WP5.3. `skills/grill/SKILL.md` and `references/story.md` hold the interview; tier-1 case `evals/cases/grill/story-empty-claims`. `build <n>`: refuses (exit 4) unless the story passes Ready, carries `status:ready`, and its body hash equals the snapshot comment's; the first run cuts `.aayudha/worktrees/<n>` on `story/<n>-<slug>` from `origin/dev`; each later run commits the agent's changes (`feat: <title> (#n, checkpoint k/N)`, DCO sign-off, trailers `Aayudha-Story`, `Aayudha-Checkpoint` with N = the larger of k and the change's layer count, `Aayudha-Model` from `AAYU_MODEL` or `[models.build.<host>]`), pushes, and opens the PR (`Refs #n`); no lease, budget breaker, per-checkpoint verify, or `--resume` (WP5.5). `ship <pr>`: the head's `aayudha/merge-gate` and `aayudha/inspect` check runs are green; the authoritative pack for the head is on the ledger, or ship lands it from the newest successful base-branch `aayudha-merge-gate.yml` run's `aayudha-pack` artifact under the human identity, recording the run (`authority.run_id`, `writer`); the pack verifies against the Ready snapshot and the head, and its floors hold (a skipped mobile floor blocks unless waived, WP4.9); then the human pass: the latest decisive review per reviewer must include an approval of the head by a human who is not the author (bot accounts and `[identity] bot_logins` never count). `--solo-bypass` (human-only, refused for agents) is the closest enforceable pass while D2 holds: only with no bot identity and no second paired human, and only after the merging human's own PR comment starting `Solo-mode bypass:`; it is written to the ship record, the Complete section, and the actions log for `audit` (WP7.6) to reconcile. Then squash-merge at the head SHA, `status:merged` (labels first, so the Ready guard ignores the body edit), the Outcome section (Complete), `proof/<story>/<head>/authoritative/ship.json` on the ledger, the branch and worktree removed, and the actions segment checkpointed to the ledger. The merge gate passes a PR that serves no story (no `Refs #n`, trailer, or `story/<n>-` branch) without running a floor, since it has nothing to prove. `status` in a checkout now reports proof coverage: done stories and bugs (merged, released, measured, done) whose authoritative pack maps every Ready criterion, matches its hashes, and holds its floors, over all of them
