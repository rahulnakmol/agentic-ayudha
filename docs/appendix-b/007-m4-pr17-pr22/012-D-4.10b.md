# D-4.10b

## Plan assumption

WP4.10 `build`/`ship` checkpoints (WP1.5: segments on `ledger` "at each checkpoint and on `ship`"), found running M4.5

## Finding

The segment sink pushed without a token, relying on the clone's git credential helper; where that helper cannot push (this orb), every segment was lost, and `build` ignored the error. Each worktree kept its own actions log under its `.aayudha/`, so `ship` removing the build worktree also removed the log of what ran there. A `ship` that refused after landing the gate's pack never checkpointed. GitHub answers deleting an already-deleted head branch with 422, not 404

## Implemented instead

`build` and `ship` checkpoint through a sink that pushes with the verb's own token (`actions.Log.CheckpointTo`); `build` warns when the segment does not land, a merged `ship` exits 5 with the message. `ship` checkpoints on every exit, refusals included. Runtime state (actions log, telemetry, notify state) of a linked worktree lives in its main checkout's `.aayudha/`, so all worktrees of a clone share one log; configuration and the local pack stay per worktree. `ship` treats "Reference does not exist" as already deleted
