# D-4.6a

## Plan assumption

WP4.6: ZAP baseline against the running app when `[verify] dast = true`; k6 thresholds for API/CLI contracts; accept: a reflected-XSS route fails

## Finding

The ZAP baseline is passive, and reflected XSS is found only by the active rule 40012; a full active scan takes far longer than a PR check

## Implemented instead

`dast` runs the ZAP Automation Framework from `zaproxy/zap-stable` pinned by digest (`--network host`): spider, the passive baseline, then an active scan limited to rules 40012/40014 (XSS), 40018 (SQL injection), and 90020 (OS command injection); high-risk alerts above `[verify.floors.dast] max_high` fail. `api` runs `k6 run --summary-export` on `[verify.floors.api] script` (new) with `BASE_URL` set to the target; a crossed threshold (k6 exit 99) fails. Tests: `TestDASTAndAPIFloors` in `floors-dast` (k6 pinned by SHA-256): the app reflecting `q` unescaped fails with "Cross Site Scripting (Reflected)", its escaping twin passes, and k6 holds on a healthy endpoint and fails on a broken one
