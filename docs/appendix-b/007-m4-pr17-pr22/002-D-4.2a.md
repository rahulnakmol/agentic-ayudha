# D-4.2a

## Plan assumption

WP4.2: LFS by extension on private repos; `[proof] media` bucket with lifecycle rules; retention TTL; `proof push\|get\|verify\|list\|purge`; one replace-in-place comment on PR and issue; agent packs advisory, CI packs authoritative; accept: live scratch test, public fixture refuses LFS media, purge removes bucket objects and tombstones `pack.json`

## Finding

No S3 SDK is on the §2 list. GitHub keeps LFS objects until the repository is deleted, so an LFS "purge" can only remove the file from the ledger tip. GitHub publishes no LFS quota API for personal accounts. There is no bucket for this repository yet

## Implemented instead

Ledger layout `proof/<story>/<head sha>/<advisory\|authoritative>/{pack.json, artifacts/…}`; `verify` leaves the local pack in `.aayudha/proof/<story>/` (git-ignored). Media are artifacts of kind screenshot, recording, or sr-transcript, or with a media extension (`proof.MediaExts`, also init's LFS list). `proof push` commits data artifacts; media only with `--media`: to the bucket when `[proof] media` is set, else to Git LFS on a private repository (`ledger.Writer.LFS` runs the LFS filters and `git lfs push` before the commit), else refused with exit 4 before anything is written (V3). The bucket is any S3-compatible store: `s3://bucket[/prefix][?region=…&endpoint=…]` or `r2://<account>/bucket[/prefix]`, path-style SigV4 (`internal/proof/sigv4`, checked against AWS's published "GET Bucket Lifecycle" example), keys `<prefix>/proof/<owner>/<repo>/<story>/<sha256>`, credentials in the secret named by the new `[proof] media_secret` (default `proof-media`, value `ACCESS_KEY_ID:SECRET_ACCESS_KEY`). Retention is a per-repository bucket lifecycle rule `aayudha-proof-retention/<owner>/<repo>` (expiry = `retention_days`), merged into the bucket's existing rules. `proof purge <story>` purges that story's media, `proof purge` media older than `retention_days`: bucket objects are deleted, LFS files removed from the ledger tip, and each `pack.json` rewritten with tombstones (hashes kept). Packs are authoritative only when pushed with `--ci` from `aayudha-merge-gate.yml` (`GITHUB_WORKFLOW_REF`), otherwise advisory; CI writes the ledger only with `AAYU_BOT_TOKEN` (D1). `proof push` posts `<!-- aayudha:proof -->` on the issue and the PR. Tests: a fake S3 (`internal/proof/fakes3`, recomputes every signature) for push, lifecycle, verify, tamper, and purge; a local bare remote with git-lfs for the private path; the CLI end to end. Live: `TestLiveLFSScratch` (private `aayu-scratch-*`: the screenshot lands in GitHub LFS, verifies by download, purge removes it) and `TestLiveBucket` (behind `AAYU_LIVE=1` plus `AAYU_LIVE_BUCKET`/`AAYU_LIVE_BUCKET_KEYS`; run against a local SeaweedFS S3 store, since no bucket exists yet: a founder action). `doctor lfs-quota` now says where media go and, without a bucket, where to read LFS usage, since there is no API (D-1.7a)
