# D-4.5a

## Plan assumption

WP4.5: Playwright drives every Completion Goal state; axe zero serious/critical at WCAG 2.2 AA; keyboard-only; reduced motion; 200 % text; 44×44 targets; Lighthouse CI budgets from config; `[verify] seed`; refuse when `AAYU_ENV` resolves to production; PII redaction (DOM masking + OCR/regex) that blocks the pack

## Finding

A criterion's state is free text, so the floor needs a way to find the page; CONSTRAINTS.md (WP0.5) already says Lighthouse budgets are product-specific with no default; Lighthouse CI's budget files are superseded by plain Lighthouse audits; no OCR library is pure Go

## Implemented instead

States are the screenshot and recording criteria of the Ready snapshot, at the path in backticks in the state (`` state: `/settings` … ``), else the root of the target. Targets are `[verify.environments.<name>] url, production` (new), picked by `AAYU_ENV` (default `local`); a production environment, or any target on a production host, makes `verify` exit 4 before seeding or writing anything. `[verify] seed` (argv, new) runs once before the first capture; `init` scaffolds `.aayudha/seed/README.md`. The embedded `web.mjs` (node; Playwright and axe-core resolved from the product, then `NODE_PATH`) runs per state with `prefers-reduced-motion: reduce`: DOM masking (`[data-aayu-mask]`, password/email/tel/card inputs), a PII scan of the masked text (email outside the RFC 2606/6761 reserved domains, Luhn-valid card numbers, national ID numbers), axe with the wcag2a/2aa/21a/21aa/22aa tags, Tab-reachability of every visible control, running animations, text clipped at `text_scale_percent` (CSS zoom), and controls under `min_target_px` (inline text links excepted). Checks: `a11y` (axe), `keyboard`, `reduced-motion`, `text-scale`, `targets`, `redaction`. Any PII (DOM, or OCR with `tesseract` when installed; the check says when OCR is unavailable) blocks: `redaction: blocked` and no capture of the run is kept. Screenshots (`screens/<n>.png`) and recordings (`recordings/<n>.webm`) are the criteria's evidence. `perf` runs Lighthouse (performance category, Playwright's Chromium) on each state URL once `[verify.floors.perf] min_score\|max_lcp_ms\|max_cls\|max_tbt_ms` (new, no defaults) set a budget; only the numbers are kept, since a Lighthouse report embeds screenshots. Tests: `TestWebFloorsWithBrowser` in the new `floors` workflow (`floors-web`; Playwright, axe-core, Lighthouse pinned in `packages/floors` and `pnpm-lock.yaml`)
