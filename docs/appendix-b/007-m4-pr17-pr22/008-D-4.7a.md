# D-4.7a

## Plan assumption

WP4.7: Guidepup VoiceOver (macOS) and NVDA (Windows); expected phrases from the Ready snapshot; transcript diff; only for L01 footprints (from `LAYERS.md` globs over the changed paths), on label or nightly; accept: an unlabeled button fails against expected phrases, an `internal/`-only PR skips with `skipped: no-L01`

## Finding

A criterion's expected text is prose; ESM imports ignore `NODE_PATH`; the screen readers read their settings from the user's profile; a Linux merge gate cannot run either reader

## Implemented instead

`screen-reader` floor: the expected phrases of each `[sr-transcript]` criterion are its quoted strings (else its whole expected text), read from the Ready snapshot on the ledger; the floor writes an embedded Playwright Test spec and config (CommonJS, so the product's or `NODE_PATH`'s `@playwright/test` and `@guidepup/playwright` resolve) and runs `voiceOverTest`/`nvdaTest` on Chromium per state (`navigateToWebContent`, 15 `next()` steps), keeping HOME and the profile variables for this floor only (credential variables stay scrubbed). The diff is case- and space-insensitive containment; missing phrases above `max_missing_phrases` (0) fail; transcripts are the criteria's evidence (`transcripts/<n>-<reader>.txt`). It applies only when the footprint meets `[verify.floors.screen_reader] layers` (else `skipped: no-L01`), the story has `[sr-transcript]` criteria, the OS is macOS or Windows, and, in CI, the PR carries `aayudha:screen-reader` or the run is scheduled. On the Linux merge gate an L01 story's floor is `skipped` with that reason, not blocking. Workflow `screen-reader.yml` (macos-15 VoiceOver, windows-2025 NVDA; label, nightly, dispatch; Guidepup pinned in `packages/floors`; the label joins the set `init` creates) runs `TestScreenReaderFloorReal`; `TestScreenReaderSkips` covers the skips
