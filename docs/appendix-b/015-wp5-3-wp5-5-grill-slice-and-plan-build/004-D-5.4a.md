# D-5.4a

## Plan assumption

WP5.4: `slice` makes XS-L stories with criteria, deps, and a footprint computed from the Feature's expected paths via `LAYERS.md` globs and confirmed by the plan, and closes an XL as "split into"; `plan` has checkpoints per layer, contracts, tests, instrumentation, rollback, with an EM plan-time review for `autonomy.never` layers recorded in the pack; accept: evals on a 3-layer and a 6-layer (L07 migration) Feature give stories ≤ L passing `ready` (tier 1, 100 %), each plan one checkpoint per footprint layer and a rollback for any L07 checkpoint, tier 2 at the WP3.4 bar, an XL input returned as ≥ 2 stories with the XL closed "split into"

## Finding

Both verbs run in the host (mode `host`), so the binary needs the drafts as input. The Story schema has no footprint field, and expected paths are globs, not changed paths. A Feature is a container: closing it would orphan its stories. The pack is written by the merge gate before `ship`, and nothing yet carries a plan into it. The eval scratch repository has no `LAYERS.md`, and the WP3.4 tier-1 replay cannot reach files the recorded run wrote

## Implemented instead

`slice <feature> --draft <file> [--create]` and `plan <story> --draft <file> [--create] [--approve]` (new registry inputs; `--create` pinned off over MCP, `--approve` human-only); without `--draft` each prints what to work within (the Feature's expected paths and footprint; the story's footprint, criteria, and never layers). `internal/planning` holds the deterministic checks. A story's footprint is held in `layer:Lxx` labels: `slice` computes it from the story's `paths` (globs inside the Feature's Expected paths) by glob overlap with the `LAYERS.md` globs (the registry's layer table when the checkout has none, as `status --streak` does). `slice` refuses (exit 4, nothing written) a Feature without Expected paths, a story that fails Ready under the Feature (so XL, unmapped criteria, missing effort), paths outside the Feature's, a Feature layer no story covers, `depends_on` that is out of range or cyclic, and a hand-written Links field; `--create` writes the stories in dependency order as sub-issues with `status:planned`, their labels, and `depends-on #N` links. An XL input is a Story labelled `effort:XL` (a Feature is always sliced, never closed): it needs at least two stories, which go under its Feature, and it is closed as not planned with `status:cancelled` and a comment "Split into #a, #b". `plan` needs a story or bug that passes Ready and refuses a second checkpoint for a layer, a footprint layer without one, one outside the footprint (re-slice), a checkpoint without tests, an L07 checkpoint without a rollback, and a criterion no checkpoint covers; a story without layer labels takes the plan's layers as its footprint (written as labels). `--create` writes `specs/<story>/plan.json` to the ledger (the plan, the body hash it was made for, and `em_review {required, layers}` when the footprint meets `[autonomy] never`); `plan --approve` by the EM seat's paired human, else the `[autonomy] approver`, else the one human in solo mode (recorded as `solo`) adds `approved_by`, `approved_at`, `as`; `ship` (WP5.5) reads it and records it in the ship record next to the authoritative pack. Evals: `slice/grill-followups-3-layer` (L02, L03, L05), `slice/proof-retention-6-layer` (L02, L03, L04, L06, L07, L09, with the config migration), `slice/xl-story`, `plan/config-migration` (L07 with rollback), `plan/purge-kind-flag` (L02, L03); recorded calls may name the case's files as `{case}/…`, and the tier-1 fake answers label writes with a list. Tier 2: `[tier2] draft = "slice"\|"plan"` and `issue` run the drafts through the same checks against the case's fixture before the judge (`slice/proof-retention-6-layer`, `plan/config-migration`); `max_usd` is 18.0
