# S-4.3r

## Plan assumption

WP4.3 and CONSTRAINTS.md: floors are static thresholds; a change to one is a protected-path edit with a human review

## Finding

Founder decision 3 (P7, research Q5): in this repository only, for 0.2, floors (coverage first) can only tighten automatically when a better value holds, and loosening needs a recorded waiver. It is not a product feature for repositories aayudha sets up

## Implemented instead

A coverage ratchet for this repository's CI: `ratchets.toml` at the root holds the floor, `internal/ratchet` checks it, and the required `build` job runs it on every PR and push. No verb, config key, `init` template, or CONSTRAINTS.md row is added, and no model or secret is used: the job's own read token reads a waiver
