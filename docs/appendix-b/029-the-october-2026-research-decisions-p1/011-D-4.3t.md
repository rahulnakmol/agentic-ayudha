# D-4.3t

## Plan assumption

Story #401 (Feedback #329, private research note agent-steering-patterns-2026-10.md): deterministic eval rules misfired on negations, near misses, and paraphrases 9 times in 7 threads, and nothing tested a rule against the text it must and must not fire on

## Finding

A rule's behaviour on a sentence is deterministic, so it can be tested like code. #333, filed by `retro --classify`, could not pass Ready (no Measure, Threshold, Scenario, Environment, or effort), so #401 replaces it with the same Completion Goal

## Implemented instead

Every deterministic rule (case.toml `[[scope]]`, session.toml require, forbid, say_forbid) carries `match`, `negated`, and `near_miss` fixtures; `TestCaseRulesHaveFixtures` fails naming the case, the rule, and a missing kind, a match it does not fire on, or a negated or near-miss fixture it fires on. `negated_fires = true` marks a rule whose topic the human parked or the request does not state, where ruling it out still takes it up; each says why in a comment. The inline `scope = [...]` arrays became `[[scope]]` tables with the same pattern, why, and allow, so the #400 ratchet sees no change there. The fixtures found three real misfires on a negation, fixed with a negation `allow` and every match fixture still firing: the brief rule in four cases ("does not show that reviewers read") and two slice/proof-retention-6-layer rules ("not the only trigger", "do not reject decimal values"). A changed allow counts as a lowering under D-4.3s, so the PR names `bar_waiver = 413`, an eval-bar waiver a human accepts. Recall gaps are out of scope: the bakery-concrete currency rule does not fire on "dollars" (only `dollar`), left as it is
