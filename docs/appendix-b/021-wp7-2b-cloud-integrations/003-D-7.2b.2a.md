# D-7.2b.2a

## Plan assumption

WP7.2b.2: Azure Blob Storage (SAS or Entra token) and Google Cloud Storage (JSON API with a token, or the XML API with HMAC keys) as `[proof] media`, with WP4.2's purge, tombstones, and lifecycle

## Finding

Azure's lifecycle rules live in the storage account's management policy, which only Azure Resource Manager serves; a SAS token reaches the blob endpoint only, and Resource Manager needs the subscription and resource group. Azure rule names are alphanumeric; GCS lifecycle rules carry no ID at all. The GCS XML API takes HMAC keys for objects but its lifecycle document differs from S3's, so the S3 code cannot manage it; HMAC keys are long-lived, which the GitHub OIDC setup avoids

## Implemented instead

`proof.Media` is the store interface (the S3 `Bucket`, `AzureBlob`, `GCS`), opened by `proof.OpenMedia` from the `[proof] media` value; credentials stay in `[proof] media_secret`, and the non-secret settings are URL parameters, so no config key is added. `azblob://<account>/<container>[/prefix]` with `auth=sas` (default; the secret is a SAS token), `key` (`<client-id>:<client-secret>`, `tenant=`), `oidc` (`tenant=`, `client=`; GitHub Actions federation), or `cli` (`az`); with an Entra credential plus `subscription=` and `group=`, aayudha keeps one rule `aayudhaproofretention<12 hex of the repository's SHA-256>` (delete block blobs under `<container>/<prefix>/proof/<owner>/<repo>/` after `retention_days`) in the account's management policy, merged with the account's other rules (a PUT replaces the policy; the last rule removed deletes it). With SAS, or without `subscription`/`group`, the push succeeds and reports `retention: lifecycle not managed by aayudha …` naming the rule to apply from `.aayudha/setup/azure/` (WP7.2b.3); `proof purge` still enforces retention. `gs://<bucket>[/prefix]` uses the JSON API with `auth=key` (default; a service account JSON key, RS256 JWT grant), `oidc` (`provider=`, `sa=`; STS and impersonation), or `cli` (`gcloud`), with the `devstorage.full_control` scope (buckets.patch needs it); aayudha's rule is the `Delete` rule whose `matchesPrefix` is exactly the repository's prefix, merged with the bucket's other rules. The HMAC XML API is not built: the token modes cover CI without long-lived keys, and an HMAC key would need a second lifecycle format. Both take `endpoint=` for emulators. The Entra and Google token exchanges moved into `internal/integrations/cloud` so the read adapters (WP7.2b.1) and the stores share them. `init --integrations` accepts `azblob://` and `gs://` bucket URLs. Tests: `TestPushVerifyPurgeBucket` now runs WP4.2's push, idempotent re-push, verify, tamper, purge, tombstone, and rule removal against S3, Azure Blob with an Entra app registration, Azure Blob with SAS, and GCS with a service account key (`internal/proof/fakecloud` checks every request's SAS or bearer; `fixture.Clouds` serves the Entra and Google token exchanges); `TestOpenMedia` covers the URL forms and refusals; `TestLiveBucket` takes any of the four schemes behind `AAYU_LIVE=1` and passed against Azurite 3 (SAS: push, get, verify, purge; lifecycle reported unmanaged) on 2026-10-12
