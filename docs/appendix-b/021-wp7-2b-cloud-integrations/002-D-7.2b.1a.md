# D-7.2b.1a

## Plan assumption

WP7.2b.1: live Azure, AWS, GCP reads for `grill` and `measure` returning WP5.2 tuples and the export readers' event shapes; tokens from Entra, SigV4, and Google; local CLI fallbacks; fixture and live tests

## Finding

The providers name no baseline metrics. Azure has no endpoint that reports a token's scopes, but Azure Resource Manager lists the caller's effective actions on a resource; AWS reports a principal's permissions only through the IAM policy simulator, which the principal must be allowed to call; Google's `testIamPermissions` reports permissions held on a project or table. CloudWatch RUM's `GetAppMonitorData` serves only the last 30 days, and Logs Insights sees RUM events only when the app monitor copies them to CloudWatch Logs. A GA4 export's daily tables are named in the property's time zone. Baseline filters come from issue bodies (untrusted, §0.1). `aws`, `az`, and `gcloud` inherit the environment, which holds aayudha's own tokens

## Implemented instead

Packages `internal/integrations/azure`, `aws`, `gcp`, and the shared `cloud` (GitHub OIDC request, CLI runner, token cache). New `[integrations.<name>]` keys for the three clouds only: `auth` (`key` default, `oidc`, `cli`), `identity` (Entra client ID, IAM role ARN, or service account), `federation` (GCP workload identity provider), `region`; `org` is the Entra tenant and `project` the Application Insights or Log Analytics resource ID, the RUM app monitor, or `<project>.<dataset>`. With `oidc` or `cli` no secret is stored. Metrics `events` and `users` for each: Azure `AppEvents` (users = `UserAuthenticatedId`, else `UserId`), AWS RUM events counted by Logs Insights on `event_timestamp` (users = `user_details.userId`; the scan runs an hour past the window and the filter decides), GCP `events_*` on `event_timestamp` with the table suffix a day wider each side (users = `user_id`, else `user_pseudo_id`). The filter is a predicate in the provider's language; `;`, line breaks, and the language's pipe (`\|`, `\|>`) are refused before any request, and it ends its own line. Read-only checks before every data request: Azure `GET <resource>/providers/Microsoft.Authorization/permissions` (any action or data action that is not `*/read`, the two Log Analytics query actions, or `Microsoft.Support/*` is write-capable); AWS `sts:GetCallerIdentity` then `iam:SimulatePrincipalPolicy` for the four read actions and nineteen write actions (root credentials are always refused; a denied simulation leaves the credential reachable but unverified, and doctor says the configured scope is trusted); GCP project `testIamPermissions` for three reads and twelve writes, then the dataset's first table for table writes, and minted Google tokens carry only `bigquery.readonly` and `cloud-platform.read-only`. The read-only transport allows only each cloud's token and query POSTs (by host, path, and for AWS `X-Amz-Target`). `measure --live azure,aws,gcp` (new registry input) writes each pull as JSON lines in its export format next to the snapshot, reads it back through `internal/integrations/exports`, and records the cloud and exact query with its SHA-256 in the Result's sources; a RUM window older than 30 days is refused before any request. The CLI fallbacks run with only `PATH`, `HOME`, and the CLI's own configuration variables. Tests: `TestBaselinesGolden` (Azure, AWS, GCP recordings with the per-request bearer or a recomputed SigV4 signature; tuples written by hand), `TestCloudAuthModes` (key, oidc, cli for each cloud, with every token exchange checked parameter by parameter by `fixture.Clouds`, including the RS256 signature of the service-account JWT), `TestCloudWriteCapableRefused`, `TestCloudRefusedBeforeAnyCall`, `TestAWSSimulationDenied`, `TestMeasureLiveMatchesExports` (the export files' rows as API responses give the WP7.2 cohorts and North Star), `TestLiveCloud` (`AAYU_LIVE=1`, skips each cloud without its settings). Binary size grows by about 0.2 MB (linux/amd64, stripped)
