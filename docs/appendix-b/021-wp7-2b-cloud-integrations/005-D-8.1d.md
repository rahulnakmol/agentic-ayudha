# D-8.1d

## Plan assumption

WP4.8: `inspect` re-entry: `fix` is fixed in the PR, and after two `fix`/`rebuild` cycles the next run pages without a model call; the orchestrator's budget for WP8.1: one `inspect` per PR plus at most one fix cycle

## Finding

`inspect` found a new P1 on each review of three stories: #130's seed check (plan and section fields, seed metadata and address literals, quoted local parts, Unicode domains), #132's request decoding (trailing input, case-insensitive and duplicate keys, a null `user_id`), and #133's simulation (the CLI truncating its output before validating, HR answers after the window). A PR that reaches the two-cycle cap can never pass `aayudha/inspect`, so `ship` cannot merge it

## Implemented instead

The capped PRs (#135 and #140 for #130, #151 for #132, #156 for #133) were closed unmerged with a comment naming the cap and their branches deleted; each story was rebuilt with `aayu build` from the then-current dev as a new PR (#142, #155, #158), with every finding fixed and a regression test for each. Story #131 (#148) and #134 (#160) each used one fix cycle. In all, the five stories took 17 `inspect` runs instead of the budgeted 10; the closed PRs stay on GitHub as the record. #156 also carried a justified `nosemgrep` on `math/rand/v2` (seeded, reproducible synthetic data), first written by another thread (e63db62) and kept in #158
