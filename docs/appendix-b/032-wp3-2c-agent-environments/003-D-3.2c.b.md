# D-3.2c.b

## Plan assumption

S-3.2c: "where a host can only be configured in its web UI, aayu prints the exact values and steps, then verifies that the result works"

## Finding

Codex environments are created only in its UI (codex 0.163.0's `codex cloud` has `exec`, `status`, `list`, `apply`, `diff`, and nothing that creates an environment). Claude Code's `/remote-env` only selects an environment; network access and variables are set in the UI. Cursor needs a dashboard step only for network rules and secrets

## Implemented instead

`install --env` prints, per host, numbered steps with the exact values: the Install script and Start skill, the domains beyond each host's default allowlist (computed from the spec, including hosts named in custom steps), and the variables by name. It then verifies the live result with a probe task that runs `.agents/check` and replies with its last line: `install --env --cloud` runs it itself where a CLI can start a task and read the reply (Amp `amp -ox --stream-json`, whose probe thread is archived once its reply is read, by `amp -x`'s default and again with `amp threads archive`, founder decision 2026-10-16, while its URL stays in the record as evidence; Codex `codex cloud exec --env <id>` then `codex cloud status`), and `install --env --host <h> --record '<reply>'` records a reply copied from Cursor or Claude Code. A reply counts only when it carries the current fingerprint
