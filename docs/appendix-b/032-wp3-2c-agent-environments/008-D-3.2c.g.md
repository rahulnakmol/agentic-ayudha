# D-3.2c.g

## Plan assumption

S-3.2c: stale means "the toolchain changed"

## Finding

A spec can drift three ways: the code asks for another toolchain, the generated files are edited, or the spec changes after verification

## Implemented instead

`.aayudha/env.toml` carries a fingerprint (SHA-256 of the requirements and setup steps, 16 hex digits). `agentenv.Status`: missing (no spec, no files, or never verified), stale (rediscovery differs, a generated file differs from the spec, or the record's fingerprint is not the spec's), verified (the container record matches; `live` when a cloud probe matched too). The generated scripts also load the dotenv file (`.env`, copied from `.env.example`) without overriding what a host sets: setup adds the loader to the shell profile, and `check` and `start` run it, since a test that reads `DATABASE_URL` failed in a clean container without it
