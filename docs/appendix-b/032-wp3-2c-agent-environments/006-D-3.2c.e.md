# D-3.2c.e

## Plan assumption

D-3.2a: `install --apply` is refused for agents (exit 4)

## Finding

`install --env --apply` writes only repository files (no home edits, no machine paths) that a human reviews in the PR, and the delegation thread's `Ensure` must regenerate and verify before a cloud hand-off

## Implemented instead

Agents may run `install --env --apply` and `--verify`; `install --apply` for skills is still refused, and installing skills stays human-only. Confirmed by the founder (2026-10-16), recorded here against D-3.2a. `--cloud` starts its probe task through the user's own signed-in CLI, never with a key aayu holds
