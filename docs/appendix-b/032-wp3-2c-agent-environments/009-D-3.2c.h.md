# D-3.2c.h

## Plan assumption

S-3.2c: `.agents/check` runs the build and tests; Story #399 (replaces #332, Feedback #328): one local gate generated from the required CI jobs, run by a pre-push hook, that cannot drift from `ci.yml`

## Finding

`docs/research/agent-steering-patterns-2026-10.md` §P2 and §5.2: about 60 self-corrections in 25 threads after a check failed on committed work, about 11 of them in remote CI; `AGENTS.md` listed the commands in prose and no hook ran them. A workflow says how CI runs a job, not how to run it on a laptop: actions such as `golangci-lint-action`, `markdownlint-cli2-action`, and `lychee-action` hide their commands, and some steps need CI itself (keyless cosign signing needs the workflow's OIDC token; `protected-paths` reads the PR's reviews). The orb sets a global `core.hooksPath` holding git-lfs's stock pre-push hook, so a hook there serves every clone. Found while proving it: git exports `GIT_DIR` (and `GIT_INDEX_FILE`, …) to a hook, so the repository's own tests, which run git in temporary directories, changed the pushing clone instead (`core.bare=true`, a local `user.email`, about 40 test commits on the local `ledger` branch; one test push to GitHub failed for want of credentials). The clone was restored by hand from its reflogs

## Implemented instead

Discovery reads the job list (`agentenv.PullRequestJobs`: every job of `ci.yml` and `protected-paths.yml` that runs on a pull request, by check name, not a job gated only on `workflow_dispatch` inputs); the commands are the repository's own `[[gate]]` entries in `.aayudha/env.toml` (`run`, and `remote` for what only CI runs), kept across rediscovery and outside the fingerprint. `.agents/check --full` runs each job's commands with `bash -eo pipefail`, stops a job at its first failure, prints `aayu-gate: FAIL: CI job "<job>" fails here: <command>`, prints `aayu-gate: NOT RUN LOCALLY: …` for every remote part and for each scanner that is not installed (gitleaks, semgrep, osv-scanner, lychee, goreleaser), and exits 1 listing the failed jobs. A job with neither commands nor a reason fails the gate, and `TestLocalGateMirrorsRequiredJobs` fails when the committed jobs differ from the workflows', so a new CI job without a local step fails `build`. `install --env --apply` installs the pre-push hook in the clone's hooks path (honouring `core.hooksPath`) and `.agents/setup` does so in cloud clones; it replaces git-lfs's stock hook and does its work after the gate, refuses a hand-written hook, and runs the gate only where `.agents/check` has one. The gate first unsets git's repository-local variables (`git rev-parse --local-env-vars`) and finds the repository from its working directory. The gate checks the working tree, and `commits` checks `origin/dev..HEAD`; the PR title, the other five platform builds, the signed snapshot, and `protected-paths` run only in CI. Proof: the Story #399 PR (each fault exits 1 naming `lint`, `docs`, `generate-drift`, or `commits`; a push to a local bare remote is refused by the hook). Tests: `TestLocalGateMirrorsRequiredJobs`, `TestLocalGateScript`, `TestInstallPrePush` Also found while building it: `aayu verify` runs the tests with a throwaway `HOME` and no network, where `amp plugins list` exits 1 (`Unable to connect to https://ampcode.com/`), so `TestHostPluginsLoad/amp` failed the coverage floor of every `aayu build` in a machine with `amp` installed; that subtest now skips with Amp's message when Amp cannot reach its server, and still checks the plugin where it can.
