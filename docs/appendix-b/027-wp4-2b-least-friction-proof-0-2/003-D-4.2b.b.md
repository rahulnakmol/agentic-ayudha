# D-4.2b.b

## Plan assumption

S-4.2b: retention from `[proof] retention_days` clamped to GitHub's limit

## Finding

GitHub caps artifact retention at the repository's (or organisation's) setting, at most 90 days for public repositories and 400 for private ones, and exposes it to a run as `GITHUB_RETENTION_DAYS`. An artifact of a public repository can be downloaded by any signed-in GitHub user

## Implemented instead

`aayu verify --ci` reports `retention_days` = `proof.ArtifactRetention(retention_days, $GITHUB_RETENTION_DAYS)` (0 or above the limit → the limit; no limit known → 90); the gate passes it to `actions/upload-artifact` and the PR comment shows the expiry date. A ship after the artifact expired is refused: re-run the gate. On a public repository media are as visible as the PR for that window, which V3 did not allow; captures use `[verify] seed` data and the redaction pass (WP4.5) as before. The founder accepted this (D-4.2b.g)
