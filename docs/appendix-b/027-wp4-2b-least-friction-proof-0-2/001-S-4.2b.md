# S-4.2b

## Plan assumption

V1 and §0.1: CI acts as a bot (App token) and writes packs to `ledger`; V3: proof media in Git LFS on private repositories, in a private bucket on public ones; M4: "ledger ops with LFS"; WP1.7: LFS quota; WP2.5 (V3 enforcement): `proof push` refuses media on a public repository until a bucket is set; WP2.6: `--integrations` offers the bucket for V3; WP4.1: artifacts `lfs\|bucket`; WP4.2: LFS by extension, `proof purge`, tombstones, CI packs authoritative; WP4.8: the merge gate "writes the authoritative pack to `ledger`"; WP7.2b.2: buckets with purge and tombstones; R5, R11, J2-1, J3-4; D1, D-2.5a, D-4.1a, D-4.2a, D-4.8a, D-4.10a, D-M4.5a, D-7.1b, D-7.2b.2a, D-7.2b.3a, as far as they describe the bot App writing proof, LFS media, purge, or tombstones

## Finding

Founder decision (2026-10-15, relayed by the orchestrating thread): proof must be the least-friction design that still keeps the rule that the builder cannot certify its own work. A product repository needs no bot App, no media bucket, no secrets, and no purge job for proof. The plan's design needed an App installation token in CI (D1: the workflow token can never write `ledger`), media storage the team pays for and purges, and a daily purge loop that itself needed the App (D-7.1b)

## Implemented instead

The merge gate (`pull_request_target`, base-branch copy) builds the pack from what CI ran on the PR head, as before, and keeps `pack.json` with every artifact as the run artifact `aayudha-pack` for `[proof] retention_days`, clamped to the repository's Actions limit (`GITHUB_RETENTION_DAYS`, else 90). Job `aayudha/pack` (workflow token, `contents: read`, `pull-requests: write`, no App, no secret) runs the new `aayudha proof comment <story> --ci`: it re-checks the pack against the PR head and the Ready snapshot and upserts one `<!-- aayudha:proof -->` PR comment with the criteria verdict table, the floor table, the SHA-256 of `pack.json`, a link to the artifact, and the date it expires; `aayudha/pack` fails with it. CI writes nothing to `ledger`. `aayu ship` (a human) finds the pack through the Actions API (D-4.2b.a), checks every artifact's bytes against `pack.json`, and only after the human pass, just before the merge, writes `proof/<story>/<head>/authoritative/pack.json` and its data artifacts (text, never media) plus the ship record (`gate_run`, `artifact`, `pack_sha256`) under the human's identity. A refused ship writes nothing. Agent previews (`proof push`, any host conversation) stay advisory (`<!-- aayudha:proof-advisory -->`), `proof push --ci` is refused, and no preview satisfies ship. Media never go to `ledger` or Git LFS; LFS stays only for design manifests and review baselines on private repositories (WP6). V1's bot identity remains for agent lanes; it is no longer needed for proof. V3's intent (no media in git, bounded retention) holds, by a different store: the run artifact. The V-table rows are unchanged in text; this row records where V1's CI column, V3's storage column, §0.1's CI row, and M4 no longer apply
