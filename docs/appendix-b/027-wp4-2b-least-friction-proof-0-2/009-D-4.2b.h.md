# D-4.2b.h

## Plan assumption

D1, D-2.5a, D-4.2b.d: the ledger ruleset lets only the admin role (and the bot App) update `ledger`, so only an admin can ship

## Finding

Founder decision (2026-10-15): anyone with write access may run ship, which merges into `dev` only (promotion to `rolling` and `main` stays a separate, admin-only release step); force pushes and deletion stay blocked. A ruleset bypass actor bypasses every rule of its ruleset (live: with `update` and `non_fast_forward` in one ruleset, the write-role bypass let the admin force-push `ledger`, "Bypassed rule violations … Cannot force-push"), so one ruleset cannot say "writers may update but nobody may rewrite". GitHub accepts `RepositoryRole` 4 (write) as a bypass actor on a personal repository, and it covers higher roles: with only that actor listed, `current_user_can_bypass` is `always` for the admin and the admin's push is a bypass. The Actions workflow token still cannot be a bypass actor (D1)

## Implemented instead

`aayu init` creates two rulesets on `refs/heads/ledger`: `aayudha-ledger` (`update`; bypass: the write role, plus the bot App after `init --identity`) and `aayudha-ledger-history` (`deletion`, `non_fast_forward`; no bypass actors). On a repository from before 0.2, a rerun creates the history ruleset first and then narrows the old one to `update`, adding the write role and keeping its other actors; an adopted ruleset is left alone. `uninit` deletes the rulesets before the ledger, since the history ruleset now blocks the ledger's deletion for admins too. This repository's own `ledger-writers` gets the same shape, with a `ledger-history` beside it. Live (`TestLiveLedgerWriters`, 2026-10-15, `rahulnakmol/aayu-scratch-1792086941983397991`, kept): `init` created rulesets 25184190 and 25184186; `uninit` removed both and the untouched ledger; after a second `init`, the admin fast-forwarded `ledger` and its force push and deletion were refused ("Cannot force-push to this branch", "Cannot delete this branch"); a `workflow_dispatch` run with `contents: write` was refused updating it (run 38781954189, "Cannot update this protected ref"). Not shown live: a push by a real write collaborator. The only second account available is an Enterprise Managed User, which GitHub refuses as a collaborator on a personal repository; `TestLiveLedgerWriters` runs that case when `AAYU_LIVE_WRITER_TOKEN` names a personal account. `audit` still labels each ledger bypass "founder-identity ledger write by" followed by the pusher's login, whoever pushed; the wording is kept so recorded reports replay byte-identically
